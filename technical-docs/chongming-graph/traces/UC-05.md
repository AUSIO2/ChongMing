# UC-05 可追溯资产生命周期

## 业务目标与完成条件
以长度、摘要和 Workspace 权限管理二进制证据，使 Graph locator 能稳定引用 ready 资产。

## 入口与调用者
asset.get、POST upload、GET content、asset.delete；本机 assets.cleanup 作为维护动作。

## 权限和前置条件
上传需 Editor，删除需 Owner，读取需 Viewer。上传需要 Content-Length、Content-Type、SHA-256、Workspace 和幂等 UUID。

## 正常调用链
`apiCreateServer → AssetsService.upload → assetsReadChunks → GridFS → AuthService.transact → metadata.insertOne`。下载先授权再返回 GridFS stream。删除在事务内检查摘要和 Graph 引用后写 deleted。

## 分支与异步续接
同用户/Workspace/idempotency key 与相同输入返回原 asset；不同输入冲突。上传重放仍读取并核验请求字节。

## 持久化读写
GridFS 保存 blob；control_assets 保存 metadata/state；asset_receipts 保存删除/导入命令回执。

## 状态迁移
私有 blob → ready metadata；ready → deleted tombstone。cleanup 只删除已标 deleted 的物理 blob。

## 异常、补偿和并发
长度/摘要不符或中断时 abort upload。发布前撤权会使事务失败并清理 blob。删除与新增引用在同一 Mongo 事务/权限围栏下串行化；被引用资产拒绝删除。

## 源码证据
`backend/api.ts#apiCreateServer`；`backend/assets.ts#assetsReadChunks/upload/content/delete/cleanupDeleted`；`backend/application.ts#dispatch`。
