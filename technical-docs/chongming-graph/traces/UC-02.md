# UC-02 治理 Workspace、成员、Agent 与设置

## 业务目标与完成条件
创建隔离协作空间，维护成员与 Agent 配置，并使后续 Run 获得一份可执行的冻结配置。

## 入口与调用者
workspace.create/update/delete、member.set、agent.list/create/update/delete/copy、settings.update。

## 权限和前置条件
Workspace 写操作需要 Owner；共享 library/settings 写入需要 HostAdmin。不能移除或降级最后一个 Owner；固定角色可编辑不可删。

## 正常调用链
`ApplicationService.dispatch → AuthService.transact → ControlService.dispatch`。认证事务先触碰用户与 token 围栏；控制服务再按 Workspace/library revision、Agent revision 和请求回执修改文档。

## 分支与异步续接
Workspace 可从空配置创建，或复制共享 library 并为副本生成新 Agent ID。agent.copy 支持 merge/replace；共享设置只提供默认模型、工具目录和 slot 上限，不保存密钥。

## 持久化读写
control_workspaces、control_library、control_settings；成员显示名从 control_users 读取。写入增加作用域 revision 并追加回执。

## 状态迁移
Workspace/library/settings 以 revision 表示配置版本；删除 Workspace 写 tombstone。Agent 自有 revision 随 update 增长。

## 异常、补偿和并发
所有写在 Mongo 事务内；同 requestId 同输入返回 replay，不同输入返回 IDEMPOTENCY_CONFLICT。角色或工具目录并发变化由 writeFence/CAS 阻断。

## 当前实现边界
parse/split Agent 可管理，但 executableKinds 目前只有 verify。

## 源码证据
`backend/auth.ts#transact`；`backend/control.ts#createWorkspace/configuration/dispatch`；`backend/control-input.ts#controlReadAgent`；`backend/application.ts#dispatch`。
