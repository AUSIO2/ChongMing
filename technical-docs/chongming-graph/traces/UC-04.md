# UC-04 动态多角度 Claim 核查

## 业务目标与完成条件
针对一个 Claim，由路由 Agent 动态选择核查角度和自定义 Agent/tool，多 Host 分摊执行，合并意见；自动模式直接入图，人工模式经过 route 与 result 两轮审核。

## 入口与调用者
用户：run.start/cancel、review.update/answer、run.get。Host：work claim/read/renew/release/fail。DSH 插件：data.read/propose。

## 权限和前置条件
用户为 Editor；目标为 Claim；Map 无活动 Run；Workspace 有 verify router、merger 和至少一个 worker。Host/插件持内部 token，proposal 还必须持未到期 grant 的 holder/fence。

## 正常调用链
1. `ApplicationService.dispatch` 在事务中解析 Workspace 配置；`runCreateRun` 冻结配置及 Claim/News revision。
2. Host 轮询 `dispatchWork(claim)`；`workReadItems` 先派 route，再派所有未完成 slot，最后派 merge。
3. `dshRunWork`读取授权数据、选择 profile、生成 persona 和临时 patch；DSH business plugin 限制工具并通过 data_read/data_propose 交付。
4. `GraphService.propose` 验证工作身份、lease 与输入 revision，以 CAS 提交 route/report/draft。
5. 自动模式 merge 后生成 Verification；人工模式创建 Review，用户批准后继续或入图。

## 分支与异步续接
路由可重复选择同一 Agent 承担不同角度，slot 工具只能是该 Agent 白名单子集。人工 route 更新增加 route/review revision，批准后 Host 才发现 worker。多个 worker 可被多个 Host 并行领取。

## 持久化读写
Run、route、reports、draft、review、lease、回执和结果节点全部原子写入 graphv3。DSH 通知和未提交思维过程不入库。

## 状态迁移
详见 ST-01。失败包括用户拒绝、显式取消和 Host 上报不可恢复错误；失租自身不直接宣告 Run 失败，其他 Host 可接管。

## 消息与跨服务调用
Host/插件与图服务用内部 HTTP；工作执行通过本机 DSH SDK/子进程。工具和模型 provider 保持外部黑盒。

## 异常、补偿和并发
续租失败或保守截止触发 Abort 并等待 runtime 关闭；release 只释放本人 fence。独立 report CAS 冲突只重试数据库提交，最多 64 次，不重跑模型。相同 proposal 可由回执确认；旧 fence、迟到 proposal、缺报告 merge 均拒绝。

## 当前实现边界
每 Host 容量为 1；外部工具副作用不保证恰好一次。客户端使用轮询，不消费 DSH 事件流。
