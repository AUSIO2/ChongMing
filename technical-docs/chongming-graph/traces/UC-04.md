# UC-04 节点范围协作处理

## 业务目标与完成条件
从用户选择的 Source、News 或 Claim 出发，按 until 推进到 News、Claim 或 Verification。范围闭包内所有必需 Operation 有有效产物或明确空结果、没有遗漏后继和待审项时完成。

## 入口与调用者
用户：run.start/pause/resume/cancel、review.update/answer、run.get。Host：work claim/read/renew/release/fail。DSH 插件：data.read/propose。

## 权限和前置条件
用户为 Editor；scope 非空、不重复且只含 Source/News/Claim；同图无活动 Run。所需阶段必须有冻结配置。Host/插件持内部 token，proposal 还必须持未到期 grant 的 holder/fence。

## 正常调用链
1. `ApplicationService.dispatch` 在事务中解析 Workspace 的 parse/split/verify 配置；`runCreateRun` 冻结 scope、until、regenerate、配置。
2. `runUpdateProgress` 在同一图快照上遍历范围：Source 生成 parse，News 在目标更深时生成 split，Claim 在 until=verified 时生成 verify；接受产物后继续扩展明确后继。
3. Host 轮询 `dispatchWork(claim)`；`workReadItems` 可同时返回多个 Operation 的 ready 工作。parse 单工作；split/verify 各自保留 router→workers→merge。
4. parse 首次读取共享 Asset 或受限公共 URL 正文并保存 rawContent。`dshRunWork` 选择 Operation profile、生成 persona/临时 patch；业务插件按 Operation kind 限制 proposal 与工具。
5. `GraphService.propose` 验证工作身份、lease、输入、配置和候选引用，以 CAS 同时提交节点、边、空结果、Operation 状态、后继和回执。

## 范围、复用与分支
until=news 不为已有 News/Claim 继续派生；until=claims 处理 Source/News 但不核查 Claim；until=verified 走完整链。derived-from 扩展 Source→News、News→Claim 的后继，不沿 related-to 或共享 Claim 的其他来源反向扩大。

默认从历史 Run 复用 kind、目标、输入版本、配置 hash、输出版本和关系均有效的已完成 Operation。`regenerate:true` 新建 Operation；既有人工数据不删除。parse 可输出零 News，split merge 可选择零 Claim，空 outputRefs 同样是完成事实。

## 审核与暂停
Review 属于单个 Operation。parse result 展示 News 草稿；split route 可编辑角度，split result 展示引用的 Claim 候选；verify 延续 route/result 两轮。一个 Operation waiting 时，其他 Operation 继续运行。

run.pause 设置独立 paused 位并在同一授权事务中过期该 Run 的 lease。暂停不改 Review/报告/业务状态；暂停中可回答 Review，批准后仍 paused。run.resume 清 paused 并从共享状态重新派生工作，不恢复模型 Session。cancel 是终态。

## 持久化读写
Run、operations[]、input/output refs、rawContent、route、两类 reports、content/draft、review、lease、回执和产出节点/边都在 graphv3。DSH 通知和未提交模型上下文不入库。

## 异常、补偿和并发
pause 与结果按数据库接受顺序裁决：结果先提交则保留，pause 以版本冲突要求刷新；pause 先提交则旧 proposal/fail/renew 被 paused+lease 围栏拒绝。多个 Host 并发只重试数据库 CAS，不重跑已返回模型结果。失租中止 DSH，任意 Host 可在到期后用新 Session 接管。

## 当前实现边界
每 Host 容量为 1；客户端以快照轮询展示多 Operation。外部工具可能重做，业务结果只接受一次。完整管理 UI 和 SSE 尚未完成。
