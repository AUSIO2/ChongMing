# UC-06 导出与导入可移植工作区

## 业务目标与完成条件
把 Map 或 Workspace 连同 Agent 与所引用资产导出为 v3 JSON，并安全导入为新的独立 Workspace。

## 入口与调用者
两个 GET export 路径与 workspace.import command。

## 权限和前置条件
Map 导出需要 Viewer，整个 Workspace 导出需要 Owner。导入包先作为 staging Workspace 的 ready Asset 上传；调用者必须是 staging Owner。

## 正常调用链
导出：`AssetsService.export* → snapshot transaction → bundlesRead* → assetsAttachBundle`。导入：读取并验证 bundle 字节 → `bundlesReadWorkspace` → `bundlesCreateImport` 重映射 ID → 准备 GridFS blob → 认证事务发布 Workspace、Map 和 metadata。

## 分支与异步续接
MapBundle 转换为单 Map 的新 Workspace；WorkspaceBundle 保留多个 Map。导入结论标 stale；历史 reportId 与无法对应的 Agent 标签保留。

## 持久化读写
读 graphv3/control_workspaces/control_assets/GridFS；成功事务写新 Workspace、多张 Graph、资产 metadata 和 import receipt。

## 状态迁移
新 Map aggregate revision=0，Node/Edge 原 revision 保留；run、runHistory、lease、执行回执清空。blob 在事务前私有准备，事务后成为 ready 引用。

## 异常、补偿和并发
格式、版本、字段、base64、摘要、重复 ID、引用闭包、数量和 64 MiB 上限先验证。确定回滚时删临时 blob；提交结果未知时保留，避免删除可能已发布的 blob。同命令重试返回原导入结果。

## 源码证据
`backend/assets.ts#exportMap/exportWorkspace/importWorkspace`；`backend/bundles.ts#bundlesReadWorkspace/bundlesCreateImport`；`backend/control.ts#createWorkspace`。
