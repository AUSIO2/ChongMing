# 095 — 后端功能与前端对应审计

日期：2026-10-17。基线：`codex/architecture-migration`，HEAD `80a32d5`，**包含当前工作区全部未提交实现**。历史计划不作为功能已经落地的证据。

## 1. 审查范围与结论

检查了公共契约、应用分发、HTTP 路由、桌面 IPC、前端网关/状态和实际组件入口，并单独检查管理员 CLI 与 Host 内部能力。当前公共客户端有 **16 个查询、29 个命令，共 45 个方法**；此外有文件上传/下载/导出与图事件订阅。

主要结论：基础工作台、成员/智能体/设置管理、资产传输、运行控制和证据库浏览已经接入。缺口集中在**图关系编辑、定义发布与通用配置、复杂运行编排、审核前的信息完整性，以及证据使用的反向追溯**，不能把整个管理面或证据库误报为“没有前端”。

在 `apps/ui` 脚本中核对方法名并追踪调用，41 个方法已有直接引用，4 个没有：

| 方法 | 实际判断 |
| --- | --- |
| `map.delete` | 缺用户入口与会话动作；不是顶部关闭标签的 × |
| `definition.publish` | 缺发布入口与管理页面 |
| `run.get` | 当前运行通过快照读取；按 ID 读取归档运行的能力未接，历史目录还需后端补充 |
| `asset.get` | 无直接调用，但 `asset.list` 已返回并展示完整资产元信息；不据此认定资产详情缺失 |

**方法被调用不等于业务能力完整。** 以下逐项区分参数、展示、入口一致性和部署能力。文中的“已接”仅表示源码链路存在，不代表本次进行了端到端验收。

### 核验案例

以下是依据代码可构造的验收步骤，本次未实际提交这些业务写入：

1. 手动添加新闻和事实，尝试连边并标注出处：当前不能建立边（F01）。
2. 有两个选择阶段结果时进入发布审核：当前无法核对完整发布集合（F02）。
3. 完成运行后修改原输入：详情应提示版本不同，当前只显示当前文本（F03）。
4. 对相同陈述/适用范围先后收录相反判断：后端返回冲突条目，UI 无冲突对照（F06）。
5. 完成运行 A，再启动 B：A 被归档后选择器中不再出现（F11）。
6. 打开 SQLite 本机服务的证据库/选材：服务未装配此能力，但 UI 入口仍出现（F08）。
7. 偏好保存时制造一次网络故障或版本冲突，然后仅刷新同工作区：后续选择不再触发有效偏好保存（F17）。

## 4. 已有对应、无需再补一套的能力

- **文件链路**：上传，资产下载，当前图导出，工作区导出，上传包导入新工作区；三种 download.kind 均有入口。文件大小、校验、权限与失败重试已处理。`AssetManagement.vue:93,212,242,276`。
- **实时链路**：snapshot/activity/refresh/error 事件已有状态处理，断流重连、身份失效与失去图权限已有退出/清理；问题是图内活动展示不足（F20），不是没接 SSE。`client-session.ts:384`。
- **连接链路**：远程地址/令牌登录、条件记住登录、退出；桌面本机服务启动、恢复模式、故障提示、切回本机；Web 的本机桥接缺失属于环境边界，不是按钮漏接。
- **来源行脚注**：手动多字段、离散行/连续范围、摘录与原文版本校验、双向跳转与高亮、旧版摘录保留均已接。`NodeReader.vue:235`、`SourceAnchorEditor.vue:75`、`client-session.ts:902`。
- **权限和租约**：工作区角色、只读状态、编辑权与运行控制权、领取/续租/释放均有处理；SQLite 本机有意不使用客户端租约。
- **证据库追溯**：库条目到当前/历史消费者、固定消费者正文、使用理由与跨图定位已经实现。F04 缺的是反向的“从当前节点回到所用库条目”。

## 5. 需要两端共同设计，不能仅算前端遗漏

| 目标 | 现有后端边界 | 应补的能力 |
| --- | --- | --- |
| 全工作区、跨数据图的总关系图 | 没有现成的轻量工作区总图接口。可逐图 map.get 拼装，但没有全局分页/快照一致性/聚合约定；证据库 relations 仅单根收录时邻域，限 128 节点、256 边、深度 8 | 两端共同确定工作集、身份、跨图关系语义与增量/聚合查询 |

| 自动提取时产生精确行脚注 | GraphProposedOutput 只有 sourceKeys，没有行定位字段；自动发布边不生成 sourceAnchors | 输出合同、模型工具、服务端定位校验和发布映射先补，阅读页继续复用已有脚注 |
| 人工逐候选编辑/只批准部分候选 | review.answer 只有 Operation 级 approve/reject，选择阶段由模型产出 | 若产品需要，新增版本化候选编辑/选择协议；不能伪装成现有审核按钮可直接支持 |
| SQLite 本机证据库 | 证据库需要 Mongo 查询适配器，local 入口未装配 | 提供本机后端能力，或在能力声明中明确不可用并门控界面 |
| 替代/合并/重新激活库条目 | 有 superseded/replacementEntryId 状态字段，但公开命令目前只有 collect/withdraw | 先定义后端写入规则和接口，再增加界面 |
| 库的日期/地点/条件筛选、排序 | EvidenceSearchParams 只有 query/confidence/subject/event/includeInactive/游标/limit | 需要新增后端查询语义；当前 UI 已覆盖现有业务筛选参数 |
| 用户名密码登录、注册、找回密码 | 当前只有令牌认证，没有对应公共账号密码接口 | 身份服务、凭据生命周期与前端共同设计 |

## 6. 管理员/宿主能力的界面边界

`apps/graph-server/admin.ts:44` 提供以下 CLI 能力，当前普通管理页面没有对应操作：

- 身份初始化、创建用户、签发/撤销令牌、启停用户。
- 默认智能体初始化、资产清理、旧数据修复与离线分支迁移。
- 本机部署设置读取、密钥设置、数据库检测/暂存、模型/网络端点测试。

这些确实属于“后端有、图形界面没有”的宿主功能，但**现有公共 ClientGateway/HTTP/IPC 没有对应受控接口**。若要做部署管理中心，需要先设计 hostAdmin 授权和本机/远端执行边界；不能从 Renderer 直接调用 CLI 或暴露内部令牌。当前 SettingsManagement 只对应 ClusterSettings，不等价于 API 密钥/数据库设置中心。

`/health` 和 `/internal/v1/{messaging,data/read,data/propose,activity,work}`、Host 的 claim/read/renew/release/fail、队列/outbox、fence/receipt，以及独立 DSH 诊断服务属于内部执行/部署能力。它们由传输、会话或 Host 消费，不需要逐接口设置普通用户按钮。
