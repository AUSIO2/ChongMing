# 073 — 文件树与模块命名整理

用户要求在072内部重构前，立即通过真实文件树和命名明确module归属。本阶段移动现有文件、修正导入和运行路径，保持导出函数、协议、持久化和业务行为。

## 文件组织

- backend/modules/graph：图操作、Run状态、Work推导与活动。
- backend/modules/workspace：工作区、成员、Agent库和配置校验；后续072再处理内部职责。
- backend/modules/identity：用户、令牌与写入身份验证。
- backend/modules/assets：资产与数据包。
- backend/modules/shared：领域错误、公共输入校验。
- backend/application：业务调用与事务装配。
- backend/ports：已有存储、消息与来源读取interface。
- backend/adapters/{http,storage,messaging,sources}：网络与实际存储/传输adapter。
- backend/execution：Host工作执行；dsh子目录包含运行时、提案执行、活动、渲染和插件资源。
- apps/{graph-server,execution-host,local-server,dsh-diagnostics,desktop,ui,cli,config}：各运行入口和共享装配配置。
- apps/ui/features/{graph,run,workspace,agents,assets,settings,management}：按界面用途归类；state和transport明确会话/桥接位置。
- tests按源码module分组；共享夹具保留明确fixtures目录。

具体旧路径到新路径见[073文件迁移表](./073-文件迁移表.json)。一个文件只移动到一个目标，不保留旧路径转发或重导出。

## 迁移约束

相对import、动态import、测试mock和fixture路径使用旧文件位置解析，再按新位置重算。项目根路径、package命令、Vite入口、DSH插件侧文件、构建复制和校验脚本同步更新。

DSH的work-executor.ts、patch和plugin继续同目录，打包后patch/plugin仍复制到service/main.mjs旁。不得改成依赖源码树的绝对路径。

初版快照包含未跟踪文件；运行源码和测试的非路径语法需要与移动前相同。新文档/检查逻辑单列，避免将文件移动伪装成行为重构。历史审计来源保持历史含义，现行说明与072计划更新为新路径。

## 验证

检查所有映射目标存在、旧文件不再存在、所有相对引用可解析；检查module依赖和本机/协作隔离；运行类型、全量测试、052/064校验、桌面运行时和构建。语法对照验证移动未修改业务表达式。
