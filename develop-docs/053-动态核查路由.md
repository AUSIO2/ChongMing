# 053 — 动态核查路由与自定义 Agent/Tool

用户明确：根据Claim动态选择核查角度、自定义Agent和tool是核心功能。替换第三阶段的固定两个报告及代码投票，不再把这两项当作可延期优化。新后端独立实现，旧Mapper工作树不改。

## 执行与数据边界

一次Run冻结configuration：router、merger、候选agents、工具名称/用途、maxSlots以及Claim/上下文版本。profile包含稳定id、名称、说明、可配置content、provider/model与tools白名单。默认配置来自backend/prompts/verify/，每个提示词独立JSON；run.start可显式提交自定义configuration，均校验后持久化。

工具声明描述能力；实际代码由可信Host的DSH插件/patch注册。未知实现或provider报错，禁止静默忽略。模型不能通过路由临时上传代码、凭证或扩大工具白名单。

```text
Claim + 配置 → DSH根路由Agent → route提案
  → auto批准 / HITL路由Review
  → DSH按批准slots委派任意N个worker
  → 每slot一个结构化报告（报告齐全才允许汇总）
  → DSH汇总Agent提交score/reason/reportIds
  → auto接受 / HITL结果Review
  → 结论+边+收据+完成状态同次CAS
```

路由slot包含id、agentId、angle、priority、hint和tools。slots至少1个、至多maxSlots；同一个Agent可承担多个不同角度；工具必须属于候选Agent白名单。批准前不接收报告。报告数量等于批准slot数量，不固定为2。

保持一个操作的路由在批准后不可变；修改待审路由提升route/review版本。报告和最终草稿绑定批准route版本与输入版本。明确重试必须用新Run ID。终结Run保留紧凑历史，结果内保留意见/作者/角度/tool出处。

## 接口变化

- run.start增加可选configuration；run冻结实际配置，不读取后续最新配置。
- review增加kind=route/result。review.answer按类型放行workers或接受canonical结果。
- review.update允许修改pending route；不复活已终结Run。
- internal data.read返回configuration、route、reports、draft、phase和服务端proposalId。
- internal data.propose使用route/report/merge三种有限提案，不再只有report。
- internal接口需要Host配置的Bearer token；插件依据真实DSH Agent身份注入router/worker/merge角色和slot，不让模型自报调用者。token认证可信Host，不隔离持有token的Host管理员；operation绑定在插件闭包，跨Host能力令牌与领取租约留待多Host阶段。
- DSH增加data_delegate，只能从当前批准路由取slot或在报告齐全后委派merger；使用原生startContinuable执行，不重写Agent队列。

一次独立操作的DSH执行器根据冻结配置装配根模型/persona；支持可信自定义patch。当前仍是loopback开发服务，完整多人鉴权与多Host领取留在既定后续阶段。本轮不使用此前泄露的模型Key。

## 正确性

并发内部提案在CAS冲突后重新读、校验原提案再提交；不重跑模型。取消、旧路由、未知slot、错误角色立即拒绝。最终报告集必须精确覆盖所有slot；不能根据相同评分或固定规则生成结论。

DSH工具过滤在执行处生效：根只做路由/受约束委派及声明工具；worker只能自己的slot；merger只能汇总。保留原生子Agent服务，拦住未经批准的原生subagent/fork/workflow绕过入口。自定义tool须有真实已注册实现。

## 文件与函数

| 文件 | 主要入口 | 职责 |
|---|---|---|
| contracts/graph.ts | GraphRunConfiguration / GraphRoute / GraphDataProposal | 前后端共享数据与命令类型 |
| backend/input.ts | inputReadObject/String/Id/Revision/Array/Names/Score | HTTP和配置边界的基础校验 |
| backend/configuration.ts | configurationRead / configurationReadSlots | 读取自定义配置、校验引用与工具白名单；组合默认JSON |
| backend/api.ts | apiCreateServer | 两个公开端点、两个内部端点及输入解析 |
| backend/graph.ts | graphCreateService → read / dispatch / readData / propose | 读图、派发命令、鉴别重复请求、提交CAS |
| backend/run.ts | runCreateRun / runCancelRun | 冻结配置和输入版本、启动/取消 |
| backend/run.ts | runReadData / runUpdateProposal | 投影当前阶段、接受路由/报告/汇总；不调用模型 |
| backend/run.ts | runUpdateReview / runAnswerReview | 人工修改待审路由、批准或拒绝；原子接受结论 |
| backend/store.ts | storeCreateGraphStore → read / create / commit | 单Map文档持久化与版本CAS |
| backend/dsh-business-plugin.mjs | data_read / data_propose / data_delegate 工具 | 从真实Agent身份绑定slot，调用DSH原生委派及内部数据接口 |
| backend/dsh-verify.ts | 单operation执行入口 | 从图读取冻结配置，装配独立DSH执行环境，运行至审核或完成 |
| backend/prompts/verify/ | router / merger / agents/*.json | 可编辑persona、候选能力和默认模型配置 |

代码只维护数据状态机和约束委派，不新增Agent队列、调度器或记忆实现。通用DSH服务不加载业务插件；只有绑定具体operation的执行器装载该插件。

## 验收

1个slot和3个以上slot都能完成；同Claim在不同配置下得到不同合法路由；路由引用未知Agent/tool失败；HITL未批准不执行；只收到部分报告不能merge；并发报告不丢失；同slot和同proposal不重复接受；汇总结果不受旧二票代码控制；取消与旧Run回调拒绝；配置快照/意见出处可恢复。插件验证persona/model/toolFilter确实传给原生DSH，并验证未知调用者和越权工具被拒绝。
