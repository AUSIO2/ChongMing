# 100 — 全库防御与兼容逻辑复查

## 目的与范围

在 099 已完成的 24 组清理基础上重新扫描全库，沿调用链继续清理剩余不必要兜底、重复验证和失效兼容。不以既定数量作为停止条件。保留工作区已有功能修改和 099 修复。

## 接口与约束

- 覆盖 apps、backend、client、contracts、platform、scripts、运行与构建配置，并核对相关测试和实验夹具中的真实调用者。
- HTTP、IPC、文件、持久化记录、模型输出等真实未知来源继续在各自入口校验。服务内部已解析值建立窄类型后直接使用；不通过重复解析补偿不准确类型。
- 保留授权与写栅栏、幂等收据优先级、并发版本和最终租约检查、事务、固定历史内容、容量及摘要约束。
- 可选字段与未装配能力须符合真实装配路径；只删除证据充分的死状态。业务确实支持的旧记录、历史 Run 与显式迁移入口不因名称含 legacy 而移除。
- 不引入新的兜底、兼容转发、无依据断言或全吞异常。不为减行数把复杂度转移给多个调用方。
- 前轮未定论的递归复制、历史定义对比、WebGL 捕获范围与服务重复解析必须重新核对前提，确认后实施；确有必要则记录依据。

## 实施与恢复

按 UI、业务、运行适配、客户端四个互不冲突的文件范围并行核查，交叉审阅边界权属和必要校验。修改前保存当前工作区差异与未提交文件副本。没有数据迁移、部署、提交或推送；恢复只撤销本轮新增差异。

## 验证

运行与实际改动匹配的既有单元与集成测试；行为修复补充能复现问题的回归，纯删除不增加镜像实现测试。最终执行 Vue/TypeScript、架构/运行文案及差异检查。记录新增清理清单、必要保留项、实际通过/跳过/失败及未覆盖范围。
