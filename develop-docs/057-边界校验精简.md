# 057 — 边界校验精简

本轮根据实际调用链精简重复校验和掩盖异常的兜底，不以删除安全边界换行数。沿用 ponytail 原则，使用标准 JSON 序列化，不增加依赖。

## 已确认的重复

- 正式 Run 配置调用链为 control.configuration → graph.dispatch → runCreateRun，同一份对象被 configurationRead 连续解析三次。保留工作区配置组装处的校验，内部 Graph/Run 接收已校验的类型，只复制冻结数据。
- 路由在 apiReadCommand/apiReadProposal 中经 configurationReadSlots 解析，再到 runValidateSlots 重做结构解析。保留入口解析，Run 层只检查与冻结配置相关的数量、唯一性、Agent 存在及工具授权，并复制提交的 slots。
- graphInputReadNodeData 已使用各 kind 的字段白名单，之后的禁用字段判断属于重复检查，可以删除。未知字段、缺失必填字段、来源 URL、分数等入口校验保持。
- DSH SDK 的通知来自 JSON-RPC；自写递归转换器仍把非 JSON 值转成字符串。替换为标准 JSON 复制，保留 undefined 对象字段省略语义；不可序列化的值直接报错。
- 桌面凭证读取的 catch 原来把所有读盘异常当成没有登录。仅保留文件不存在/损坏 JSON 的重新登录路径，其他文件系统错误上抛；系统密钥不可用时不返回 token 的行为保持。

## 保留的逻辑

HTTP/IPC/模型和文件导入都是外部输入边界，不能因为有 TypeScript 接口就删掉运行时校验。角色、版本、幂等回执、租约 fence、Agent 工具权限及报告完整性属于业务约束，保留。网络错误的统一提示与显式重试不是返回假数据。

Mongo lean 读取不会应用 schema 默认值；旧 Graph 中字段是否完整不能只凭 TypeScript 推断。本轮不盲删存储默认值，也不增加新的读时兼容路径。新旧后端源码清理仍待剩余功能接线完成。

## 验证

补充非法路由结构和节点混用字段仍在 HTTP 入口拒绝的回归；标准 JSON 通知的深复制与不可序列化值回归；凭证读盘异常不会被吞掉的回归。运行相关测试、类型和全量现有测试，报告实际净行数，不承诺未经验证的大幅压缩。
