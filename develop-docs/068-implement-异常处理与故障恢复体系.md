# 068 — 异常处理与故障恢复体系实施原稿

编写日期：2026-09-14。状态：主体实现完成，原生Electron故障界面待解锁验收。技术决策与退出语义见[设计](./068-异常处理与故障恢复体系.md)，模块边界遵守[067架构](../ARCHITECTURE.md)。

## 1. 实施顺序与依赖

默认顺序为 `A → B → C → E → D/G → F → H`，优先补齐P0进程与原生端边界。D和G在B/C完成后可以独立推进；若E的原生窗口验收等待解锁，可先完成D/G等独立工作，但不能把E标为已验收。F依赖A中的错误合同及D/E中的传输、恢复入口。此处是工作包依赖，不预设多代理或多人并行执行。

| 工作包 | 优先级 | 交付物 | 退出条件 |
|---|---|---|---|
| A 错误合同与诊断基础 | P0 | 公共投影、errorId、报告端口、脱敏及受限日志 | 序列化/泄漏/循环对象/日志故障负例通过 |
| B 所有入口的终端责任 | P0 | Node/Main全局fatal、启动边界、错误退出码 | 真子进程抛错/拒绝后记录并非零退出 |
| C 受控关闭与资源所有权 | P0 | 总预算、停止准入、部分启动补偿、关闭结果 | 启动中停止/关闭步骤失败/永久等待均有界 |
| E Electron进程与加载故障 | P0 | 加载/崩溃/卡死处理、Main外的恢复入口 | 真实窗口可提示/重开，业务服务状态正确 |
| D HTTP、SSE与IPC传输 | P1 | 安全响应、故障关联、二次失败与就绪状态 | 500有诊断、断连不误杀、客户端无泄漏 |
| G Host与消息错误策略 | P1 | 重试分类、故障向上通知、坏消息/程序错误分离 | 暂时失败可恢复，永久故障不无限重投 |
| F Vue/Web错误边界 | P1 | mount前全局钩子、最小错误页、业务错误链收敛 | 根错误有退路，取消/表单错误不过度升级 |
| H 故障矩阵与发行验证 | P0 | 故障报告、运维说明、打包与平台验证 | 满足技术设计第10节，无未解释失败 |

## 2. A：错误合同与日志

- [ ] 汇总GraphError、ClientError、QueueError、WorkAccessError、桌面服务错误和进程退出结果；为现有码逐项标记安全消息、类别、范围和重试规则。
- [ ] 定义DiagnosticReporter、上下文白名单、errorId和公共错误投影；保留现有业务码，不增加平行错误类。
- [ ] 实现未知错误的安全转换，不直接沿用Error.message。为已审查业务消息建立明确映射，保留合法的currentRevision等字段。
- [ ] 实现节点身份/请求关联：requestId保持幂等职责，errorId保持故障职责；抛出非Error值也能得到安全结果。
- [ ] 实现stderr结构化输出、桌面文件滚动、去重/采样、容量限制和降级路径；停止对第三方stderr无限原样追加。
- [ ] 统一所有HTTP/SSE/IPC/CLI序列化器及客户端类型；业务端口通过apps注入记录器，更新依赖审计的精确规则。
- [ ] 验证调用栈首行、cause、URI、授权头、模型文本、路径以及超长/循环对象不会穿透脱敏。

验收证据：相同错误编号能关联安全响应与诊断；未知错误对外只有固定摘要，日志包含安全栈帧；记录器损坏时不会递归，也不无限占用内存。

## 3. B：入口兜底

逐一覆盖，不以一个公共工具文件代替实际接入：

| 入口 | 必须纳入的路径 |
|---|---|
| apps/server/api.ts | 配置、数据库连接、初始化、监听、消息启动、信号 |
| apps/server/host.ts | 配置、传输连接、Host主循环终止、信号 |
| apps/server/admin.ts | 解析、临时连接、命令执行、输出、finally关闭 |
| apps/local/main.ts及runtime.ts | 本机文件/身份启动、队列终止、HTTP及Host装配、部分失败补偿 |
| apps/desktop/service.ts | 父IPC、就绪消息、启动期间disconnect、关闭拒绝和ready发送失败 |
| apps/desktop/client-main.ts | whenReady、窗口创建/加载、全局fatal、before-quit |
| apps/cli/main.ts | stdin/stdout/stderr、客户端请求、信号及清理 |
| apps/dsh/main.ts | 诊断运行时启动、监听和退出，不因非默认入口而遗漏 |

- [ ] 把进程监听注册在可行的最早入口；需要时拆出薄bootstrap和受保护实现加载。
- [ ] 为uncaughtException和unhandledRejection提供幂等、同步、终止性的处理；验证Electron已有监听器不会使其继续运行。
- [ ] 捕获入口Promise以及catch/finally返回的次级Promise；解决仅设置exitCode但仍有活动句柄的情况。
- [ ] 全局warning分级/限频，不能把SQLite实验性提示等普通warning一律视为致命故障。
- [ ] 释放测试/HMR生命周期中的监听器，避免重复注册后多次退出或重复日志。

验收证据：在计时器、Promise和事件回调中注入逃逸异常，实际子进程在预定上限内非零退出；终端日志最多一份主故障，退出后没有继续执行的业务标记。

## 4. C：关闭协调与资源所有权

- [ ] 从实际资源取得顺序列出反向清理责任，覆盖失败发生在每一项资源取得前后。
- [ ] 明确starting/ready/degraded/stopping/stopped，阻止停止后的新工作和迟到ready。
- [ ] 一开始停止就启动总预算；等待starting、finally和子进程回收都算在预算内。
- [ ] 先停新claim和公共写入，再排空Host；保留内部释放/在途事务收尾的必要API窗口。
- [ ] 关闭步骤失败时继续其他安全清理，结果同时保留主故障和各失败步骤。
- [ ] Main、桌面子服务、独立服务、协作入口和CLI采用相同原则及各自预算；重复信号复用关闭任务。
- [ ] 父进程突然消失、子进程提前退出、IPC断开和强制树终止分别处理；确认旧实例离开后才允许重启。
- [ ] 致命逃逸路径不复用这一套异步业务关闭逻辑；只执行最小fatal出口。

验收证据：分别让Host.close、server.close、queue.close、database.close、logger.flush拒绝或永久等待，整体仍退出；没有把原始错误改写成最后一个清理错误，SQLite锁/端口实际可重新取得。

## 5. D：传输边界

- [ ] HTTP最外层区分业务、断连和未知异常；未知异常生成errorId并记录路由模板及上下文。
- [ ] 错误回复本身失败时，避免再次writeHead/end；记录一次次生发送失败后结束连接。
- [ ] SSE首次/后续帧、鉴权、背压超时、心跳、订阅注销和写失败分别有归属。
- [ ] IPC未知异常只返回安全公共错误，保留现有sender/主Frame验证；Renderer提交诊断需要独立限长、限频和字段校验。
- [ ] 定义健康/就绪/降级能力，不把MQ降级误当成API数据库不可用；停机后拒绝新增业务准入。
- [ ] 客户端使用服务端提供的恢复语义；网络回包丢失提示结果可能未知，既有同身份重试保持。

验收证据：请求未知异常不会泄露原始消息，且能在日志找到errorId；客户端取消、SSE关闭、上传中断和EPIPE不会杀掉服务；错误回复再次失败不会形成未处理拒绝。

## 6. G：工作执行与消息

- [ ] 明确Host主循环终止的可等待结果/终止通知，由入口决定进程退出与状态；不能只console.error后结束内部循环。
- [ ] 审计所有重试分支，白名单区分网络/选主/忙租约等可恢复原因与协议错误/不支持配置等永久原因。
- [ ] 检查队列handler失败是否错误ACK、无限重投或被坏消息catch吞掉；监听器程序错误应向上升级。
- [ ] 本机通知失败保存安全原因并解除订阅；修正“先aborted后跳过unsubscribe”等关闭路径。
- [ ] 保留work.fail的有效grant验证；取消、暂停、租约丢失和系统停机不转成Run失败。
- [ ] 重连错误聚合计数，恢复单独记录；Activity允许丢弃但有计数，不能静默隐藏核心调度失败。

验收证据：真实MQ/DB中断后能恢复，永久协议错误停止无效循环；重启后已接受报告不重做，旧grant不得写入，系统停机不修改用户Run终态。

## 7. E与F：桌面/浏览器恢复体验

- [ ] Main捕获窗口加载失败、Renderer进程退出、卡死/恢复和Electron子进程异常。
- [ ] 恢复入口由Main或最小静态页持有；Vue已崩溃时仍能提示并重新打开界面。
- [ ] 页面级重载不会自动重放最后一次写操作；说明未保存表单可能丢失。
- [ ] Vue mount前安装全局错误钩子及浏览器error/unhandledrejection；router加载失败单独处理。
- [ ] 根渲染失败、普通按钮异步失败、业务拒绝、用户取消采用不同UI范围，不全部显示崩溃页。
- [ ] 审计session.disconnect、handleFailure、watch重连、偏好保存和管理刷新中的次级失败，避免错误处理函数再向外逃逸。
- [ ] UI展示安全说明、错误编号及有效动作；重复错误页失败停止自动刷新，回退Main控制的退出/恢复。
- [ ] Main监听到已停止/崩溃的子服务后同步清理过期gateway状态，重试成功才建立新连接；原有远程凭据仍独立保存。

验收证据：真实Electron分别触发加载错误、Renderer崩溃和卡死；Web/Vue注入渲染与异步异常。验证提示、按钮、重新连接、保存数据、未保存输入提示、沙箱与受限IPC。

## 8. H：故障注入矩阵

| ID | 注入场景 | 必须观察的结果 |
|---|---|---|
| F01 | Node定时器同步throw | 一次主fatal记录、非零退出、后续业务不执行 |
| F02 | 未处理Promise拒绝，含字符串/非Error理由 | 安全记录并退出，不因序列化再次崩溃 |
| F03 | 启动实现模块导入失败 | 由已建立的bootstrap或父监督报告；没有无限等待ready |
| F04 | server.listen端口占用 | 明确启动失败，已取得资源释放，非零退出 |
| F05 | 启动一半收到停止/父IPC断开 | 无迟到ready，关闭预算从停止开始计算 |
| F06 | 关闭步骤拒绝、另一关闭步骤挂住 | 后续安全清理尝试执行，最终在预算内退出 |
| F07 | 记录器写入拒绝、目录不可写或缓冲饱和 | 有界降级，不递归、不OOM、不改变业务收据 |
| F08 | Error含Token/URI/正文/路径/stack首行秘密 | 所有公共输出和默认日志均无秘密哨兵值 |
| F09 | 循环cause、BigInt、抛错getter、超长堆栈 | 输出受限、安全退路可用 |
| F10 | 同一异常经过多层catch | 同一编号可关联，主堆栈不重复刷屏 |
| F11 | HTTP业务409/403与未知异常 | 前者安全业务提示；后者通用500+可追溯编号 |
| F12 | headersSent后流失败，错误回复再失败 | 不重复写头，无未处理拒绝，连接结束且有诊断 |
| F13 | 上传中止、客户端断连、CLI stdout EPIPE | 确定的取消/退出行为，其他请求仍可用 |
| F14 | SSE背压、授权撤销、订阅回调异常 | 对应关闭/拒绝准确，根因有记录且无权限泄漏 |
| F15 | MQ黑洞/断线/恢复 | 停止无授权执行，重连补发，日志限频并记录恢复 |
| F16 | MQ坏消息与业务handler抛错 | 两者分别计数/处理，程序错误不被当作坏消息吞掉 |
| F17 | 永久协议/配置错误 | 不无限重投，不声称运行仍健康 |
| F18 | Host运行循环意外终止 | 入口/监督可感知，进程状态和退出码一致 |
| F19 | SQLite本机通知失败 | 保存终止原因、清理监听器、有界停服务 |
| F20 | Mongo选主/短时不可达 | 恢复策略不改变幂等身份或已有报告 |
| F21 | 业务数据库写入失败、文件写满 | 无半提交成功；不虚构失败/完成收据 |
| F22 | SIGKILL或原生进程退出 | 不要求JS日志；锁恢复、事务回滚、旧lease受尊重 |
| F23 | 产物已提交、回包丢失后重启 | 同身份得到原收据，不重复节点和边 |
| F24 | pause/resume与旧Host迟到 | fence有效，旧结果被拒绝，paused不被清理逻辑修改 |
| F25 | Electron loadFile/loadURL失败 | 能显示Main持有的安全提示与恢复动作 |
| F26 | Renderer崩溃/卡死/重复崩溃 | 明确提示，无自动刷新风暴，本机任务状态正确 |
| F27 | Vue根渲染、异步事件、router失败 | 各自进入合适边界；普通业务错误不误触发整页崩溃 |
| F28 | disconnect或handleFailure内部再次失败 | 最终可见且受控，不从错误处理链逃逸 |
| F29 | 错误页/诊断IPC自身失败 | 最小退路可用，IPC仍验证sender、大小和频率 |
| F30 | 子服务超时拒停、Main退出与重启竞争 | 只处理自有进程树，不重叠打开SQLite，不误报已退出 |

每条至少记录：运行入口/版本、平台、注入点、实际退出码、耗时、输出样本、脱敏断言、资源回收结果及重启后的业务断言。涉及Node全局错误和强杀的用例使用真实子进程；涉及浏览器/桌面的用例必须明确是单测、Web实测还是原生实测。

## 9. 交付检查与发布安排

### 9.1 基础检查

保留现有入口并增加故障专项命令，具体脚本在实现时提供：

```bash
npm run test:boundaries
npm run test:local
npm test
npm run test:desktop-runtime
npm run build:check
```

补充检查项：

- [ ] 故障专项可直接在无正式凭据环境运行；本机专项不依赖Mongo/Rabbit。
- [ ] 协作故障专项使用临时Mongo副本集与RabbitMQ，不操作用户服务。
- [ ] 审查新增void Promise、事件回调和空catch，逐处确认责任，不写一个“有catch就通过”的文本检查器。
- [ ] 日志实现不得使本机包重新引入Mongo/Rabbit依赖；更新入口/架构审计的允许清单。
- [ ] 从实际安装包注入服务故障并验证父IPC、错误编号和退出回收，不能只测试源码运行。
- [ ] 在当前Electron/Node版本实测生命周期；记录Mac锁屏等实际阻碍，不虚报平台覆盖。
- [ ] 旧业务测试数量及场景保留，运行结果按当前提交状态记录，不复用历史通过记录。

### 9.2 分批实施和回退

各工作包形成可独立审查的变更，先落合同和基础能力，再迁移入口与传输，最后收敛旧console/重复catch。原有业务错误路径在同一批次切换到新投影，不留永久双格式或别名。

首次启用采用本机与隔离协作环境；只有故障矩阵对应范围通过后，才进入正式部署或平台发行。此计划不授权部署、自动发送日志或操作他人服务。

本期不改业务数据库schema，回退代码不能清库。新增本机日志/诊断文件可独立保留或清理；如果实施中确实需要新增持久字段，必须先补充显式迁移和回退说明，不能隐式升级用户数据。

### 9.3 最终提交资料

1. 更新后的068实施记录，逐项标注完成/未完成及依据。
2. 全进程异常边界图和错误分类表。
3. 公共错误/诊断字段及日志位置、容量、脱敏说明。
4. 故障矩阵实际结果，包括失败用例和修复后重测。
5. 服务退出码、总超时、父/外部监督重启方式的运维说明。
6. 原生UI与平台验收范围，保留尚未验证的项目。

## 10. 实施启动时的第一步

先保存当前工作区基线与未提交修改，确认067模块边界和现有测试仍通过。随后执行A，接B/C的一个完整参考入口，再用相同机制覆盖其余入口。禁止只完成一个process.on监听器便宣布这一阶段结束。

## 11. 本轮实施记录（2026-09-14）

### 已完成

- 增加公共DiagnosticReporter、事件上下文和errorId；ClientErrorData与GraphFailure统一携带errorId。HTTP、SSE、IPC、CLI和界面调用方已一次性更新，没有双格式运行路径。
- Node诊断只保存事件名、组件、进程实例、固定上下文、错误类型/安全code及去除首行消息的有限栈帧。未知Error.message、cause、请求正文和环境变量不进入默认诊断。单条限制16 KiB、40帧；桌面文件5 MiB轮转、保留3个归档。文件写失败用一次同步stderr降级，不递归。
- 增加全局uncaughtException/unhandledRejection终端边界。实际子进程验证同步throw和未处理拒绝均只写安全fatal记录并以1退出，不在损坏进程中继续业务或执行异步数据库清理。
