# 069 — 旧后端收口与消息枚举

## 1. 目标

确认064/067之后旧后端的剩余范围，并将运行时代码中作为异常、失败响应或错误状态使用的硬编码message集中为TypeScript字符串枚举。提示词、数据正文、正常UI标题/按钮、日志事件名、CLI帮助和测试夹具文本不属于错误message。

## 2. 旧后端结论与处理边界

- 运行时代码不再包含旧Mapper、AgentLoop、LangGraph/LangChain/LangSmith、旧Electron API、旧src/flow-map或旧server/bootstrap入口；当前入口闭包与package依赖检查继续作为硬门槛。
- Git中旧文件表现为删除、对应新目录表现为新增，是尚未提交的目录迁移状态，不代表旧文件仍被加载。
- 旧Mongo集合和用户数据不自动删除。运行代码删除与数据销毁是两个动作；后者需要用户明确的数据迁移/清理任务和备份，不能因“清理完全”顺手执行。
- develop-docs、technical-docs及064/067本机归档继续保留，用于审计和恢复，不参与构建。
- Mongo修复/显式迁移工具属于当前协作存储维护能力，不视为旧执行后端。

## 3. 消息枚举设计

在contracts/messages.ts建立`RuntimeMessage`字符串枚举；所有运行层均可依赖contracts，避免core反向依赖UI或平台。动态文案使用枚举模板和一个`messageFormat`纯函数，变量按位置替换，不在调用处保留句子片段。

枚举成员使用可读英文语义名；相同完整文本复用同一成员。消息值保持当前行为，避免本轮把“抽取常量”混成产品文案改写。以后修改、国际化或安全审查只检查集中清单。

以下位置必须抽取：

- `new Error/GraphError/ClientError/QueueError/WorkAccessError/HostApiError/HostProtocolError`中的字面量和模板；
- 传给`clientCreateError/clientCreateIpcError/clientCreateServiceError`的错误文案；
- 错误响应或失败状态对象中名为`message`的字面量/模板及其fallback；
- abort/reject中构造异常的消息。

以下不抽取：

- 从远端合同读取的`error.message`、业务Run中已持久化的用户/Host失败message；
- Error基类中的`super(input.message)`等变量传递；
- 正常产品文案、提示词与结构化日志事件名；
- JavaScript DSH插件：Node直接加载`.mjs`，不能引用未编译的TypeScript枚举。本轮在插件内使用冻结消息表并由检查器要求所有异常文案引用该表；桌面构建继续复制该文件。此处是运行格式差异，不建立第二套业务错误合同。

## 4. 防回归

新增AST检查扫描apps/backend/client/contracts/platform的TypeScript运行文件和DSH插件：上述错误位置出现字符串、模板或字符串拼接即失败。检查器校验枚举值唯一，TypeScript编译校验成员引用，二者均纳入`test:boundaries`及构建。

检查器只针对消息语义，不以全库禁止字符串的方式误伤协议路径、错误code、事件名、UI文案和测试。动态message必须使用`messageFormat`，不得用枚举值再拼硬编码句子。

## 5. 验收

- 枚举前后错误code、status、retryable、errorId和实际message保持；已有断言不因文案变化而放宽。
- AST负例证明新增硬编码异常和message字段会使检查失败。
- 旧入口/依赖/目录检查通过；列出仍保留的历史数据、文档和归档边界。
- 运行故障专项、全量测试、类型、桌面运行时和构建通过。
