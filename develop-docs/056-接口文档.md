# 056 — 客户端接口与连接协议

本文补充 056 客户端边界。业务 HTTP 方法的完整参数、权限、CAS 版本和幂等规则沿用 [055 接口文档](./055-接口文档.md)；056 不新增业务 HTTP 路由。共享类型定义在 [contracts/client.ts](../contracts/client.ts)、[contracts/graph.ts](../contracts/graph.ts) 和 [contracts/control.ts](../contracts/control.ts)。

## 1. 调用链

桌面：`ClientHome → useClientStore → src/api.ts → window.chongmingClient → Electron Main → client/api.ts → Graph API`。

浏览器：`ClientHome → useClientStore → src/api.ts → client/api.ts → Vite 同源代理 → Graph API`。

客户端不调用 `/internal/v1`、不持有 Host token、不管理 DSH Session。Host 执行、失租接管、路由和结果提交仍由后端负责。当前只接核查界面，parse/split、完整管理和文件 UI、产品 SSE 尚未接入。

## 2. ClientGateway

`src/api.ts` 导出 `api` 单例；`apiCreateGateway()` 选择桌面桥或浏览器实现。所有业务查询和命令均有按方法名推导的输入/输出类型。

| 方法 | 输入 | 返回 |
| --- | --- | --- |
| `getConnection()` | 无 | `Promise<ClientConnection>` |
| `connect(input)` | `{baseUrl, token, remember}` | `Promise<AppBootstrap>` |
| `disconnect()` | 无 | `Promise<void>` |
| `read(method, params, signal?)` | 查询方法、参数、可选 AbortSignal | `Promise<QueryOutputMap[method]>` |
| `dispatch(requestId, method, params, signal?)` | 稳定请求 ID、命令方法、参数、可选 AbortSignal | `Promise<GraphSuccess<CommandOutputMap[method]>>` |

`ClientConnection` 为 `{baseUrl:string, configured:boolean, remembered:boolean, canRemember:boolean}`。不会返回原始 token。`configured` 表示客户端持有连接凭证，不代表本次网络验证成功；恢复登录仍须读取 `app.bootstrap`。

`baseUrl` 必须是 HTTP(S) origin，例如 `https://graph.example.com`，不能携带账号密码、子路径、查询参数或 fragment。`token` 为管理员签发的用户访问令牌，trim 后不能为空且只允许可打印 ASCII。`remember` 为 boolean，浏览器忽略持久保存意图。

连接时先终止旧客户端请求，清除旧会话，再验证新服务的 `app.bootstrap`。连接失败保持未连接状态。退出登录清空内存状态和已保存凭证；关闭桌面应用只结束客户端请求，保留已明确选择记住的登录信息。

## 3. 业务方法映射

| query method | 返回 data |
| --- | --- |
| `app.bootstrap` | `AppBootstrap` |
| `workspace.list` | `Page<WorkspaceSummary>` |
| `workspace.get` | `WorkspaceView` |
| `map.list` | `GraphMapSummary[]` |
| `map.get` | `GraphSnapshot` |
| `run.get` | `GraphRun` |
| `agent.list` | `AgentList` |
| `asset.get` | `Asset` |

| command method | 返回 data |
| --- | --- |
| `map.create`、`graph.apply`、`run.start`、`run.cancel`、`review.update`、`review.answer` | `GraphWriteResult`：snapshot、createdNodeIds、createdEdgeIds |
| `map.delete` | `{mapId, deleted:true}` |
| `workspace.create`、`workspace.update`、`agent.copy` | `WorkspaceView` |
| `workspace.delete` | `{workspaceId, deleted:true}` |
| `member.set` | `{userId, member:Member\|null, workspaceRevision}` |
| `preferences.set` | `Preferences` |
| `agent.create`、`agent.update`、`agent.delete` | `AgentList` |
| `settings.update` | `ClusterSettings` |
| `asset.delete` | `{assetId, deleted:true}` |
| `workspace.import` | `ImportResult` |

客户端只允许上述方法。支持方法并不表示本阶段提供了对应管理 UI；资产原始字节上传/下载及包导出也没有加入本 gateway。

```ts
import { api } from './src/api'

await api.connect({ baseUrl: 'http://127.0.0.1:4320', token: userToken, remember: false })
const snapshot = await api.read('map.get', { mapId })
const requestId = crypto.randomUUID()
const result = await api.dispatch(requestId, 'run.start', {
  mapId, expectedRevision: snapshot.revision,
  id: crypto.randomUUID(), targetId: claimId, mode: 'human-in-loop',
})
// result.data.snapshot 来自服务器；不要在客户端重建 Run。
```

浏览器开发使用 Vite origin 代替示例中的后端 origin；连接地址与代理设置见第 7 节。

## 4. HTTP、重试与取消

`clientCreateApi({baseUrl, token, timeoutMs?, fetch?})` 提供 `read/dispatch/close`；默认超时 15 秒。`clientCreateGateway({baseUrl, timeoutMs?, fetch?, store?})` 在其上管理连接生命周期。`store` 只由桌面 Main 注入，浏览器省略。

- 查询：`POST /api/v1/query`，body 为 `{method,params}`；客户端返回响应中的 data。
- 命令：`POST /api/v1/command`，body 为 `{requestId,method,params}`；返回完整 `{ok:true,requestId,replayed,data}`。
- 请求使用 `Authorization: Bearer <user token>` 和 JSON，`credentials:omit`，拒绝 HTTP 重定向。
- 响应按实际读取字节限制为 16 MiB，检查成功信封、请求 ID、关键 DTO 字段和 Graph 节点数据。缺少必填 `news.context` 属于非法响应，不补默认值。
- 超时或网络错误可能发生在服务器已接受命令之后。用户重试时必须复用原 requestId 和原参数；store 冻结两者。传输层不自动重发命令。
- 409 刷新服务端快照但保留草稿。禁止自动改 expectedRevision 后覆盖；用户应重新载入或明确采用当前版本再提交。
- AbortSignal / IPC cancel 只中止本次客户端等待。取消业务执行必须显式发送 `run.cancel`，关闭标签、切换工作区或退出登录均不等于取消 Run。

store 以单请求快照轮询更新当前图，默认 1 秒间隔；每 5 轮同时刷新工作区与权限。会话/视图代次隔离迟到响应，同图 revision 不倒退。草稿独立记录 Map/Review 版本，不随轮询覆盖。401 清除会话；失去工作区访问权时清除对应缓存；临时网络中断保留画面并暂停写操作。

## 5. 错误

Gateway 抛出 `ClientError`，字段为 `{status,code,message,retryable,currentRevision?}`。本地错误通常 status=0；服务端错误保留 HTTP status。IPC 参数/来源校验错误为 status=400。

| code | 含义与处理 |
| --- | --- |
| `INVALID_URL`、`INVALID_TOKEN`、`INVALID_TIMEOUT`、`INVALID_REQUEST_ID` | 修正连接或调用参数 |
| `NOT_CONNECTED`、`DISCONNECTED`、`CONNECTION_CHANGED` | 未连接、已关闭或被后续连接替代 |
| `UNKNOWN_METHOD` | 不在公开方法白名单 |
| `NETWORK_ERROR`、`REQUEST_TIMEOUT` | 可使用相同命令 ID/参数重试 |
| `REQUEST_ABORTED` | 本次请求已取消，无自动业务撤销 |
| `INVALID_RESPONSE`、`RESPONSE_TOO_LARGE` | 响应不符合契约或超过大小限制 |
| `DESKTOP_BRIDGE_UNAVAILABLE`、`INVALID_BRIDGE_RESPONSE` | 桌面桥加载或返回异常，不回退旧 API |
| `IPC_FORBIDDEN`、`INVALID_CALL_ID`、`INVALID_ARGUMENT`、`CALL_EXISTS` | IPC 来源、参数或调用 ID 异常 |
| `UNAUTHORIZED`、`FORBIDDEN`、`REVISION_CONFLICT` 等 | 沿用 055 服务端错误语义 |

重试判断使用实际 `retryable` 字段。服务端明示值优先；没有明示时，HTTP 5xx/429 默认可重试。非法 JSON 来自 5xx 时也可重试；普通 DTO 结构错误不可重试。

## 6. Electron IPC 与凭证

Renderer 仅暴露 `window.chongmingClient` 六方法。除 cancel 外，返回 `{ok:true,value}` 或 `{ok:false,error:ClientErrorData}`，由 `src/api.ts` 转为 Promise 返回值或 ClientError。

| channel | bridge 方法与参数 | value |
| --- | --- | --- |
| `client:connection` | `getConnection()` | `ClientConnection` |
| `client:connect` | `connect({baseUrl,token,remember})` | `AppBootstrap` |
| `client:disconnect` | `disconnect()` | null |
| `client:read` | `read(callId,method,params)` | query data |
| `client:dispatch` | `dispatch(callId,requestId,method,params)` | `GraphSuccess` |
| `client:cancel` | `cancel(callId)` | 无（单向消息） |

`callId` 是每次 IPC 请求的新 UUID；`requestId` 是业务命令的稳定 UUID，重试时复用。AbortSignal 不跨 IPC 序列化，adapter 通过 cancel 转换。Main 校验受信 WebContents、主 frame 及来源 URL；只接受公开方法，params JSON 限制为 1 MiB。窗口销毁时终止其未完成请求。

BrowserWindow 开启 sandbox、contextIsolation、webSecurity，关闭 nodeIntegration，拒绝新窗口、任意导航、webview 和权限请求。桌面生产构建注入 CSP：脚本只允许自源，Renderer 禁止联网（connect-src none），样式允许自源与动态内联样式；开发模式不注入以保留 HMR。未暴露旧 electronAPI、数据库或任意 Fetch 能力。

Main 将连接保存在 userData 下 `client-connection.json`。只有 safeStorage 可用且不是不安全存储后端时才保存加密 token；Linux 只接受明确的 libsecret/KWallet 后端。文件以 0600 临时文件原子替换。不勾选记住只保存地址；解密失败返回未登录状态。用户输入提交后清空，后续接口不读回原始 token。

057 收窄了读取异常处理：凭证文件不存在或 JSON 损坏时可重新登录，其他文件系统错误向界面报告，不再静默伪装成没有登录。

## 7. 启动

先按 [README](../README.md) 启动独立 Graph API 与 Host，再运行 `npm run dev` 启动桌面。桌面地址直接填写 Graph API origin。

浏览器开发运行 `CHONGMING_GRAPH_API=http://127.0.0.1:4320 npm run dev:web`。登录地址保持 Vite 当前 origin，代理只转发 `/api/v1`，目标固定在启动配置且拒绝跟随重定向。浏览器没有 token 持久化或“记住登录”；刷新后重新登录，偏好从服务端恢复。`CHONGMING_WEB=1` 禁用 Electron 构建/启动插件。

## 8. 空 News.context 的显式修复

056 修复 Mongoose 默认 minimize 省略空对象的根因，新写入的 `news.context={}` 可完整往返。以前已省略该字段的新 Graph 数据，可运行本机管理员命令：

```bash
# repair-check.json 内容为 {}；只统计，不修改图
npm run admin -- data.repair-news-context --input /absolute/path/to/repair-check.json

# repair-apply.json 内容为 {"apply":true}；显式执行修复
npm run admin -- data.repair-news-context --input /absolute/path/to/repair-apply.json
```

输入只接受可选 boolean `apply`，默认 false。返回 `{matchedMaps:number,modifiedMaps:number}`。仅针对新 Graph 集合中未删除、News 节点缺失 context 的图；补 `{}`，保留节点内容和 Node revision，Map revision 加 1 并更新时间。重复执行不会再次改动已修复图。不修已有的非法非对象值，不迁移旧 Mapper 数据，不在应用启动或普通读取时自动执行。
