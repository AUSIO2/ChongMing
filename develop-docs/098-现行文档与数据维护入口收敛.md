# 098 — 现行文档与数据维护入口收敛

日期：2026-10-17。

## 目的

主仓库同时保留了早期产品蓝图、阶段接口稿、一次性实施清单和现行运行说明。其中部分文档仍以已删除的 Mapper、单 `run`、固定 `NodeData`、v3 数据包、旧路径或已退役命令为基线，会误导开发与运维。本轮将现行约束收敛到稳定主题文档，历史阶段稿交由 Git 追溯。

## 审计结论

- `050`–`060` 共 36 份旧蓝图和阶段合同已被当前 `contracts/*`、`ARCHITECTURE.md`和 `077` 数据/分支协议取代。`052-校验契约.mjs` 只自检同目录的冻结目标契约，不检查生产协议。
- `068` 将已实现故障边界、待验收项与旧源码路径混在一起；现行运维规则需要独立文档。
- `072`/`075` 的函数名、文件数、行数和测试基线均已失真，且全部仍标为待实施。可读性规则由 `coding.md` 继续维护，业务不变式单独固化。
- `071`/`076`/`078` 是当时注释补齐的一次性设计、实施和 154 文件覆盖快照；当前代码集已大幅变化，现行规则已在 `coding.md` 中。
- `branch-migration.ts` 和 Mongo `maintenance.ts` 仍被生产入口、错误指引与 Mongo/SQLite 测试使用，不是死代码。
- `data.repair-news-context` 原先在预览前执行整个应用初始化，会创建索引/管理状态并要求事务型 Mongo，与“默认只统计”不符。

## 改动范围

1. 新建稳定文档入口：
   - `docs/architecture/behavioral-invariants.md`：当前部署、图、分支、Run/Work、幂等和客户端并发边界。
   - `docs/operations/fault-handling.md`：公共错误、诊断、关闭、恢复与尚未验证范围。
   - `docs/operations/data-migrations.md`：Mongo/SQLite 显式迁移、News context 修复、备份和禁止条件。
2. 删除审计确认失效的 50 份 `develop-docs` 工件：`050`–`060`、`068`、`071`、`072`、`075`、`076`、`078`。
3. 重写 README、架构/开发/测试入口的历史链接，不再把阶段号当成现行文档导航。
4. 让 `data.repair-news-context` 在应用初始化前直接运行专用维护函数，并用真实管理 CLI 回归证明预览不创建无关集合。

## 不变式与排除项

- 不执行任何用户数据写入迁移，不连接未确认的 legacy 远程库。
- 不删除迁移器、存量读取兼容或历史归档类型。删除迁移能力需要全部部署的独立 `matchedMaps=0` 证据和明确退役版本。
- 除修复命令的预览副作用外，不改公共协议、持久格式、运行语义或依赖。
- 不修改当前已有未提交变更的两份 `096` 文档。
