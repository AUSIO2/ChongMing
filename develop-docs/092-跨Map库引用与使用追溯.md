# 092 跨 Map 库引用与使用追溯

日期：2026-10-07。承接 084/091，用户授权继续。先写真实用例并审阅再实现；不发布新版，不更改用户保存的定义包和数据库。

## 本轮闭环

在目标 Map 的有限计划步骤显式选择库条目，启动时校验同 workspace、active、精确摘要和 Claim 定义。冻结所选条目的原文、固定0/1、范围、理由/依据引用及精确定义。Operation 规格绑定这份集合，Work data_read 单独返回库材料；库来源 ID 不进入本图 inputs/context 节点数组，也不扩大 branch.scope。撤回后新 Run 拒绝选择，既有已冻结 Run/Work继续用原材料。

模型或人工核查产物显式声明被使用的 entryId/contentDigest 与非空理由。Work只能引用本 Operation 已获权集合；正式发布时在图提交同一事务登记使用。收据重放不会重复登记。目标节点编辑/移除、目标图删除结束当前使用关系，但永久保留原消费者快照和使用历史。

## 契约与兼容

- GraphRunStep.libraryClaimRefs?: EvidenceLibraryRef[]，每步0..32、身份不重复，启动校验并冻结。GraphRun.libraryClaimSets?: Array<{stepId,claims:EvidenceFrozenClaim[]}>，每步只保存一次完整材料；历史无字段保持原行为。
- EvidenceFrozenClaim={ref:EvidenceLibraryRef,entry:EvidenceLibraryEntry,definition:DataTypeDefinition,snapshotDigest:string}。entry保存固定陈述、范围、理由和判定依据引用，完整原始材料继续由已固定库记录/关系及永久资产承担；不向模型补读来源当前版本。
- 联调审阅补充：完整Run冻结材料增加snapshotDigest=definitionsDigest({ref,entry,definition})；它与库contentDigest分开，后者还绑定未复制进Run的关系/依据快照。ExecutionSpec.librarySnapshotDigests按规范化refs顺序保存并参加specHash。存储入口重算冻结摘要并核对规格对应摘要，拒绝单字段损坏后仍沿用旧ref/specHash的材料；Work投影沿用完整快照摘要，不把投影后的内容冒充完整原快照。
- ExecutionSpec.libraryClaimRefs?: EvidenceLibraryRef[] 及相应定义摘要参加 specHash。GraphDataRead.libraryClaims?: EvidenceFrozenClaim[]，只投影当前步骤集合，nodeSnapshot沿冻结definition.agentProjection，不包含未选库条目；空集合保留原协议形状。
- EvidenceUseRef={entryId,contentDigest,reason}，GraphProposedOutput.libraryClaimRefs?与正式GraphNode.libraryClaimRefs?保存这份引用。当前已发布payload schema保持不变，库引用先作为通用节点元信息而非偷偷修改不可变旧Opinion定义。人工GraphNodeInput可显式设置/移除；省略时保留原引用。
- 显式选择的冻结材料最多每步1MiB、整个Run总量4MiB，规格仅存refs避免重复完整材料；超限明确拒绝并回滚。规格摘要以规范排序后的refs/定义摘要绑定，不因管理状态或UI顺序改变材料。

## 使用记录与查询

evidence_uses记录workspace、entry ref、consumer {mapId,nodeId,revision}、reason、kind:'work'|'manual'、runId/operationId/workId（manual为null）、startedAt、endedAt与原consumerSnapshot。使用身份绑定entry及消费者内容版本，重复发布不重复新增。图版本变化结束旧版本使用并登记新版本；相同已有引用允许继续引用已撤回固定内容，新增/替换人工引用要求active。

evidence.uses({workspaceId,entryId,includeHistory?,cursor?,limit?})返回轻量摘要页与独立使用目录版本，默认25/上限100；evidence.use.get({workspaceId,entryId,usageId})返回单条原消费者快照。两者viewer授权；Mongo原生索引过滤/投影/游标，不全库读取。来源或消费者图删除后仍能读取历史快照。

## 模块分工

图规则使用contracts和注入的冻结/提交回调，不导入库业务实现。application在既有授权事务组合库冻结、图变更和使用索引，Host正式提案沿既有Workspace执行写栅栏。库模块提供冻结/使用同步/查询；Mongo query adapter增加有界使用查询。DSH工具合同开放可选libraryClaimRefs，并将获权库材料作为明确只读材料提供，沿用现有lease/fence/候选发布与审核规则。

UI运行表单增加可取消的库检索/显式选材（不自动选择、不全库扫描），在实际生成的步骤绑定所选refs；库详情展示当前/历史使用及冻结消费者正文，定位当前Map仍标明当前版本。身份/工作区/来源和步骤变化隔离草稿及迟到响应。

## 测试先行与验收

先写真实Mongo/HTTP运行与使用闭环、规格/工具及UI用例，再授权源码修改。覆盖另一Map选材、same nodeId不替库出处、固定0/1/正文/定义与specHash、不同集合禁止旧产物复用、未选/假摘要/跨workspace输出拒绝、冻结后撤回仍发布、新选择拒绝、开始/输出合法重放不重写材料或重复使用、人工引用新增/保留/移除、图删除历史保留、权限和回滚组合、分页0与使用目录游标、数据读projection及DSH字段合同。

复用数据库事务和Host/Run租约机制，不新增底层数据库/锁/接管算法压测。既有114用例保持，实际已实现相关项接入后运行；历史证据集回放、替代、导入导出和完整压力不在本轮。

联调审阅还补充真实SQLite入口无库服务时新增/改变非空引用的负向验收，以及真实HTTP两个步骤分别选材时的只读与提案授权隔离。SQLite允许保留或清除历史引用，新增/改变要求证据库服务；图写入与收据必须一起回滚。

现有v4便携包没有库引用及对应库条目的交换协议。联调发现含非空库引用的Map导出后会被现有导入器拒绝，因此本轮明确拒绝此类Map/工作区导出，说明原因；省略/空引用的原导出保持。不能静默丢弃非空引用或把跨工作区原entryId原样导入。完整库交换继续后续独立设计。
