# 108 — 无需邮件的用户名账户

用户要求在线上邮箱服务尚未配置时，额外提供无需邮件的注册方式。本次增加用户名和密码账户，注册后直接进入默认私有工作区，保留邮箱账户和访问令牌能力；完成测试后更新重明网站。

## 范围

- 用户名3至32位英文字母、数字、下划线或短横线，去除首尾空格后忽略大小写；显示名称继续允许中文。用户名与邮箱使用独立身份字段，不制造假邮箱或假验证状态。
- `registerUsername` 原子创建普通用户、默认私有工作区和账户会话；`loginUsername` 验证原密码哈希。会话刷新、注销、改密、工作区权限复用现有实现，不授予站点管理员权限。
- 增量HTTP入口 `/api/v1/auth/register-username` 和 `/api/v1/auth/login-username`，Web及桌面网关走同一正式合同。默认纸面表单展示用户名方式，邮箱方式有明确入口。
- 不需要SMTP、邮件验证码或验证码密钥。用户名账户没有邮件找回能力，注册界面明确说明；不增加临时找回后门或新的密码规则。

## 先行测试

1. 真实事务：无邮件依赖注册成功、规范化与重复用户名、非法输入、密码哈希、普通身份、默认工作区唯一、失败回滚。
2. 真实HTTP：用户名注册/登录后读取和保存自己的图，另一用户不可读取，旧管理员令牌和邮箱流程保持；Mongo兼容既有无用户名用户并保持唯一性。
3. 客户端及IPC：固定端点和参数、注册后激活、会话不泄漏、失败或迟到结果不覆盖已有连接，记住和刷新复用原生命周期。
4. 真实浏览器：无SMTP注册直接进入工作区、退出后用户名登录、确认密码错误拦截；原邮箱注册/重置仍可从其入口完成。

不扩大异常测试框架，不用生产用户做自动化测试。红绿日志及636文件可恢复基线位于 `test-results/108-username-auth`。

## 发布

生产数据升级仅添加可选用户名字段及稀疏唯一索引，不转换原身份或重置既有工作区。复用107的Linux发布目录和已修复Mongo TLS；准备备份后切换新版，检查现有令牌、定义、工作区以及匿名表单。保持SMTP缺失状态说明准确，不假称邮箱邮件已可用。
