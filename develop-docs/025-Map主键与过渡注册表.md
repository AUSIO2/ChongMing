# 025 — Map 主键与列间过渡注册表（阶段 A）

## 背景

Timeline 架构将 Map 工作区拆为四阶段实施。阶段 A 完成数据主键与微观过渡统一，为后续 parse（0-1）与 Timeline UI 打底。

## 目标

1. Mongo `News` → `Map` 集合；`mapId` 替代 `newsId`
2. 正文 / claims / splitMeta 迁入 `chains[scopeNodeId]`，默认 scope = `__news_root__`
3. `TRANSITION_REGISTRY` + `runTransition` 统一 `1-2`（split）与 `2-3`（verify）
4. IPC：`map:*`、`graph:run-transition`；**不保留** `news:*` 别名（coding.md §4）

## Schema

```ts
Map {
  _id: mapId
  chains: Record<scopeNodeId, { content, context, claims, splitMeta? }>
  timeline?: { activeScope, scopes }
  mapRun?, mapGraph?
}
```

启动时 `dbMigrateNewsToMap()` 一次性迁移存量 News 文档。

## API 变更

| 旧 | 新 |
|----|-----|
| `DisplayNews` | `DisplayMap` |
| `newsId` | `mapId` |
| `graphType split\|verify` | `transitionKey '1-2'\|'2-3'` |
| `startSplit` / `startVerify` | `graph.runTransition({ mapId, transitionKey, parentNodeId })` |

`mapRun` / graph payload 均带 `transitionKey` + `parentNodeId`。

## 模块

- `electron/api/map-service.ts` — CRUD + persist
- `electron/transitions/` — registry、split、verify 包装
- `electron/shared/map-scope.ts` — chains 读写
- `graph-service.runTransition` — 唯一微观入口

## 不在本阶段

- parse `0-1`、`runTimeline`、Timeline UI
- 删除 `NEWS_ROOT_ID`（阶段 D）

## 验收

- `map:get` 等价迁移前 content/claims
- `runTransition('1-2'|'2-3')` split→verify 全链路
