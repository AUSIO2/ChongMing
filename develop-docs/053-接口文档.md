# 053 — 新后端当前接口

本文件记录053阶段。054已用Host领取替换无租约执行及data_delegate，当前完整接口见[054-接口文档](./054-接口文档.md)。

这是 `backend/` 当前实现的接口。052 中的完整架构仍包含后续阶段；旧 Mapper/IPC 不适用此文档。权威类型：[contracts/graph.ts](../contracts/graph.ts)。DSH 通用运行时接口保持不变，见 [README](../README.md)。

## 地址与约定

图服务默认 `http://127.0.0.1:4320`。全部 POST 使用 `Content-Type: application/json`，请求体最多 1 MiB。未知字段、错误类型、无效枚举会被拒绝。Map、节点、边、Run、Review、公开 requestId 使用 UUID；operationId、proposalId、reportId 是服务端生成的不透明字符串，不按 UUID 解析。

开发工作区固定 `workspace:development`。版本从 0 开始。图修改通过 Map 的 `expectedRevision` 做 CAS，每次成功写入增加 1。相同 requestId 与相同输入重放不重复写入，返回当前快照；同一 requestId 改内容返回 409。活动 Run 期间禁止 graph.apply 和 map.delete，先取消 Run。

## 公开端点

| HTTP | 地址 | 用途 |
|---|---|---|
| GET | `/health` | 返回 `{"ok":true}` |
| POST | `/api/v1/query` | 读取图 |
| POST | `/api/v1/command` | 修改图、Run 与 Review |

query 请求为 `{method,params}`。command 请求为 `{requestId,method,params}`。

成功包络：`{ok:true,requestId,replayed,data}`。query 的 replayed 为 false。首次 map.create 返回 201；其余成功返回 200。命令的 data 为 `{snapshot,createdNodeIds,createdEdgeIds}`，map.delete 例外返回 `{mapId,deleted:true}`。

错误包络：`{ok:false,requestId,error:{code,message,retryable,currentRevision?}}`。5xx 的 retryable 为 true；409 应先重新读数据，处理冲突后使用新 requestId；传输失败可重发原请求。

### 方法表

| method | params | data / 行为 |
|---|---|---|
| `map.list` | `{workspaceId}` | `[{id,workspaceId,revision,name,nodeCount,claimCount,updatedAt}]` |
| `map.get` | `{mapId}` | GraphSnapshot |
| `map.create` | `{workspaceId,expectedRevision:0,id,name}` | 新空图，snapshot.revision=0 |
| `map.delete` | `{mapId,expectedRevision}` | 软删除，活动 Run 时 409 |
| `graph.apply` | `{mapId,expectedRevision,changes}` | 原子修改节点、边、名称 |
| `run.start` | `{mapId,expectedRevision,id,targetId,mode,configuration?}` | targetId 必须是 Claim；一个 Map 同时一个 Run；id 不可复用 |
| `run.cancel` | `{mapId,expectedRevision,runId}` | 标记 cancelled，后续新提案拒绝 |
| `review.update` | `{mapId,expectedRevision,runId,reviewId,expectedReviewRevision,reason,slots}` | 只编辑 pending route Review；替换完整 slots，route/review revision 各加 1 |
| `review.answer` | `{mapId,expectedRevision,runId,reviewId,expectedReviewRevision,decision}` | decision=approve/reject；route 批准放行 worker，result 批准提交已保存的草稿；拒绝令 Run failed |

map.list/map.get 用 query，其余用 command。run.start.mode 是 `auto` 或 `human-in-loop`。run.start 创建状态；执行器独立驱动该 operation，当前没有自动领取队列。

### 图数据

GraphSnapshot：`{mapId,workspaceId,revision,name,nodes,edges,run,updatedAt}`。node：`{id,revision,data,createdAt,updatedAt}`。edge：`{id,revision,kind,from,to,createdAt,updatedAt}`。时间为 ISO 字符串。

node.data 为以下之一：

- news：`{kind:"news",content,context:{字段名:{value,visibleToAI}}}`。value 为字符串；DSH 仅能读到 visibleToAI=true 的 context 字段。
- claim：`{kind:"claim",content,category}`，category 为字符串或 null。
- verification：`{kind:"verification",score,reason,reportIds,opinions}`。score 为 0/0.5/1；opinions 为完整 GraphReport 数组，可直接回传编辑，不丢失出处。

edge.kind：`mentions` 为 news→claim；`verifies` 为 verification→claim；`related-to` 可关联任意两个不同节点。禁止悬空边、自环、改变已有节点种类。

changes：`{name?,nodes?:{put?:[{id,data}],remove?:[id]},edges?:{put?:[{id,kind,from,to}],remove?:[id]}}`。put 按 id 整体替换 data；删除节点同时删除关联边。不能同批 put/remove 同一 id，空 changes 无效。

### 自定义 Agent / Tool 配置

configuration 为 `{router,merger,agents,tools,maxSlots}`，Run 持久保存这份配置，不再读取后来修改的默认配置。

| 字段 | 类型与约束 |
|---|---|
| router / merger | GraphAgentProfile |
| agents | 1–64 个候选 GraphAgentProfile，路由只可引用这里的 id |
| tools | `[{name,description}]`，工具名唯一且对应 Host 已注册的真实工具 |
| maxSlots | 1–32 的整数；默认 8 |

GraphAgentProfile：`{id,name,description,content,tools,provider,model}`。id 在 router/merger/agents 间唯一；name 是显示名称；description 帮助路由选择；content 为实际 persona；tools 是允许使用的工具名称数组；provider/model 为 DSH 已注册 provider 与模型。不同 Agent 可以使用不同模型。自定义 endpoint/凭证在 Host 注册 provider 时配置，不写进图。

id、slotId、工具声明名称符合 `[a-zA-Z0-9_-]{1,64}`。profile.tools 必须属于 configuration.tools。`data_read/data_propose/data_delegate` 及原生 subagent/fork/workflow 等编排入口保留给运行时，不能作为自定义能力扩大权限。

配置只描述工具；实现通过可信 Host 的 DSH patch/plugin 注册。声明一个名称不会生成工具实现；执行器在运行前检查注册情况，缺失时报错。自定义 Agent 配置入口已在 run.start，独立资产管理 UI/CRUD 尚未接入。

示例（省略外层 requestId）：

```json
{
  "method": "run.start",
  "params": {
    "mapId": "00000000-0000-4000-8000-000000000001",
    "expectedRevision": 1,
    "id": "00000000-0000-4000-8000-000000000003",
    "targetId": "00000000-0000-4000-8000-000000000002",
    "mode": "human-in-loop",
    "configuration": {
      "router": {"id":"router","name":"路由","description":"选择适合陈述的角度","content":"读取任务并提交路由，再委派批准的角度和汇总。","tools":[],"provider":"deepseek-official","model":"deepseek-v4-flash"},
      "merger": {"id":"merger","name":"汇总","description":"综合证据与分歧","content":"读取全部报告，给出结论并提交merge。","tools":[],"provider":"deepseek-official","model":"deepseek-v4-flash"},
      "agents": [{"id":"statistics","name":"统计核查","description":"核对统计口径、比例和时间段","content":"按批准的角度核查并提交本slot报告。","tools":["ledger_query"],"provider":"deepseek-official","model":"deepseek-v4-flash"}],
      "tools": [{"name":"ledger_query","description":"查询可信统计资料库"}],
      "maxSlots": 4
    }
  }
}
```

同一个候选 Agent 可以承担多个不同角度。上例需要 Host 实际注册 ledger_query；也可以省略整个 configuration 使用默认配置。

## Run 与审核数据

Run：`{id,mode,status,configuration,operation,createdAt,updatedAt}`。status 为 running/waiting/completed/failed/cancelled。

operation：`{id,kind:"verify",targetId,status,inputRefs,route,reports,draft,review,resultNodeId}`。inputRefs 为 `[{id,revision}]`，绑定 Claim 与关联新闻版本。route/draft/review/resultNodeId 初始为 null。

route：`{revision,reason,slots,approved}`。slots 是动态数组，长度 1..maxSlots，slot.id 唯一。每项 `{id,agentId,angle,priority,hint,tools}`；priority=high/medium/low；angle 为非空核查角度；hint 可空；tools 必须是该 Agent 白名单的子集。批准后不再修改路由；重做使用新 Run。

GraphReport：`{id,slotId,agentId,agentName,angle,tools,routeRevision,score,reason,createdAt}`。Agent 身份、角度、允许工具由服务端按冻结的 slot 填写；tools 表示授予的工具，不表示每个工具都实际调用过。实际调用记录属于 DSH 日志。

draft：`{id,routeRevision,reportIds,score,reason}`。merger 必须精确引用全部批准 slot 的报告，代码不投票、平均或重算 score。

review：`{id,kind,revision,state,decision,createdAt,answeredAt}`。kind=route/result，state=pending/answered，decision 初始 null。人工模式先审 route，再审 result；前端根据 kind 展示 route 或 draft。result 批准提交保存的 draft，不能在 answer 中传临时结果。

终结 Run 在开始下一 Run 时保存在数据库 runHistory；当前 map.get 只返回最新 Run。历史 verification 节点保留报告意见，独立 Run 历史查询端点尚未实现。

## 单 operation 执行器

代码入口为 `dshRunVerification(input)`，见 [backend/dsh-verify.ts](../backend/dsh-verify.ts)。必填 `{mapId,operationId,dataApiUrl,token,dshHome}`；可选 `patches`（可信部署patch绝对路径数组）、`env`（只传给DSH子进程）、`onEvent`（DSH通知）、`rootSessionId`、`dshBin`、`cwd`、`processCwd`、`maxTokens`、`maxRounds`。

返回 `{mapId,runId,operationId,sessionId,phase,finalResponse}`，phase 只能是 waiting/done。已经处于这两个阶段时不启动DSH，sessionId 为 null。运行前提前空闲时最多跟进 maxRounds 轮根Agent（默认3，范围1–10），仍未到业务边界则抛错并保留已提交进度；不重跑已报告的slot。执行结束关闭本次DSH进程。

done 表示 Run 已终结；是否成功以 map.get 返回的 run.status 为准。当前自定义工具通过 Host patch/plugin 注册，尚未提供 DSH 用户 preset 的独立装配接口。

命令行：

```bash
npm run dsh:verify -- --map-id MAP_UUID --operation-id OPERATION_ID \
  --patch /absolute/path/to/custom-tools.patch.yml
```

CLI 从 `CHONGMING_DATA_TOKEN` 读取内部认证，从 `CHONGMING_DATA_API`（默认 loopback:4320）读取图服务地址，从 `CHONGMING_DSH_HOME`（默认项目下 `.dsh-runtime`）读取DSH目录。`--data-api`、`--dsh-home` 可覆盖；`--patch` 可重复。人工批准 route 后再次调用即可继续。默认使用新的 rootSessionId，按数据库阶段恢复业务进度；不要把跨进程重用 `--session-id` 当作 SDK 冷恢复。

## DSH 内部桥接

仅可信 Host 调用，必须带 `Authorization: Bearer <CHONGMING_DATA_TOKEN>` 和 `x-dsh-role: router|worker|merge`；worker 另带 `x-dsh-slot`。未设置 token 时内部入口也拒绝访问。token 认证 Host；本阶段不隔离持有 token 的 Host 管理员或恶意插件。真实 Agent→operation/slot 的绑定由插件闭包和 DSH Agent 对象校验执行，模型参数不包含这些身份字段。

### POST /internal/v1/data/read

请求 `{mapId,operationId}`，成功返回 `{ok:true,data:GraphDataRead}`。

GraphDataRead：`{mapId,runId,operationId,claim,context,configuration,route,reports,draft,review,phase,proposalId}`。claim 为完整 Claim 节点；context 为 `[{id,content,context}]`，排除不可见上下文。phase=route/workers/merge/waiting/done。waiting 时停止当前执行，等待 Review；done 时停止。worker 只允许读取已批准的绑定 slot。proposalId 由服务端生成，插件用于幂等提交。

### POST /internal/v1/data/propose

共同请求字段 `{mapId,operationId,id,kind,reason}`，id 取本调用者 data.read 的 proposalId。根据 kind 增加：

| kind | 额外字段 | 调用者 / 条件 |
|---|---|---|
| route | `{slots}` | router；尚未产生 route |
| report | `{routeRevision,slotId,score}` | 绑定该 slot 的 worker；路由已批准且版本一致 |
| merge | `{routeRevision,reportIds,score}` | merge；全部 slot 的报告齐全，精确覆盖其 id |

成功返回 `{ok:true,data:GraphSnapshot}`。相同提案重放不重复提交；不同 slot 并发使用 CAS 重读后重试同份提案，不重跑模型。错误角色即使重放已接受提案也拒绝。Run 取消、旧 operation、旧路由版本、新内容复用 proposalId 均拒绝。

模型可调用工具 `data_read`、`data_propose`、`data_delegate`；工具层注入 map/operation/id/角色/slot。root 委派批准的 worker，再在报告齐全后委派 merge；persona、provider/model 和 tools 按冻结配置传给 DSH 原生子 Agent 服务。worker 不可委派其他 Agent。

## 主要错误与当前边界

| HTTP | code 示例 | 含义 |
|---|---|---|
| 400 | INVALID_JSON / INVALID_ARGUMENT / INVALID_CONFIGURATION / UNKNOWN_METHOD | 请求或配置错误 |
| 401 | UNAUTHORIZED | 内部 token 缺失或不正确 |
| 403 | FORBIDDEN / ROLE_NOT_ALLOWED / SLOT_NOT_ALLOWED | 未绑定的角色或越权 slot |
| 404 | MAP_NOT_FOUND / RUN_NOT_FOUND / OPERATION_NOT_FOUND | 目标不存在 |
| 409 | REVISION_CONFLICT / IDEMPOTENCY_CONFLICT | 版本或重复请求冲突 |
| 409 | RUN_ACTIVE / RUN_ID_REUSED / RUN_NOT_ACTIVE | Run 生命周期约束 |
| 409 | ROUTE_NOT_APPROVED / REVIEW_CONFLICT / REPORTS_INCOMPLETE / PROPOSAL_CONFLICT | 提案或审核不满足当前阶段 |
| 410 | MAP_GONE | 图已删除 |
| 413 | PAYLOAD_TOO_LARGE | 请求超过 1 MiB |
| 422 | UNKNOWN_AGENT / TOOL_NOT_ALLOWED / INVALID_ROUTE / INVALID_RUN_TARGET / INVALID_RELATION | 业务引用或路由无效 |
| 503 | WRITE_CONTENTION | 高频并发重试已耗尽，可稍后重发原提案 |

当前是单 Map 文档 CAS、单活动 Run、单 Claim verify，暂不包含自动领取、多 Host 租约、用户鉴权、Agent/tool 资产管理页面或旧前端接线。DSH 原生执行与数据库已接受进度分离：重新驱动任务会读取已保存的阶段与报告，不承诺官方 SDK 尚不支持的冷 Session 原样恢复。
