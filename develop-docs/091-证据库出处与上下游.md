# 091 证据库出处与上下游

日期：2026-10-07。状态：本轮实现与验收完成。用户授权继续 084/090 的真实关系接入。先写验收测试并检查用例，再实现；不发布新版，不改默认定义或用户数据。实际结果见 [091 实施记录](./091-implement-证据库出处与上下游.md)。

## 本轮闭环

新收录保存 Claim 来源 Map 中当时真实的上游、核查下游和已选 node 依据。上游沿 successor 入边，核查下游沿 successor 出边，引用依赖沿已声明的 node 引用及 reference 出边；引用不当作 successor，也不取得写范围。复制精确节点版本、定义摘要、实际边及来源锚点，保护冻结节点声明的资产。人工依据不造来源边；已选 node 依据可用明确 basis 关系连接到 Claim，关系并不把其他核查意见自动变成收录理由。库自身 0/1 不变，Opinion 原分数照原值保存。

关系仅在新收录成功事务中冻结，与库记录/资产引用/收据一起提交。合法重放与精确重复返回原固定内容，不因当前图新增结果而刷新旧快照。已收录的旧记录没有关系快照时返回 snapshot:null，界面明确提示未保存；不查当前图补成历史关系，不迁移用户数据。

## 公共查询契约

新增 evidence.relations({workspaceId,entryId})，viewer 授权与 get 一致，撤回后可读。返回 EvidenceRelationsView={workspaceId,entryId,contentDigest,snapshot:EvidenceRelationSnapshot|null}。

EvidenceRelationSnapshot={version:1,capturedAt:string,rootKey:string,nodes:EvidenceRelationNode[],edges:EvidenceRelationEdge[],truncated:boolean}。

EvidenceRelationNode={key:string,ref:EvidenceClaimRef,nodeSnapshot:GraphNode,definitionDigest:string,role:'claim'|'upstream'|'downstream'|'basis'|'dependency'}。key 绑定 mapId/nodeId/revision，不以同名 nodeId 合并不同 Map 或版本。

EvidenceRelationEdge 为明确联合：

- {key,kind:'graph',from,to,mapId,edge:GraphEdge}：保存实际边完整快照，from/to 为节点 key；sourceAnchors 保留。
- {key,kind:'payload',from,to,mapId,path}：保存节点声明的真实引用路径，不伪装成实际 GraphEdge。
- {key,kind:'basis',from,to,basisIndex}：关联用户明确选择的 node 依据与 root，保持原依据位置。

捕获最多 128 节点、256 关系、沿每种遍历路径深度最多 8；visited 防引用环，所有边端点均已保存。达到边界以 truncated 明示，响应不冒充完整链路。固定内容+依据+关系总量沿用 1 MiB 限制；超限拒绝并回滚，不静默删材料。关系字段纳入新记录 contentDigest；原无关系记录保持旧摘要算法。去重业务身份保持来源/范围/判断/依据，重复收录继续返回第一次快照。

## 界面

选中库条目时并行读取固定详情和关系，窗口代次统一隔离身份/服务/工作区/选择及迟到错误。先显示已加载库节点，再为当前选择展示有限邻域；邻域节点用独立展示 key，root 使用实际 entryId。GraphScene 画真实 successor/reference；payload/basis 显示为引用关系。点击邻域节点读取已保存快照，单页和旁栏显示其原版本、上下游/依据角色与内容，不冒充另一库条目，也不向当前来源图取正文。原 Map 定位仍明确打开当前版本。
