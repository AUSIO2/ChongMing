# 110 — 工作区与智能体模型调用配置

用户要求模型调用配置按Agent优先、工作区兜底，不再由服务器提供API Key。本次提供网页配置、私有凭据交付和实际执行链，保留图/成员权限和历史运行；不自动把余额不足的服务器Key复制给任何工作区。

## 职责与合同

- `contracts/model-connection.ts`：模型scope、可写输入、脱敏视图及仅供当前Work的私有连接。`model.get`读取状态，`model.update`按独立revision和原requestId保存。scope只属于工作区或其Agent，不属于共享库。
- 工作区提供provider、模型、API地址和Key；Agent逐字段继承，可独立覆盖。同提供方可只改模型，更换provider/base时不误用原Key。初版接DeepSeek、OpenAI官方HTTPS API；本机/测试显式允许自己的loopback模型服务。
- Key字段省略表示保持，null表示移除，字符串表示替换；API只返回是否已配置和生效来源，不回显Key片段或密文。owner可写，成员只读脱敏状态，非成员不可见。
- `backend/modules/workspace/model-configuration.ts`：单独私有集合存连接与加密Key，版本、幂等、继承和目标绑定。`workspace-service.ts`沿原授权事务接入，模型配置不增加Agent或定义版本，不复制到工作区导出包。
- `backend/adapters/identity/model-secrets.ts`：AES-256-GCM、随机IV及认证标签。主密钥独立于业务库，保存在部署私有配置目录；首次原子创建，重启重用，损坏不自动重置。

## 运行与密钥交付

1. 新Run按其选中转换的stage和plan候选解析Agent→工作区连接，缺模型、地址或可用Key则拒绝启动。已有发布定义和精确Agent归档保持；新执行规格冻结实际provider/model/base，不冻结明文Key。
2. Host先取得原Work授权和不含Key的data_read，再调用独立 `/internal/v1/model/read`。服务器同时检查内部身份、operation/Work/holder/fence与有效租约，不经公共查询提供Key。
3. Key仅注入该次执行子进程。父环境中的模型Key、地址和认证缓存不参与兜底。Key轮换作用于后续受权调用；改变运行已冻结目标必须新起运行。
4. DSH使用显式本Work凭据；OpenAI路由采用已有官方pi-ai插件。Codex使用显式provider `env_key` 和独立CODEX_HOME，不回退宿主登录缓存。保留原accepted权威确认、取消、租约与清理。
5. Key不进入模型提示、阶段补丁、公开图/运行、导出、浏览器本地存储或活动日志；对SDK可能回显的秘密字段/当前Key做脱敏，Codex含Key产物在提交前拒绝。

## 界面

工作台管理的工作区资料页增加“工作区模型调用”，Agent页增加“智能体模型调用”，纸面视觉保持。Key保存后清空输入，仅显示状态；空框不删除Key，删除/继承用明确按钮。共享库不配置Key，全局页只保留工具和槽位等部署设置。

## 先行测试

- 真实SQLite：字段/Key继承、Key保持/移除、不同目标隔离、owner/member/非成员权限、独立revision/幂等、原定义不变及新旧冻结模型。
- 真实HTTP：公开视图与data_read无Key；私有Key路由拒绝用户/匿名/旧fence/错误operation；有效Work才能读取，响应no-store。
- 加密适配器：随机密文、认证失败/错主密钥拒绝；首次并发初始化、0600文件、重启恢复和损坏不覆盖。
- 执行器：污染父环境不被采用，缺Key不spawn，两个Work使用各自Key，Key不进prompt/argv/补丁/事件/产物；原accepted/取消行为保持；真实DSH→本机模型Header核对。
- 浏览器：配置持久化不回显，Agent改模型与Key/恢复继承，真实任务使用对应Header，editor/viewer只读，无Key拒绝启动且不留下Run。
