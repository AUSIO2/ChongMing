# 函数命名规范（模块前缀 + CRUD）

## 背景

仓库内函数命名风格混杂（`apply*`、`ensure*`、`upsert*`、`mark*`、`clear*`），读代码难以快速判断模块归属与操作类型。

## 目标

内部实现函数统一为 `{prefix}{Verb}{Entity}`：

- **prefix**：模块短名（`doc`、`mapId`、`run`…）
- **Verb**：单一 CRUD 或扩展动词
- **Entity**：纯名词复合，**无介词、无定语**

## 硬规则

1. 禁止介词：`From` `To` `For` `With` `On` `In`…
2. 禁止形容词定语：`Rejected` `Active` `Empty` `All`…（动词已表意则省略）
3. 动词单一：不用 `UpdateReset`，用扩展动词 `Reset`

## 动词表

| 动词 | 含义 |
|------|------|
| Create | 新建 |
| Read | 查询/解析/序列化 |
| Update | 变更/upsert/投影 |
| Delete | 移除/清空 |
| Reset | 回到初始态 |
| Restore | 恢复会话 |
| Can / Is | 权限/谓词 |
| Build / Run / Register / Format | 工厂/执行/注册/展示 |

## 豁免

- `MapAPI` 接口方法
- Vue `use*` composable、Pinia store
- IPC channel 字符串
- 类型/组件名
