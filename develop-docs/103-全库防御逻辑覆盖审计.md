# 103 — 全库防御逻辑覆盖审计

## 目标

完成一次有明确文件清单、调用链、保留依据和交叉审查的全库只读审计。复核上一轮报告的 14 组主要问题及 7 处小项，再按同类路径横向检查，不以发现数量作为完成标准。

本阶段只修改本编号审计工件与 counter，不修改生产、测试或构建实现，不提交、部署或迁移数据。只读指不修改受审实现；快照、审计索引、复现脚本、覆盖矩阵和结果记录可以保存。

## 文件范围与基线

以当前工作区实际存在的受版本管理及非忽略未跟踪文件为准，固定清单和 SHA-256。覆盖 apps、backend、client、contracts、platform、scripts、根构建配置、tests 与 experiments 的本仓库源码。JSON/YAML/HTML/CSS、部署配置、资源与说明用于核对契约和装配，不混入运行源码数量；生成目录、依赖、Git 元数据和历史开发文档不作为当前实现扫描范围。

## 审计维度

| 标记 | 检查内容 |
|---|---|
| F | 默认值、字符串化/数值化、空值与假成功兜底 |
| E | catch、错误分类、清理覆盖主错、异常降级 |
| V | 输入/存储/响应边界与重复校验的所有权 |
| S | 状态不变量、不可达分支、已退役兼容路径 |
| P | 同份值重复解析、遍历、编译和读取 |
| K | 动态字典键、通配引用和具体路径的读写 |
| L | 身份/代次、资源、取消和异步阶段的责任 |

语法索引仅生成候选，不能宣称已证明冗余。每个文件记录每类人工审查状态和实际依据；纯合同/声明文件可以标记不适用并解释。每个候选主题必须归为确证问题、必要保留或待确认，记录实际调用者和约束，不靠 TypeScript 断言替代未知输入校验。

## 分工及闭环

- domain：graph/workspace/assets/application 及对应测试。
- runtime：adapters/execution、非 UI 应用入口、platform 及对应测试。
- ui：apps/ui、client、客户端及浏览器测试。
- root：shared/evidence/identity/ports/contracts/scripts、根配置、experiments 及未分配测试。

先固定文件与候选索引，再逐模块检查并写入分区结果。每发现一个根因，横扫全范围同类路径；同一根因多个位置合并，旧问题残留明确标注。复现只使用进程内 fixture 或临时目录，不能读写用户数据库或线上服务。交叉审查所有确证问题和高风险保留项；完成时检查文件清单无漏、源码基线无变化、发现有证据、待确认项有明确限制。

## 必须保留的边界

鉴权及授权写栅栏、Receipt 优先与输入摘要、CAS 和最终租约条件、真实可选合同字段、跨请求/异步阶段身份复核、历史存储和外部响应的完整解析、导入重映射后的新值校验、文件/正文容量限制，不因看起来重复而直接列入删除项。

## 交付

保存机器可核对的覆盖矩阵、候选状态、确证发现与保留/待确认依据、行为复现证据、关键生产调用链和范围限制。报告不得写成“证明全库无遗漏”；完成含义是固定范围按本流程审查闭环，仍需列出静态分析及环境限制。
