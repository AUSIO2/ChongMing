# 066 — 桌面本机模式

## 使用

首次打开桌面应用，选择“在本机运行”。Main启动自带Node 24服务进程、SQLite和一个DSH Host，自动连接本机用户，无需复制Token，也无需系统Node、MongoDB或RabbitMQ。选择会保存，之后打开应用自动恢复本机模式。

“连接已有服务”继续使用原来的地址/用户Token登录。远程模式首次启动不创建本机服务；本机临时端口和凭据不会覆盖记住的远程凭据。进入工作台后可“回到本机”。本机服务一旦启动，会保持到退出应用，切换远程或退出登录不停止已开始的本机工作。

macOS关闭窗口后服务继续；选择退出重明时Main先断开客户端，再等待本机Host排空和SQLite关闭。超时只终止自己创建的服务进程树。Main意外退出造成IPC断开时，服务自行关闭。启动超时、资源缺失或服务提前退出会显示失败，可重新点击本机按钮；没有无限重启循环。

模型和工具正常联网。模型密钥继续取自启动环境或本机host-config/secrets.json，环境优先；模型/provider与Agent配置在管理工作台编辑。CHONGMING_CONFIG_DIR可显式指定已有Host配置目录。默认资料和服务配置位于Electron的userData目录：
- local-service/：SQLite、资产、DSH数据、服务日志。
- host-config/：本机服务配置/秘密配置。
- client-mode.json：上次选择的连接方式。
- client-connection.json：原远程连接的OS加密凭据。

不自动搬移065命令行默认的.chongming-local。需要保留命令行数据时，先停止所有相关服务，再按065备份说明迁移完整目录，或使用现有图/工作区包导入。

## 构建

开发和打包都要求Node.js 24：

```bash
npm run desktop:prepare
npm run dev
npm run build:check
npm run test:desktop-runtime
```

prepare将构建机Node二进制及其LICENSE、锁定的生产依赖、服务bundle和DSH插件放进.desktop-runtime。首次或lockfile/Node/平台变化时在独立目录npm ci，之后复用依赖缓存并重新编译服务。不会把项目native模块重建成Electron ABI；electron-builder关闭依赖重建，服务资源放在asar外。

node-pty等原生模块和Node二进制必须与目标平台/架构匹配；打包前强制检查。每个目标平台采用原生构建，不能从macOS arm64静默交付Windows或universal包。Node安装缺少LICENSE时，可用CHONGMING_NODE_LICENSE指向该运行时随附的许可证文件。

本轮验证macOS arm64。Windows/Linux构建路径存在，但尚未进行原生验收；发行签名/公证仍需正式环境配置。test:desktop-runtime使用所带Node完成真实DSH协议+确定性本机模型核查、持久重启和IPC父断开，不连接真实付费模型。

## 安全边界

Renderer仅有固定connectLocal/localState及状态订阅，不允许指定命令、数据目录、二进制或读取Token。ready凭据通过服务子进程IPC进入Main，再由Main的gateway认证；Renderer只收到公共Bootstrap和状态。本机API随机端口且仅监听127.0.0.1，单实例锁避免重复Main，SQLite继续执行065的独占和围栏语义。
