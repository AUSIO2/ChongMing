### C06 — 节点的证据引用管理

#### 范围与交互

从一个节点回答两件事：用了哪些固定库证据、每条为什么使用。所有节点类型都可作为消费者，不能只为意见开放。

1. 节点详情和单页增加“所用固定证据”区，逐条显示本次理由及“查看固定证据”。固定身份与摘要放次要信息，完整陈述、0/1判断和当前撤回状态复用既有固定条目单页，不为这个区默认扫描整库或加载全部关系快照。
2. 详情点击“编辑所用证据”打开一个窗口。正文有未保存草稿时，先保存或恢复正文。单页保持阅读，可沿现有入口回到节点详情编辑。
3. 窗口复用现有候选检索，用户明确“加入所选证据”，逐条填写使用理由；支持改理由、移除一条和明确清空。取消不保存，只有确认保存才写节点。
4. 已保存引用独立复制为草稿，不用当前搜索页重建它们。撤回条目即使不在活动候选中，也保留原身份/摘要/理由，可继续保留、改理由或移除。新选材料只接受活动候选。
5. 打开固定条目使用原 `entryId + contentDigest`；核对读取结果后进入既有库单页。缺失或摘要不符保留原引用并提示，不自动换条目、升级摘要或删掉引用。

候选搜索、分页和选材复用 `evidenceCreateSelection()` / `EvidenceSelectionPanel.vue`。它们只负责新增候选；原引用草稿另行保留，不把已撤回旧材料塞回活动候选接口，也不改运行选材的参数含义。

### C07 — 结构化依据与固定目标导航

#### 业务对象与范围

用户已明确：Claim与证据在节点层面同等，证据表示使用角色；证据库条目保存某个Claim版本及其收录判断，不增加Evidence节点类型。C07处理收录决定的依据，把说明和选中的材料随一次 `evidence.collect` 保存，不调用C06的 `saveNodeEvidence()`，也不建立结构连线。

收录主体仍须是已注册 `factcheck.claim` 的具体版本；节点依据可以是同工作区中任意已注册、schema合法的节点，包括来源、新闻、事实、意见、结论及自定义类型，允许跨Map。所有候选查询只读，不领取依据节点写租约。

| 依据类型 | 用户选择与保存身份 | 阅读入口 |
| --- | --- | --- |
| 人工说明 `manual` | 输入实际说明，保存原文 | 直接显示文本，不解析成节点、URL或连线 |
| 节点 `node` | 先选Map，再选真实节点；保存 `{ mapId, nodeId, revision }` | 优先打开收录时保存的对应节点快照；另列当前节点定位 |
| 文件 `asset` | 从已有资产分页选择文件名，保存真实assetId及SHA-256 | 核对原摘要后下载已有文件 |
| 库条目 `library` | 从同工作区活动条目选择，保存entryId及contentDigest | 复用C06固定摘要校验，打开固定单页；之后撤回仍可读 |

这四类可以混合。**总依据上限64项，保留用户顺序**，不能照搬C06节点使用引用的32项规则。`basisIndex` 对应实际保存顺序，不静默排序、去重或把跨Map同nodeId合并。人工单项及总体输入大小继续遵守后端既有限制。

#### 最小交互

1. “收录到证据库”窗口保留原Claim、0/1判断、适用范围和收录理由，增加一个内嵌依据区；不再套一层模态窗口。
2. 用户明确添加依据，选择人工/节点/文件/库条目。每项展示可读材料名称或陈述、类型以及所选版本，允许移除；人工说明保留真实文本。未选择材料时不生成空引用，不默认引用当前图全部节点。
3. 节点选择只读 `map.get` 取得所选Map，不能调用 `session.openMap()` 切走原收录对象；切换Map候选不改变已加入依据的身份和版本。文件只选已有资产，本批不扩上传流程。
4. 库候选复用现有有界检索和0/1展示。逐项明确加入，按64项总容量控制；不直接套用核查步骤/C06选材的32项上限，也不为此改它们的默认容量。
5. 只有确认收录才提交完整有序依据；取消不写。选择后材料版本变化时保留原选定身份，交后端明确拒绝并让用户重新核对；未知提交继续确认原请求，不把新读取到的版本替换进原请求。
6. 条目详情及固定单页分别提供“阅读固定节点依据”“下载依据文件”“查看固定库依据”；人工说明直接阅读。Viewer可阅读已保存依据，收录入口沿既有权限与服务能力门控。

#### 固定阅读的实际边界

后端 `freezeBasis()` 已冻结四类依据，但 `evidence.get` **不公开内部 `basisSnapshots`**。本批先复用已有公开能力，不让前端假设存在这些字段，也不直接读存储。

- 节点依据：新条目的 `evidence.relations` 保存节点快照和带 `basisIndex` 的basis边。按 `basisIndex + 完整Map/node/revision` 核对边和节点，再用既有 `selectRelation()` / 固定单页打开。不能只查 `role === 'basis'`，同一个节点可能同时是根或上游。
- 当前节点：已有 `homeOpenLibrarySource()` 可以定位现行Map内容，只在明确“定位当前节点”的入口使用，提示与固定原版本的差异；不把它叫成历史阅读。
- 旧条目缺关系快照，或截断导致所需材料没有保存：显示固定正文当前不可用，保留原依据身份；可另行定位当前节点，不补造历史。若未来要求读取这些记录的内部完整快照，另定最小公开接口，本批不先扩合同。
- 文件依据：`asset.get` 核对workspace和所存SHA，再用 `gateway.download({ kind: 'asset', id })`、现有完整性校验和 `clientSaveFile()` 保存；摘要不符/不可用时不下载另一个版本。
- 库条目依据：复用 `library.select(entryId, contentDigest)`；已撤回条目仍展示固定正文及当前状态。新收录引用库项时必须active，不能从历史浏览结果绕过。

### C08 — 收录结果与相反判断冲突

#### 目标与现有缺口

收录完成后明确告诉用户：这次是新条目还是使用已有条目、是否为原请求的确认，以及后端是否返回相反判断。保留既有Claim及固定条目模型，结果展示不改变任何判断、依据或图结构。

当前 `collect()` 首次返回完整 `EvidenceCollectResult`，但 `runCommand()` 只接纳entry；重试只返回boolean。页面首次只使用result.entry.id，重试只使用library.entry，导致 `existing/replayed/conflictEntryIds` 都没有持久展示。此批补这一条结果链路，不重写收录、撤回、四类依据或C06/C07固定阅读。

#### 已核实的四种结果

| 后端结果 | existing | replayed | 建议结果文字 |
| --- | --- | --- | --- |
| 新请求建立新条目 | false | false | 已收录新条目 |
| 新请求匹配已有精确收录 | true | false | 已有相同收录，返回已有条目 |
| 原新建请求重放确认 | false | true | 原收录请求已确认；该次结果为新条目 |
| 原重复请求重放确认 | true | true | 原收录请求已确认；该次返回已有条目 |

这两个标志独立，不互相推导，也不把它们合成互斥三分类。当前collect收据重放会同时把HTTP信封的replayed和业务data.replayed置true；UI按完整收录业务结果展示，不按“用户点过重试”猜测是否重放，更不能由信封replayed推出existing。

精确去重包含工作区、原Claim的Map/节点/revision、等价适用范围、判断、收录理由、依据引用及冻结内容；不能仅凭正文相同在前端判重复。新请求会重新验证来源和依据，是否existing以本次后端结果为准；已有撤回条目不会因为重复请求而重新激活。

#### 相反判断的边界

- 相反判断是**成功附带信息**，不是error，不触发自动重试或撤回。新条目正常保存，双方原文和0/1判断保持各自记录。
- 后端匹配的是同工作区、active、规范正文相同且适用范围等价、判断相反的条目；正文只做NFC/空白规范化，范围做既有等价归一。它不负责语义矛盾判断或部分重叠范围推理。
- `conflictEntryIds` 最多返回32个，没有完整总数标志。结果区应写“本次返回的相反判断（N项）”，不能称为全部冲突总数。
- 原请求重放返回**原entry快照和原相反判断ID列表**，不重算当前状态。之后新增的相反判断不会进入旧收据；原列表中的条目可能已撤回。打开时重新读取固定详情及当前管理状态，不把收据里的旧status当实时状态。
- 当前是工作区权限，没有单条目ACL。本批不新增“单个冲突条目撤权”规则。工作区权限变化或单次读取失败沿现有错误处理，保留已确认收录结果，不拿旧详情冒充新目标。

#### 最小交互

1. 成功后沿现有流程进入证据库、选中实际返回条目，在库视图顶部增加一个小“本次收录结果”区。关系图和固定单页共用这一份结果，不再弹新对话框。
2. 结果区显示上述两类独立信息，可“查看本次条目”。相反判断用可展开的有序按钮列表逐项打开固定详情；新条目和相反条目可以来回阅读，初版不做双栏比较器。
3. 不预加载32份全文、不扫描全库找相反内容。相反项只有ID，点击后用现有 `evidence.get` 读取真实条目；不伪造digest。本次条目有固定摘要，继续沿C06的摘要校验打开。
4. 相反项读取失败只提示该次阅读不可用，原结果和返回的ID仍保留；不改为收录失败，不自动新建或合并。当前撤回状态由重新读取的详情显示。
5. 新的有效收录意图开始时清旧结果；普通浏览、筛选或撤回不改写这份收录结果。关闭结果区只清展示，不删条目，也不丢未确认命令。换服务、身份或工作区沿既有生命周期清理，旧确认不能回填新工作区。
