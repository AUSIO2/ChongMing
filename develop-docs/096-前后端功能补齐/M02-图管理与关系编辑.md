### C05 行为校正 — 类型决定后继，业务动作产生关系

#### 1. 已核实的定义与边界

规则来源为当前目录中的精确 `typeId/version`，默认包见 `resources/data-definitions/fact-checking.json`。不在 UI 硬编码五种类型，不从场景位置或连线推断许可。

| 当前默认 v1 类型 | 合法结构后继 | 对应的上下文动作 |
| --- | --- | --- |
| 来源 | 新闻 | 在此来源下新增新闻 |
| 新闻 | 事实 | 在此新闻下新增事实，可同时指定来源行 |
| 事实 | 核查意见 | 执行核查转换，或手工新增核查意见并明确人工来源 |
| 核查意见 | 核查结论 | 核查转换产生结论，或手工新增结论并明确人工来源 |
| 核查结论 | 无 | 不显示新增结构后继入口 |

这是类型许可链，不是实例单链：一个节点可有多个合法后继，多个意见可参与同一结论；具体结构仍受服务端 DAG、版本与占用规则约束。手工后继数量不能照搬某次自动转换的输出上限。

| 当前默认转换 | 实际输出与自动结构 |
| --- | --- |
| 解析来源 | 一个来源产生0–8篇新闻；输出按 `successorOf` 连接来源 |
| 拆分事实 | 一篇新闻产生0–64条事实；输出连接该新闻 |
| 核查事实 | 一个事实、可带0–8篇新闻上下文；产生1–8条意见和1份结论；事实连意见，同批意见连结论 |

合法后继类型与创建方式是两条规则。用户已明确允许手工创建意见和结论，并要求明确人工来源；因此它们同时保留手工创建与核查转换两类业务入口。手工创建仍遵守精确类型后继、权限及版本，不伪造 producer、Run 或生成出处；转换输出沿真实 producer 记录展示。作为上下文的新闻不能被前端擅自连成新闻→意见的结构父节点。

**人工来源的最小要求**：手工创建时由服务端按实际命令路径记录来源类别，与节点及关系同次提交；Map 详情和单页明确显示“人工创建”，重新读取后仍成立。现有 GraphNode 只有 producer/importedFrom 等信息，没有可直接等价为人工创建的明确标记，因此实施时允许增加必要的最小来源元数据及响应校验，不再承诺“完全不动来源合同”。不接受前端仅临时贴标签，也不把“没有producer”当作人工来源证据。已有导入记录继续标明导入；历史数据缺少明确来源时显示“来源未知”，不回填猜测。创建人及完整来源导航与M05协调，不把本批扩为完整历史系统。

人工编辑一个自动生成节点，不会把它原先的生成来源改写为人工创建；创建来源和后续编辑行为分别表达。本次决定不新增“只有转换才能产生某类节点”的限制，也不改变独立根节点允许范围的待定边界。

| 声明引用字段 | 允许的实际目标 | 保存方式 |
| --- | --- | --- |
| 意见 `evidenceClaimIds` | 同图 Claim v1，0–32项 | 在意见表单选择证据事实，写 payload 字段，后端派生 payloadReferences |
| 结论 `opinionIds` | 同图 Opinion v1，1–8项 | 在结论表单选择依据意见，写 payload 字段，后端派生 payloadReferences |

普通 `reference` GraphEdge 不会更新这些字段，不能代替这两种业务引用。后端当前仍支持通用 reference，本文不谎称它已受 successorTypes 约束，也不在本轮仅改方案时调整其兼容性。界面撤下自由连线入口；已有显式 reference 继续如实只读显示，不批量转换或删除。资产引用仍走现有资产入口，不混作节点引用。

#### 2. 默认操作

1. **在当前节点下新增**：父节点及结构关系固定，只列其精确定义允许的后继类型；只有一种时直接进入对应内容表单。意见和结论也允许人工填写，统一标明人工创建。用户可明确选择来源行。节点、来源类别、successor 及可选脚注由一次 graph.apply 原子保存，失败不留下孤立节点或半条关系。
2. **执行转换**：显示当前类型实际可用的转换；正式输出及连线由后端发布，前端不让用户再给生成产物牵线或改类型。
3. **编辑内容**：编辑 payload，实例类型和所属结构不是普通表单的可改字段。开始编辑是明确的用户意图，会话处理授权；浏览不领取编辑权，占用或冲突用业务文案解释，不能强行抢占。
4. **选择业务引用**：仅为定义声明的节点引用字段提供受目标精确类型约束的候选；修改字段后图上引用随派生索引更新，不能同时维护另一条手工 reference。
5. **结构展示**：前置/后继及引用仍可阅读、定位；移除默认添加关系、编辑起终点、切换边类型、单独删除结构边的入口。旧通用表单不以“高级操作”名义继续绕过这条默认规则。标签备注、特殊来源调整与节点删除策略另行界定，不用旧表单代替业务设计。

独立创建根节点与“从父节点创建后继”分开命名，不能点击已选中的父节点后仍悄悄创建孤立根。当前类型合同没有根创建许可字段，不能仅凭 successorTypes 反推出“只允许创建来源”；根类型范围另行确认，不在校正中暗自禁止独立 Claim 或修改存量图。
