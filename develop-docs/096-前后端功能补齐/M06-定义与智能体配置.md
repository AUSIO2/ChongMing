## 拟新增契约

### D05 共享定义目录（C13）

现有 `definition.get` 继续服务工作区。共享智能体库也需要自己的精确目录，拟新增只读 `definition.library.get({ packageId?, packageVersion? })`，返回 `LibraryDefinitionView {scope:{kind:'library'}, catalog, package?}`。目录读取真实 `control_library/global` 内的包和归档/当前精确Agent，revision取共享库revision；任意已认证用户可读，与现有共享Agent读取规则一致，不额外要求管理员或工作区成员身份。

packageId/packageVersion必须成对，包版本从1开始，未找到精确包返回404，不回落最新版本或工作区。查询使用现有纯读取，不调用会推进writeFence的复制读取。工作区目录仍要求viewer以上，发布仍要求owner。

不能用当前工作区的目录冒充共享库目录。工作区发布继续用 `definition.publish`；本轮不增加共享库发布接口。bootstrap增加可选 `libraryDefinitions?:boolean`，新服务声明true，旧服务缺省时只关闭共享定义目录读取，工作区浏览/发布仍可用。同步公共查询类型、客户端方法目录和响应校验；HTTP/application/CLI/IPC沿既有通用转发，不为相同查询新增平行路径。

JSON草稿在客户端是未校验输入：拟仅在 `CommandInputMap['definition.publish']` 将package区分为unknown；服务端 `ControlCommand` 仍在 `controlReadCommand → definitionsReadPackage()` 后持有DefinitionPackage。HTTP信封、发布命令和校验语义不变，避免前端断言JSON为可靠DTO、导入backend或复制整套定义解析器。其它命令输入类型保持。

#### 第一版行为

在现有“工作台管理”增加“定义中心”分类，延续中文纸面编辑样式。C13完成包浏览和工作区发布，C14再处理智能体角色/阶段绑定，不把两批合在一起。

| 区域 | 第一版内容 |
| --- | --- |
| 目录 | “当前工作区/共享库”范围切换；按包ID与精确版本选择，不默认用latest。工作区成员可读；共享库只读，即使管理员也不在本批增加发布入口 |
| 已发布包 | 标题、ID/版本、摘要、包/Agent精确依赖；展开数据类型的schema/合法后继/引用/展示提示，以及转换的端口/数量/阶段/审核规则。完整JSON可展开，正文保持只读 |
| 草稿 | 工作区owner可复制选定包为独立草稿，或粘贴/载入JSON文件；不自动保存，不写已发布包。文件内容进入同一文本草稿，不另设导入协议 |
| 发布核对 | 明确目标工作区、预期工作区revision、包/类型/转换各自版本、依赖与本包变动，再点击“发布新版本”。显示“本包不再包含”的条目不表示删除全局旧定义 |
| 结果 | 成功显示精确包版本、服务端摘要和新workspaceRevision，再刷新目录与工作区。目录刷新失败仍保留“已发布”事实，不能误报发布失败或自动重新发布 |

**版本规则必须说明清楚。** 现有后端不仅拒绝同版本异内容，也禁止不同包版本重复声明同一个类型/转换精确版本，即使正文相同。仅把package.version改大、原样携带旧类型/转换仍会失败。复制草稿只是编辑起点：实际重声明的定义须使用新版本并调整精确引用；不重声明的旧定义通过旧包依赖使用。不自动给所有定义升版、不重写整张引用图，也不拿改Agent配置当作已升级转换依赖。包/类型/转换版本与Agent配置版本分别显示，Agent版本0合法。

前端仅做JSON语法、基本形状及当前目录可证明的精确引用/版本提示，不声称“本地验证通过即可发布”。Agent历史版本可存在归档，不能仅凭当前Agent列表缺少某版本就误判依赖不存在。依赖闭包、Schema语义、阶段绑定和不可变规则仍由原后端权威校验；缺依赖或冲突时整包失败，无部分发布。不新做校验预览接口、图形Schema编辑器或依赖自动修复器。

#### 状态与失败处理保持简单

- 新增一个组件及一个纯草稿模块；不另建 `definition-state.ts`。请求复用 `useManagementTask` 的复制参数、取消、原请求重试和401处理，身份/工作区替换沿既有组件key释放；范围/包选择在读取、发布或待原请求确认时锁定，避免再造查询竞态框架。
- 已发布目录、精确包体、文本草稿和草稿预期revision分开保存。刷新目录不静默覆盖脏稿或提升其发布版本；放弃草稿必须是明确动作。JSON文件读取也绑定开始时的范围，关闭/换身份后不接纳迟到内容。
- REVISION_CONFLICT保留原文本，手动刷新并重新审阅后才采用新的工作区revision；不自动重发修改后的草稿。同版本内容冲突保留文本，提示新版本处理。
- 丢响应保留同requestId、同包内容、同expectedRevision，锁定新发布，使用“重试同一操作”。不扩大公共重试框架；已有收据重放返回的workspaceRevision可能反映后续写入，测试只要求原包/摘要和无重复写，不虚构历史响应完全相等。
- 发布后调用现有管理刷新，使创建/运行入口取得新目录；已有节点、选中图/运行和旧Run冻结配置继续使用原精确版本。不自动迁移既有图。

### C14 — 通用智能体角色与绑定

#### 第一版要补什么

现有AgentManagement已经能编辑提示词、变量、工具等内容，并保留/只读显示role与bindings；缺的是通用创建、角色选择和绑定增删。C13已接通真实工作区/共享目录，C14直接复用，不另建配置中心或查询层。

| 改动 | 第一版行为 |
| --- | --- |
| 新建 | 新稿可选“绑定已发布阶段”或原有旧版拆分/核查配置；通用稿选择生成内容、规划任务、选择结果三种职责，不再受旧子智能体两种用途限制。没有可用阶段时仍保留原未绑定创建路径 |
| 阶段绑定 | 在当前作用域按“转换ID/精确版本/阶段ID”添加或移除，可绑定多个同职责阶段；选择项只来自真实已发布目录，不默认latest，不要求该stage当前agentRef等于正在编辑的新Agent |
| 变量与结果 | 继续复用原输出格式展示，变量可选项取全部已选阶段允许变量的交集；换角色/绑定后不再适用的已选变量保留并提示，由用户明确移除，不静默清洗草稿 |
| 保存 | 复用agent.create/update、目录revision和Agent revision、原请求确认、脏稿切换与冲突处理。保存结果显示实际Agent配置版本，新配置可为0，更新生成新revision |
| 作用域与权限 | 工作区owner可改，共享库hostAdmin可改；viewer/editor不能管理工作区Agent。两个范围用C13各自真实目录；旧服务缺共享目录时可读原配置，禁用新增/更换绑定，不借工作区选项填充 |

通用配置的role与非空bindings必须一起提交；编辑中可暂时移除所有绑定，但不能保存空集合、重复绑定或职责不匹配的阶段。新通用稿使用一个稳定的自定义kind，业务职责由role表达；所有已保存配置的id/kind/promptPath仍只读，不把角色选择误写成kind变更。

已有未绑定旧配置保持原编辑路径，首版不自动迁移，尤其不自动给旧固定角色添加bindings。删除按钮与“固定”标签沿服务端返回的deletable，不按旧kind猜测；后端现状是绑定配置可以返回deletable:true，本批不顺带改变这一策略。缺失/未解析的保存绑定明确展示原精确身份，不丢字段，不偷偷换成新版本。

#### 绑定不等于启用

bindings声明“可参与这些阶段”，不会改写旧转换的stage.agentRef或规划候选plan.agentRefs。新Agent可以先绑定已发布阶段，以配置版本0保存，再通过C13发布显式引用它的新转换版本；不需要先让旧stage引用新Agent才能创建。更新Agent产生新revision，也不会让旧转换自动取最新版本，旧Run冻结内容保持。

没有任何现成阶段时，可先用原未绑定Agent创建路径建立配置，再在C13发布首个转换，之后补绑定。C14不承诺一次保存从零互相引用的新Agent和新转换，不自动发布包、不自动重写引用或重新运行任务。

#### 一个需要对齐的已有输入规则

讨论时核对发现：已发布定义允许字母开头、含点号、最多128字符的stage.id，但旧controlReadBindings使用只允许字母数字/下划线/连字符且最多64字符的运行时名称规则。合法已发布阶段在绑定输入处被误拒，后续已先测后修，证据见文末。

C14拟将此字段按“已发布阶段引用”读取，并继续由原controlValidateAgentBindings检查精确转换中确有该阶段；不修改Agent ID、kind、工具名等其它运行时名称规则。先补“真实发布带点号/长合法阶段→创建绑定”的有效红，再修这一处输入边界；不存在阶段仍拒绝。既有空/重复绑定、角色/变量、权限/身份和冻结规则保持。此为必要的最小后端修正，没有新API、存储、能力声明或迁移。
