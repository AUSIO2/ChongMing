## 目标与验收层次

本模块同时提高验收层级和验证强度：

- **产品级主验收 A**：以用户目标组织完整流程，验证真实界面操作、服务端事实及同一份数据重新进入后的结果。
- **可靠性验收 R**：验证真实并发、结果不确定时的重放、应用重启和应用崩溃恢复。
- **性能验收 P**：在明确数据规模与机器条件下测量加载、交互和持续负载。
- **设施资格检查 Q**：验证环境隔离、启动/清理、runner 和诊断，作为可信运行的基础门槛。

原计划的环境自检保留为 Q；不以其通过代替 A/R/P。主线是“真实界面发起→真实后端处理→独立授权读取核对→关闭旧 context 后重新进入同一数据”。关键被测操作不能由预置 API 代做。

## 范围与共同约束

复用真实 Vue/HTTP、SQLite、临时 Mongo 副本集、已有 RabbitMQ 和确定性本机响应。基础用例不创建 Run，模型调用数为零。完整审核、复杂编排、手动建边、证据库新交互及全工作区总图仍由所属模块验收。

1. 每个 worker 使用隔离环境，每个独立 test/retry 使用新 case；**同一旅程内的多个角色、context、服务重启共享原 case**，全部操作完成后才撤销令牌。
2. 场景分为空账号、预置关系图、共享角色、多独立分支和规模图。创建旅程仅准备账号/已注册定义，由 UI 创建工作区、图和数据；阅读/并发/性能场景才预置必要数据。
3. SQLite/Mongo 项目分别运行真实 HTTP。SQLite 不启动 Mongo/Rabbit；HTTP 验收不冒充 Electron 本机 IPC 验收。
4. 存储与应用服务分别持有生命周期。重启/强杀只针对自有应用服务；SQLite 目录、Mongo 数据库、身份、令牌、资产和收据保持。最终 dispose 才清理存储。
5. Vite 与故障转发代理保持稳定地址，应用重启后更新真实上游。代理只转发/延迟/截断真实请求或响应，不伪造业务成功、快照或提交结果。
6. 原始 trace/HAR/video 默认关闭，诊断采用受控结果和遮罩截图。服务端核对使用独立授权 gateway，不读取 Vue/Three 私有对象。
7. 实验时序由请求/提交/响应屏障控制，等待有期限；不得用任意 sleep 猜测竞态。结果、失败、冲突、超时和未完成分别记录，不靠重试掩盖失败。

## 可靠性验收

以下轮数为拟定起点，不是已执行成绩；SQLite/Mongo 分别验证各自真实规则。

| 编号 | 故障或并发场景 | 断言与建议强度 |
| --- | --- | --- |
| M00-R01 | 两个编辑者争用同一分支，再交接编辑权并提交已知旧版本 | 协作租约互斥，本机仍有版本保护；旧证明明确冲突，无静默覆盖；2 context，10 轮。不得要求两个客户端同时合法持有同一排他租约 |
| M00-R02 | 不同编辑者同时保存无共享后继的独立分支 | 2 写者×10 轮共 20 次保存均有真实重叠与完整结果；4 写者作为扩展；SQLite 串行提交不被描述成数据库并行 |
| M00-R03 | 真实 UI 上传资产，后端提交成功后截断响应，再点击已有“重试同一操作” | requestId 与参数/字节摘要不变，仅一份资产，真实下载内容一致；3 轮。代理先收到真实成功响应且独立读取查明提交，再截断，不伪造成功 |
| M00-R04 | UI 已收到保存成功后，优雅停止并重启应用，再用同账号新 context 读取 | 原身份、全文、版本及资产保持，后续仍可写；3 轮；不 seed 覆盖旧库 |
| M00-R05 | UI 已收到保存成功后，仅强杀自有应用服务，再打开同一存储并重新进入 | 已确认提交不丢、存储可继续使用；3 轮。应用崩溃不等于 Mongo failover、数据库进程崩溃、断电或磁盘损坏 |
| M00-R06 | 两个工作区来回切换时延迟旧请求响应，或中断并恢复事件流 | 迟到结果不覆盖当前身份/图；恢复后公共读取和 UI 最终一致；5 轮，不写成“每个事件恰好一次到达” |

未知在途请求必须独立查明最终状态，不能假定全部成功或全部回滚。M00-R03 固定使用已有上传重试；偏好冲突恢复及其他尚未具备的恢复 UI 留 M01。

重启后的再次写入保持真实租约规则：协作模式的未过期占用可能仍有效，新 context 应显示该事实，在到期或合法释放/回收后再取得编辑权。使用明确的测试短租期、服务端到期事实及有界轮询；不清租约、改数据库时钟或降低生产校验来制造立即可写。本机无客户端租约另行断言。R01 中界面占用/交接与独立公共 API 的旧证明拒绝分别留证。

## 性能与容量验收

容量沿用[082 的工程阶梯](../082-前端图工作台与阅读视图重构计划.md)作为方向。本轮测当前单 Map 工作集；全工作区总图由 D-01 设计，不能将单图成绩称作全库容量通过。

| 配置 | 节点 / 存储边 | 当前计划用途 |
| --- | --- | --- |
| calibration | 200 / 800 | 校准测量链路，不作为容量通过的主要依据 |
| standard | 1,000 / 10,000 | 第一档正式性能门禁候选 |
| capacity | 10,000 / 50,000 | Sandbox 量级的单图容量评估目标，明确报告阻塞或失败 |
| workspace-future | 50,000 / 200,000 | 既有全工作区目标；当前不在 M00 声称已能完整查询/绘制 |

数据固定随机种子、类型/正文大小分布和拓扑；包含独立分支、引用环与高连接节点。正文与 JSON 字节数实际记录，不能只用极短空 payload。successor 保持合法 DAG，payloadReferences 由后端派生；边数、派生引用数、加载数和实际绘制数分别报告。超过现有响应/批量上限要明确失败，不能抬限、截断或减少数据后仍沿用原规模标签。

初始数据提案按实际可构造的精确类型固定分布：新闻 5%（正文约 8 KiB）、事实 65%（约 512 B）、意见 20% 和结论 10%（各约 1 KiB），另含少量约 64 KiB 长正文；全部按 UTF-8 实际字节记录。若当前精确定义不允许该组合，调整输入方案并记录，不能注册特制的空 schema 减轻负载。

| 编号 | 场景 | 记录与候选目标（未实测） |
| --- | --- | --- |
| M00-P01 | 登录后的打开图与正文读取 | standard 图数据/DOM 可用目标 ≤5s；选点/单页内容响应 ≤250ms；capacity 候选 ≤10s/500ms。Vite 静态编译预热 1 次后测 5 次，报告 median/max；每次新 context 使用原 case 登录，确认目标图尚未打开，再计时首次打开；已保留场景的热复访和服务冷启动另记 |
| M00-P02 | 20 次图↔单页往返及 10s 旋转/缩放 | 身份、关系、选择保持，交互仍可完成；报告 RAF 间隔 median/p95、浏览器/服务端内存序列。固定 GPU 条件下 RAF 候选 median≤33ms、p95≤50ms；RAF 只是调度代理，不等于真实 GPU 帧率 |
| M00-P03 | 2 个真实浏览器 context 加真实 HTTP 混合负载，80% 读/20% 独立分支写 | stress 闭环分别保持最多 8/16 个在途逻辑操作，限时 5min 或最多 10,000 操作；endurance 以 3 个逻辑操作/秒运行 5min（900 个，上限 1,000），扩展 30min（5,400 个，上限 6,000）。记录逐操作延迟、真实并发、吞吐及所有结果，前后数据无丢失或重放重复 |

80/20 按逻辑业务操作计，branch.get、claim/renew 等辅助 HTTP、失败尝试和重放单列。stress 遇操作数/期限任一上限即停止并排空，报告实际时长；短运行不能冒充耐久通过。endurance 依单调时钟节拍发起、限制在途量，超过排队/请求期限明确失败；操作上限提前触发或不足完整时长标为 incomplete，不能报告完成 5/30 分钟。每个阶段记录目标/实际发起速率，不能用 Promise 数量声称真实数据库并行。

性能测量起止点、设备、软件/GPU 模式及样本数必须明确。当前无公开渲染完成信号时只报告“数据/DOM 可用”“首次交互完成”和 RAF 代理，真实 GPU 完成标为 unavailable；不得注入 store/访问 Three 私有场景伪造证明。无 WebGL 的二维回退单独报告，不代替三维成绩。

5 次只用于 median/max。逐 API p95 至少 100 个完成样本，p99 至少 1,000 个，仍为经验分位数；样本不足标记 insufficient，不捏造统计保证。原始样本保留，失败/超时不从总体中消失。浏览器内存不可用时写 unavailable，不能用 Node worker 内存替代或填 0。

**验收强度与阈值是当前工程提案**：首次测量前记录并冻结参考设备和门禁配置；变更必须说明理由，禁止因测试失败自动放宽。standard 是候选必过档；capacity 当前要求完成真实评估及问题归属，若未达标不能宣称容量通过。混合负载的时延和内存预算待参考机首测前确定，不用任意百分比冒充已验证预算。
