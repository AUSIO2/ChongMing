## 2. 装配与资源所有权

```text
suite：受限运行目录、按需 broker
  → worker runtime：稳定存储（SQLite目录 / Mongo副本集及数据库）、namespace、case身份
    → 稳定故障转发代理 → 独立 Vite Web进程（浏览器始终连接该origin）
    → 可单独停止/强杀/重开的应用服务进程（API/Host/数据库连接）
  → 每个test：新case，内部可含多个角色/context和同case服务重启
    → UI操作 → 独立公共API核对 → 新context重新读取原数据
  → 用例所有context关闭后才revoke case
  → 最终dispose：应用/Web/代理结束 → 最后清自有存储与namespace
```

- **应用寿命小于存储寿命**。父 runtime 持有 SQLite 目录、MongoMemoryReplSet/固定数据库、消息 namespace 和私有 case/初始身份状态。应用 child 借用目录/URI/queue，restart 不清库、不创建替代 case、不覆盖 seed；最终 close 才删除。
- run-ui 持有/借用套件 broker；父 runtime 分配并记录 namespace，私有 start IPC 传 queue。child 不停止 broker、不删除 namespace；旧无参数 ui-fixture 继续自建并清理，兼容旧调用。
- worker 间隔离；独立 test/retry 新 case。A01 使用空账号由 UI 创建；A02 使用真实关系图；A04/R 使用同 case 多角色/独立分支；P 使用固定种子的规模图。不得全场景一律预置最终结果。
- 同一 test 可开多个全新 context；重入/重启持久化一直使用原账号、workspace/map/node 和未撤销令牌。父侧 case 记录跨服务 generation 保持，最后统一释放；不同 test 不共用业务身份。
- Vite 与代理的 origin 在服务重启期间稳定。Vite 启动时固定指向该 runtime 代理；代理更新到新 generation 的真实 API 端口。没有预探测端口/假业务响应；SSE 流正常转发。
- 服务崩溃只强杀应用 child 的自有进程树，不能杀父层 Mongo/Vite/代理；等待旧 SQLite 连接所在进程退出后再打开同目录。单成员 Mongo 的应用崩溃恢复不等于主节点切换或数据库崩溃测试。
- 故障代理只支持受控屏障/中断/延迟；提交丢响应场景先收到真实成功结果并经独立读取核对，再丢弃客户端响应。未知在途结果必须查明，不能假定回滚。
- Node 准备与核对使用真实授权 gateway，凭据只在私有内存/IPC/必要受限文件。报告不序列化 token、broker URL 或原始 payload。
- 应用/Web 进程在启动前安装 SIGINT/SIGTERM/父 IPC 断开监听；取得资源立即登记。父层看门狗只回收归属可核验的对象；超时不等于资源已经释放。
- SQLite/Mongo 均为 HTTP 产品验收。Electron 本机 IPC/窗口、Windows 强制回收、数据库进程崩溃/磁盘故障不混记为本轮成绩。

## 4. 测试内数据与接口

类型跟随实际所有者文件，不创建集中转发的 `types.ts`。

| 类型 | 定义位置 | 内容与约束 |
| --- | --- | --- |
| `UiFixtureOptions` / `UiFixture` | `ui-fixture.ts` | 保留旧默认及返回值；增加 signal、测试租期、借用目录/queue/mongoUri、fresh/reopen 模式及私有 bootstrap 引用。reopen 仍正常 application.initialize/索引与消息恢复，但不调用 seed/createUser/createToken/createWorkspace |
| `WorkspaceRuntimeOptions` | `workspace-runtime.ts` | storage、目录、brokerRef、启动/关闭/重启时限及已知故障枚举；父侧持有实际存储，SQLite 不接受外部 queue |
| `WorkspaceRuntime` | 同上 | 稳定 proxy/webUrl、当前 API 与 serviceGeneration、存储句柄、createCase/releaseCase/restartService/close；close 为最终销毁，restart 只换应用 |
| `WorkspaceCase` | 同上 | caseId、场景形状、actors(owner/editor/viewer) 的私有凭据、已存在/由 UI 新建后读回的业务身份与预期；父侧跨 context/restart 保持，不能序列化为附件 |
| `WorkspaceRuntimeRecord` | 同上 | runId/runtimeId、存储目录/自有 Mongo 进程、应用与 Web 各进程/组、serviceGeneration、代理/服务回环端口、brokerRef 和 namespace；借用关系明确，不含 token/连接 URI/模型 key |
| `WorkspaceFixtureMessage` | 同上 | 带 runtimeId/requestId/serviceGeneration 的 start(fresh/reopen)/createCase/releaseCase/stop 和响应；旧 generation 响应失效，case 不因换 generation 消失 |
| `WorkspaceFixtureFailure` | 同上 | 阶段、稳定故障 code、资源种类、首个错误及附带清理失败；原始 cause 仅在测试内存保留，公开诊断采用字段白名单 |

调用方传入目录/queue/mongoUri 时，调用方持有最终删除责任；现有无参数调用仍由 ui-fixture 自己创建并关闭资源。fresh 的初始身份引用由父侧私有保存，reopen 使用原记录并检查仍有效；不能创建同名新用户冒充原账号。

另有 WorkspaceFaultRule（请求身份/阶段/次数的有限枚举）、WorkspaceLoadProfile（规模/负载/预算）及 WorkspaceMeasurement（指标种类、原始样本、单位、起止点、可观测性与失败分类），分别跟随代理与性能文件；不复制生产 Graph DTO。

## 5. 文件与主要函数设计

下表参数和返回值是设计合同，不是本轮生成的可运行代码。实例方法可保持简短名称；普通导出函数遵守领域命名。

### 5.1 `tests/client/ui-fixture.ts`

| 函数 | 输入 → 输出 | 责任与失败规则 |
| --- | --- | --- |
| `fixtureCreateEnvironment(options)`（现有） | 可选 UiFixtureOptions → Promise<UiFixture> | 保留旧默认；runtime 只借用存储/queue。每次都执行正常应用初始化/连接/索引/消息恢复，fresh/reopen 只决定是否 seed 和创建基线身份；失败不删借用库 |
| `fixtureCloseEnvironment(state, policy)`（新增私有） | 本夹具具体资源状态、关闭时限 → Promise<void> | 按资源依赖顺序尝试关闭，继续执行其他清理，汇总失败；重复 close 共用同一 Promise；错误不能变成成功 |
| `fixtureObserveLifecycle(event, probe)`（新增私有） | 允许的阶段/资源事件、可选测试钩子 → Promise<void> | 暴露 after-db、after-http、before-ready 与资源关闭边界；钩子仅制造测试故障，不替换实际后端/网关 |
| `fixtureReadBootstrap(mode, reference)`（新增私有） | fresh/reopen 及私有引用 → 既有启动身份 | fresh 建立原有基线；reopen 从同存储认证原 token、读取原 workspace，拒绝缺失/失配而不重新 seed |
| `fixtureRunMain()`（现有） | CLI 选项 → Promise<void> | 保留手动夹具入口；使用同一关闭合同，启动前注册中断，公开事件不含原始凭据或异常文本 |

应用内先停止 Host/新工作与 HTTP，再关闭消息和数据库连接；runtime 模式不处理 Vite、Mongo 副本集、namespace 或父侧目录，这些留最终父层 dispose。旧自建 fixture 仍清自己的数据库与目录。相互独立的后续清理继续；有写入者存活时不抢先删除其工作目录。

单项关闭超时只说明该步未确认；需交给父层回收与核验，不能只用 Promise.race 就标记资源已结束。启动错误作为首要 cause，附带清理错误共同保留；不能用 catch 中的关闭异常覆盖原错误。

### 5.2 `tests/browser/workspace-runtime.ts`

| 函数 | 输入 → 输出 | 责任与副作用 |
| --- | --- | --- |
| `workspaceStartRuntime(options)` | WorkspaceRuntimeOptions → Promise<WorkspaceRuntime> | 预建私有目录/存储/namespace；启动真实应用、稳定代理及独立 Vite；登记 PID/端口与借用关系，部分失败进入最终收尾 |
| `workspaceCreateCase(runtime, shape)` | runtime、empty/related/shared/independent/dense 场景 → WorkspaceCase | 按场景准备前提，记录 actors 和业务身份；empty 不预先创建被测 workspace/map/node；结果归父侧 case 注册表 |
| `workspaceRestartService(runtime, mode)` | runtime、graceful/crash → Promise<void> | 只停止/强杀应用树，核验旧进程结束，保持存储/namespace/actors/proxy/Vite；generation 增加后 reopen 并切换真实上游 |
| `workspaceReadAuthoritativeState(runtime, actor, target)` | 同 case 合法角色、目标身份 → 授权读取 DTO | 使用独立 gateway 从公共 API 读取身份/正文/revision/资产，断开连接；不用 DOM 与服务端同一份前端缓存互证 |
| `workspaceBindCreatedTargets(runtime, caseId, evidence)` | UI 真实成功响应身份或公开列表定位条件 → CaseTargets | 被动观察 workspace.create/map.create/graph.apply 成功响应的实际 ID，或按 case 唯一名称标记完整分页定位；经独立授权 get 核对后登记父 case；不预造目标对象或读 Vue 私有状态 |
| `workspaceReleaseCase(runtime, caseId)` | runtime、case 身份 → Promise<void> | 该用例所有 context 关闭后，依据父侧原 tokenId 撤销所有 actors；跨重启沿用该表，重复释放幂等 |
| `workspaceStopRuntime(runtime)` | 所属 runtime → Promise<void> | 仅最终 dispose 调用；先停应用/Web/代理，再处理自有 Mongo/namespace/目录，限时回收并核验；不得将此函数当作 restart |
| `workspaceAssertStopped(record)` | 所有权记录 → Promise<void> | 在有限期限内观察实际端口不可连接、自有进程结束及目录结果；不能只检查 stopped 消息或 Promise 已完成 |
| `workspaceExchangeMessage(channel, request)`（私有） | 私有 IPC、类型化请求 → Promise<响应> | 负责超时、取消、序号/身份校验及注销 listener；不暴露公共 HTTP 控制 API |

普通错误、挂起、父 IPC 断开分别可观测。进程回收只处理本次运行登记且归属仍可核验的对象；不能使用进程名匹配或清理全局 Docker。遗留资源/归属无法核验时报告明确失败。

### 5.4 `tests/browser/workspace-fixture.ts`

### 5.5 `tests/browser/safe-reporter.ts`

采用 Playwright reporter 的既有方法约定；实际选定版本后核对其接口并固定依赖。

| 方法/函数 | 输入 → 输出 | 责任 |
| --- | --- | --- |
| `onTestEnd(test, result)` | runner 结果 → void | 输出静态编号、项目、状态、耗时、源码位置及安全诊断 code；不序列化原始 error、调用日志、附件正文或 expect 实际值 |
| `onStdOut()/onStdErr()` | worker 输出 → void | 不直通任意文本；仅接纳自有结构事件的白名单字段，其他输出记为被抑制的诊断类别 |
| `onError(error)` | 框架级错误 → void | 输出可定位的受控错误分类与仓库内源码位置，原始消息/stack 不进入终端或公开报告 |
| `workspaceReadSafeResult(result)`（私有） | 不可信结果对象 → 安全结果 DTO | 显式投影字段并检查路径/长度，不靠正则替换几个已知 token 宣称全面脱敏 |

首版不启用默认 HTML/JSON/raw trace 报告链来绕过此策略；HTML 报告如以后需要，基于已确认安全的 DTO 另做输出。用例中不将 token 传给 expect 的失败值或测试标题，避免断言输出反向泄露。

### 5.6 `tests/run-ui.ts` 与 Rabbit 复用点

| 函数 | 输入 → 输出 | 责任 |
| --- | --- | --- |
| `uiReadRunOptions(argv)` | CLI 参数 → UiRunOptions | 仅允许 local/collab、suite=qualification/acceptance/reliability/performance、已登记 load-profile、load-mode=stress/endurance、soak、受限 grep/list；不允许 reporter/config/debug 覆盖 |
| `uiRunBrowserSuite(options)` | 项目和运行选项 → Promise<void> | 启动前安装信号；预建运行目录；只有含 collab 才取得套件 broker；启动 Playwright、接收受控结果，finally 收尾 |
| `uiCloseBrowserSuite(state)`（私有） | runner/运行目录/broker 所有权 → Promise<void> | 转发停止并限时等待；复核登记的残留 runtime；处理自有 namespace/目录，最后释放自建 broker；保持业务失败/中断的非零结果 |
| `rabbitDeleteNamespace(queue)`（按需提取） | 已验证的测试 queue 配置 → Promise<void> | 复用既有具体队列/交换器删除规则；caller 必须持有本次分配的 namespace，保留现有 deleteNamespace 的范围检查 |

Rabbit 夹具可增加可选 brokerFile 输入，省略时沿用现有环境变量/自建行为；父 runtime 用显式输入取得 queue 及删除句柄，避免并行环境通过修改全局环境变量切换 broker。

runner 使用管道接收输出，不直接继承任意 stderr 到终端；只展示安全 reporter 的字段，未知输出标为基础设施诊断。运行目录中的所有权记录使用原子写入和受限权限，凭据不写入该记录。

恢复记录的顺序明确为：运行启动前建立 runId 和受限 brokerRef→runtime fork 前原子登记记录→每取得进程/端口/namespace 后更新→正常退出写入已核验的终态。run-ui 收尾枚举本 run 的记录并核对 runtime 身份；runner/worker 中断后，由该记录和启动时登记的受限 broker 配置恢复清理。先正常停止/限时回收自有进程并验证端口，再清 namespace 和目录，最后关闭自建 broker。记录缺失或归属/停止状态无法确认时保留失败诊断，不猜测或扩大清理范围。

公开 CLI 不允许覆盖 reporter/config、trace/video/HAR、输出目录或启用 debug/record；子进程环境由必要系统项与本次测试配置显式组装，不继承可开启原始动作日志的调试选项。故障子 runner 同样强制安全 reporter 和产物策略；直接调用底层框架命令属于未受此验收入口保证的运行，不能将其报告冒充 Q07 通过证据。

保留 `tests/run.ts` 的既有行为。Rabbit 提取只在确有既有夹具与外层收尾两个调用者时进行，不为统一入口改造全部测试基础。

### 5.7 故障、数据与性能文件

| 文件/函数 | 输入 → 输出 | 责任与验证边界 |
| --- | --- | --- |
| workspace-fault-proxy / `workspaceCreateFaultProxy(input)` | 初始真实 target、允许规则 → FaultProxy | HTTP/SSE 流转发，稳定监听地址；随 serviceGeneration 切换上游；不读写生产存储 |
| 同上 / `workspaceArmFault(proxy, rule)` | 一次性请求/响应屏障 → FaultHandle | 只匹配指定请求/连接和次数；提交丢响应时先等真实上游成功及独立核对；迟到与断流不返回伪造快照 |
| 同上 / `workspaceReleaseFault(handle)` | 已登记屏障 → Promise<void> | 继续/断开受控流并注销规则，finally 也能释放，不影响下一用例 |
| workspace-dataset / `workspacePrepareDataset(gateway, catalog, profile)` | 授权网关、精确目录、固定种子/规模 → DatasetManifest | 通过合法公共命令批量准备前提；记录实际节点/边/派生引用与字节，检查计数/身份；不把生成耗时计入正式图加载 |
| workspace-performance / `workspaceMeasureInteraction(page, action, expectation)` | 真实动作及可观测完成条件 → Measurement | 以浏览器同一单调时钟记录，区分 DOM/交互/RAF 代理；不能把 HTTP完成或canvas存在当GPU完成 |
| 同上 / `workspaceRunMixedLoad(runtime, case, profile)` | 真实授权请求/浏览器与预算 → LoadSamples | 固定种子、受控在途量和屏障；记录每个逻辑操作及尝试/重放/冲突，限时停止并排空；SQLite 不宣称SQL并行 |
| 同上 / `workspaceSummarizeMeasurements(samples, profile)` | 原始样本与冻结阈值 → SafeMetrics | median/max及足样本分位数；失败/超时/insufficient/unavailable显式保留，不能过滤成好看的平均值 |
| workspace-load.config | profile 数据常量 | 参数与门禁唯一执行配置；数值来源见 M00 计划，开测前冻结，报告机器/GPU/版本/payload/拓扑及变更理由 |

角色准备可使用现有授权 API；创建旅程的 UI 写入不能被 dataset helper 代替。并发图要有真正无共享后继的独立根，不能把 news→claim 当作不相交分支。服务端核对与 UI 交互不同来源；不为验证方便注入 Vue/Three 内部状态。

独立核对直连当前真实应用 API，使用同 case 合法凭据，避免被故障代理的目标响应屏障阻塞；UI 始终走稳定 Web/代理。A01 的 case 初始目标字段为空，UI 成功后通过 workspaceBindCreatedTargets 登记实际身份，再做独立读取和重入；不得把 DOM 中同名文字当作身份一致的证明。

重启不清持久租约。R04 可显式释放编辑权后优雅重启；R05 另验证崩溃前占用仍按真实到期规则存在，新 context 先观察占用，再按测试短租期/服务端事实有界等待并重新领取。不能为“后续可写”绕过租约。规模/持续负载的租约取得/续租辅助请求单列统计。

持续写入使用固定长度正文并记录真实业务与收据存量增长，不靠定期删数据/收据维持成绩。纯图↔单页往返的内存序列与混合写入分开，避免把真实业务增长误判为前端泄漏或反过来掩盖无界缓存。

## 7. 配置、时限与失败产物

- Chromium local/collab 两项目，runner workers=1/retries=0；可靠性/负载在单个case内显式创建并发客户端，不能把worker数与业务并发混淆。
- Vite由独立Web进程装配，稳定代理与存储由父runtime持有；最终dispose才销毁。资格/产品/可靠性/性能按suite明确选择。
- 启动/重启/关闭与单用例均有预算，初始建议启动120s、普通页面30s、正常关闭30s、最终回收15s；可靠性和5/30min负载用例按其明确预算另设deadline，不被普通30s误杀，也不使用无限超时。
- 性能起止点、负载参数、候选阈值、样本数和机器条件见模块计划及workspace-load.config；尚未实测，数值需在首次运行前确定。current单图与未来全工作区容量分开。
- RAF是调度代理，DOM就绪不等于GPU完成；缺少支持的观测标为unavailable。二维/软件渲染单独分类；Node worker内存不等于浏览器内存。
- POSIX目录0700、必要凭据文件0600；凭据目录与报告分开。原始trace/HAR/video、自动全页截图默认关闭；受控失败截图遮罩输入/敏感提示。
- 成功不默认留截图；脱敏失败报告和原始性能样本保留到显式清理。性能样本仅含允许元数据，不保存正文/认证header。CI保留期另配，不能声称本轮已经接入CI。
- 不输出token、broker URL、SDK任意异常或原始payload；允许结果中包含profile/样本单位/观察类型/失败分类/设备和聚合统计。未知输出抑制，原始错误cause只留私有测试内存。
- reporter/config/debug/record及原始产物选项不能经普通CLI旁路；故障子runner使用同策略。资源释放未核验时保留失败，不能因进程已退出就算清理通过。
