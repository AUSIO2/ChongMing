## 已核实的现状

- C02 实施前，bootstrap 有 `clientLeases` 等元数据，没有独立功能能力声明。协作装配注入了 `evidenceQuery`，本机装配没有；现已按实际装配声明能力，不从 URL 或租约策略猜测证据库可用。
- C03 实施前，`persistPreferences()` 每轮新建 requestId，网络失败与明确冲突都会设置 `preferencesBlocked`，普通刷新不会解除。现已保留待确认原请求，偏好恢复独立于图命令重试。
- 只修这两条用户路径，复用现有 Vitest 类型化 gateway、Playwright fixture 与正常连接流程，不增加进程协议、看门狗或通用重试框架。

## 拟新增契约

### D01 服务能力（C02）

在 `AppBootstrap.metadata` 增加可选的 `capabilities`。C02 首先落实 `evidenceLibrary`，由 apps 实际是否装配 `evidenceQuery` 注入控制面，不由 URL、客户端模式或租约策略推断。

`publicationPreview / runHistory / mapRename / libraryDefinitions` 继续作为后续模块的预留名称；对应 API 未落地时保持未报告或 false。本批不为这些未来能力编造业务测试。现有 `run.get` 不代表已有历史目录，现有 `definition.get/publish` 也不代表共享定义库完成。

未报告的新能力按不可用处理，并给出中文说明；既有基础图读写继续按现有合同工作。角色权限在能力之上单独核对。后续 C04/C09/C11/C13 在实现相应 API 后才声明该能力可用。不得为了隐藏错误把失败请求当作空数据。

### C02 — 能力声明与门控

- 测试已落地于现有 `tests/backend/modules/graph/local-coordination.spec.ts`、`tests/backend/modules/workspace/workspace.spec.ts`、`tests/client/graph-client.spec.ts`、`tests/client/session.spec.ts`、`tests/browser/workspace-acceptance.spec.ts`。只在既有浏览器文件新增一组 M01-C02（本机/协作各一例）并扩展 A04，不新增测试文件、夹具或依赖。
- 验收：本机不发出不可用库请求，协作入口可用；viewer 不因能力开启获得写权限；旧服务缺少能力字段显示明确状态；身份/连接切换不遗留上个服务的能力。

- 确认生产范围为六个现有文件：`contracts/control.ts`、`backend/application/graph-application.ts`、`backend/modules/workspace/workspace-service.ts`、`client/graph-client.ts`、`apps/ui/views/WorkspacePage.vue`、`apps/ui/components/shell/WorkspaceSidebar.vue`。不新增独立能力层，不修改两个 apps 装配文件、client-session 或 C03 偏好逻辑。
- 契约为可选 `metadata.capabilities?: { evidenceLibrary?: boolean }`。后端始终输出显式 true/false；客户端允许旧服务省略对象或该字段，已存在字段必须为 boolean，未知后续字段不作本批能力宣告。
- 后端 `applicationBuildService()` 按 `options.evidenceQuery !== undefined` 推导能力并传给 `controlCreateService()`，在现有返回对象 `read()` 的 bootstrap 分支输出；不新增并不存在的 `controlReadBootstrap()`。
- 前端直接从 bootstrap 派生一个可用性 computed，门控侧栏、收录、选材和库相关 active/canEdit。读入口与写权限分别判断，viewer 可以读取可用内容，写动作继续使用已有角色门控及后端鉴权。能力失效时清除 runEvidence 已选引用并关闭收录，复用现有页面清理逻辑。
- 回退：新能力入口关闭；保留基础读写及已加载只读数据，不伪造成功结果。

### C03 — 偏好保存恢复

- 测试只扩展既有 `T/client/session.spec.ts`，四组覆盖原请求重试、版本冲突两种选择、保存中连续操作、切工作区迟到结果（含 A→B→A）。原跨工作区用例保留，不把已有通过行为追认为红灯。
- 既有 `T/browser/workspace-reliability.spec.ts` 增加两条单轮流程：真实提交后丢响应并原请求重放；同身份独立客户端制造真实版本冲突并从页面恢复。后者不宣称真实双窗口验收。后端原偏好用例仅补同 ID 改参及新 ID 旧版本拒绝对照。
- 验收：结果不确定时原请求重试、明确冲突由用户选择、切换工作区后迟到回包隔离；节点/标签可继续操作且明确显示未同步状态。

- 生产只改既有 `UI/state/client-session.ts` 与 `UI/views/WorkspacePage.vue`，不新增 composable 或提示组件。保留现有 250 毫秒防抖和串行保存，偏好同步状态归会话独占，不占用图命令的 busy/canRetry/error。
- `persistPreferences()` 持有一份完整待确认请求及最新本地改动；新增 `retryPreferences()`、`resolvePreferencesConflict('server'|'local')`。身份或工作区变化结束旧偏好代次；旧成功、失败和 finally 均不得污染新范围。
- 网络结果不确定保留原 requestId 和完整参数重试；原请求确认后再保存期间产生的最新选择。重放可能返回服务器当前值，只接纳保存基线，不覆盖最新本地选择；若内容已不同于原请求，则停在冲突选择，不继续覆盖远端。明确 REVISION_CONFLICT 才走版本冲突；IDEMPOTENCY_CONFLICT 保留原请求并显示错误，不能通过新选择自动换 ID 越过。
- 冲突恢复用现有 `workspace.get` 读取最新偏好。采用服务器设置时显式恢复标签/选择；保留本窗口选择时用最新偏好 revision 和新 ID 保存当前快照。普通刷新不擅自丢弃待确认请求或覆盖本窗口选择；二次冲突仍停下供用户选择，不无限自动重试。
- 回退：停止新队列并保留当前界面选择；不覆盖远端偏好来伪造回退。
