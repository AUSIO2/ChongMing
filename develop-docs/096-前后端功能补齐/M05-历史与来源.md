## 拟新增契约

### D04 运行目录与产出定位（C11）

已随C11新增 `run.list({ mapId, operationId?, cursor?, limit? }) → GraphRunPage`，只读单个Map，以现有viewer权限逐页授权，不领取分支/Run控制权、推进工作或写收据。

`GraphRunPage` 返回 `mapId`、`items: GraphRunSummary[]`、`nextCursor: string | null`、`directoryVersion`。每条摘要只含 `runId`、status、archived、mode、paused、createdAt/updatedAt，以及 `stepCount`、`operationCount`、`pendingReviewCount`、`outputCount`；不返回payload、definitions、完整Operation或冻结材料。

数量按已保存记录解释：步骤数取计划步骤数，Operation数取已实例化数量；待审核数只计活动Run中 waiting且review.pending的Operation；产物数取各Operation保存的outputRefs总数（包含复用产物引用），不把候选数当已发布数量，也不查询当前节点还在不在。

合并 `runs/runHistory` 后按runId去重，current优先，与 `run.get` 保持一致；再按 `createdAt DESC, runId ASC` 稳定排序。archived按实际存储归属判断，不能从completed/failed/cancelled状态推断。默认25条、最大100，limit须为1–100整数；operationId精确匹配 `operation.id`，不是关键词、前缀或 `reusedFromOperationId` 的隐式匹配，不提供动态状态筛选。

游标使用项目已有base64url JSON/稳定摘要方式，在本模块内小范围实现，不抽跨模块分页框架。内容绑定Map、规范查询摘要（operationId及实际limit）、目录版本和最后一条 `(createdAt,runId)`；不超过1024字符，解析失败或跨查询使用返回明确游标无效错误，不将游标当授权凭据。operationId沿现有普通非空字符串合同，不为目录改成UUID限制。

无效格式/跨图或参数不符的游标返回400 `INVALID_CURSOR`；合法游标的匹配目录版本已变化才返回409 `RUN_CURSOR_EXPIRED`。非法limit沿400 `INVALID_ARGUMENT`，不混成权限或可自动重试错误。

目录版本基于匹配的有序 `(runId,createdAt)` 集合：新增/移除匹配运行导致 `RUN_CURSOR_EXPIRED`；状态更新、updatedAt 改变、current→history 搬移不导致过期。每页状态取读取时的值，不承诺分页是状态快照。新增匹配 operationId 的成员按目录变化处理。

真实启动B通常同时新增B并归档旧终态A，未筛选目录会因“新增B”过期，不能误记为归档导致。搬移不参与版本可在纯记录或排除B的精确筛选中验证；不要据此要求启动新运行后旧游标总能续用。

详情复用 `run.get`，保留current优先、找不到Run的原行为。C12拟将 `producer.operationId` 或 `reusedFromOperationId` 显式作为operationId查目录；不从workId或节点ID猜runId。

bootstrap已增加可选能力 `capabilities.runHistory`，当前本机/协作实现均声明true；旧服务缺省视为未提供目录。前端不探测未知方法，也不把 `snapshot.runs` 假装成完整历史。

存储仍沿现有整图读取，可能整体载入runHistory，当前只保证列表响应有界；不新增表、索引、存储端口、迁移、历史保留/删除策略，不宣称数据库级无限历史分页。也不承诺恢复任意旧输入正文。

### C11 — 有界运行历史

#### 要解决的问题与现状

现有 `runCreateRun()` 在启动新Run时，把 `runs` 中已终态的记录移到 `runHistory`，活动Run继续留在 `runs`；完成本身不会立即归档。`run.get` 已能读取两处并返回完整保存详情，但 `GraphSnapshot` 只公开 `runs`，当前下拉框也只遍历它。因此旧运行通常是已有记录却没有发现入口，C11补目录和只读阅读，不重做运行系统。

#### 最小交互与状态归属

1. “运行历史”打开一个独立面板。列表显示时间、状态、未归档/已归档、处理方式、步骤/Operation/待审核/产物数量；详情按需 `run.get`，只保留当前选中一份，不预载25份完整Run。
2. 面板顶部显示该Run的读取时状态，再按Operation折叠复用C10内容：输入/context版本、阶段、已保存计划/候选、审核记录、实际产物和冻结材料。普通输入版本不符仍明确不可用，产物仍是发布时保存内容，不假装当前节点正文。
3. 历史选中与 `session.selectedRunId/selectedRunControl` 完全独立。面板不调用 `session.selectRun()`、applySnapshot、claim/release、pause/resume/cancel或review.answer；点到正在运行/待审核的记录也只读，不提供“在此领取/批准”等写入口。
4. 列表/详情标注“读取时记录”，不承诺实时状态快照；状态更新或归档后可手动刷新。无后台轮询，不因控制续租或snapshot.revision自动重载目录。
5. `useRunHistory()` 拥有目录及详情各自的loading/error、取消信号和请求序号，提供 `refresh()`、`loadMore()`、`select(runId)`。打开首读25条；游标过期停止追加、提示刷新，手动刷新从第一页重新读取，不偷偷拼接新旧目录。
6. 用户/服务/工作区/Map变更或面板关闭时取消并清空；详情A→B→A也以请求序号隔离。响应接纳时核对Map上下文、目录版本或所选runId；旧401不结束后来会话。查询失败、空列表和详情不可用分开提示。
7. 原写命令busy或待确认时仍允许历史只读查看；历史读取不占用会话busy、不调用clearError，不丢失原“重试同一操作”。打开/关闭面板不取消后台运行或释放当前控制权；原控制租约续租可照常进行。

#### 复用C10的只读边界

仅给 `OperationReview.vue` 增加默认false的 `readOnly` 模式。历史时令预览上下文的operation为空，pending/pendingResult门控关闭，操作函数同时拒绝写意图；不显示批准/拒绝、发布预览/刷新预览等入口。不能只传canEdit=false，因为C10允许viewer读预览；也不能只关闭预览能力而显示错误升级提示。

历史面板直接复用此组件，不套入带运行控制的 `RunReview.vue`，不连任何answer/控制事件。completed条目沿outputRefs显示保存候选，active/waiting历史只称“已接纳候选”，不推算最终发布。使用真实当前Map快照核对输入版本，不合成把归档Run塞进snapshot.runs的假快照。RunReview、C10预览helper及会话控制逻辑保持原职责。

### C12 — 节点与运行来源记录

前置衔接：C05行为校正已确认手工意见/结论须有服务端明确的“人工创建”标记并展示。C12扩展来源导航时复用该合同，区分生成、人工、导入与来源未知；不能把缺少producer当作人工，也不能用人工编辑覆盖原生成来源。用户随后授权实施，实际结果见文末。

#### 目标与已经保存的信息

当前Inspector/NodeReader已用 `nodeReadOrigin()` 显示来源类别，但没有详细记录或来源运行入口；Operation中的复用关系和完整冻结规格也尚未作为明确的阅读区呈现。

后端已有 `producer`、`manualOrigin`、`importedFrom`，已有Operation的 `reusedFromOperationId/executionSpec`，C11也已经提供精确Operation目录和Run详情。C12先只改前端，补“这个节点怎么来的”“本次用了哪个历史结果”“当时冻结了什么配置”。不新增来源接口、存储字段、迁移或事件时间线。

#### 来源卡的最小内容

| 类型 | 第一版展示及入口 |
| --- | --- |
| 自动生成 | 显示保存的转换ID/版本、智能体名称/ID/版本、阶段、Work/Operation身份；通过“查看生成记录”定位原Operation。名称与版本取producer/冻结记录，不用当前Agent目录覆盖 |
| 人工创建 | 显示明确的创建用户标识和保存时间，保留原用户ID，不把它当作可查询的当前成员姓名；编辑不把生成来源改成人工来源 |
| 导入 | 显示bundleId、原nodeId、原revision；可展开包内保留的producer/manualOrigin。导入归类优先，不把包内Operation当成本地图记录，不提供猜测的原Map跳转或原包下载 |
| 来源未知 | 明确“未保存创建来源信息”，不猜人工、生成运行或创建人 |

沿用原分类优先级：导入→生成→人工→未知；不是四套互斥后端记录。导入确实会保留producer/manualOrigin，但同时重分节点/Map及部分Agent身份，并清空运行历史；包内Agent引用还可能被重映射，所以只能称“包内保留记录”，不能冒充原工作区的冻结配置。再次导入只知道最近一次保存的importedFrom，不承诺完整导入链。

仅新增一个 `NodeProvenance.vue`，放在当前Map的Inspector和NodeReader正文/元信息区，展示同一份已保存来源。组件无网络调用，只发带真实workspace/map/node身份及版本的只读导航意图。已有C06证据引用/脚注阅读保持，不复制进来源卡。

第一版不顺手扩展固定证据库单页的执行来源跳转：固定库单页实际位于EvidenceLibraryView/EvidenceEntryDetails，不是NodeReader。其来源身份与“定位当前来源”仍沿原功能；将来若加入相同卡或跨Map历史导航，必须使用entry.claim.origin/关系节点ref并独立读取真实源图，不能借当前活动Map。本批不增加这条额外读取链。

#### 生成来源怎样定位

1. Page从当前可见、已保存节点建立固定来源目标；导入记录不生成本地Operation导航目标。后续导航不以可编辑草稿或后来选中的节点替换原目标。
2. 复用C11的 `run.list({mapId,operationId,limit:25})` 和 `run.get`。历史状态增加可选精确operationId上下文，首次读取、续页和刷新均携原过滤；目标变更进入既有取消/代次键，不另建lookup缓存或请求系统。
3. 只有目录完整且唯一匹配时自动打开详情；0项显示“原运行记录不可用”，多个匹配保留列表供明确选择，不扫描未过滤的全部历史、不从workId推runId。详情必须包含精确Operation，才能定位到其 `data-operation-id` 区块。
4. 节点来源还核对保存的转换版本及产物映射：outputRefs含该节点/work，候选键、阶段、端口及类型与保存记录对应。匹配不上就提示记录不符，不把同名ID的内容认作已核实来源。当前节点revision与产出revision不同不阻止看原记录，但要并列提示版本差异。
5. 详情里的正文仍是发布时保存候选，当前节点正文不替代历史；当前节点已删除或旧输入正文没保存时，继续沿C10/C11的“不可用/错版本”说明。不会恢复未保存的任意旧正文。

历史面板接收来源目标后聚焦Operation，提供“返回全部运行”；普通“运行历史”按钮仍从无过滤目录打开。全部行为保持只读，不改变 `session.selectedRunId/selectedRunControl`、节点选择、正文草稿或原写命令重试。旧服务缺runHistory能力时只保留来源元数据及明确不可定位提示，不探测未知方法。

#### 复用来源与冻结配置

`runReuseOperation()` 创建新Operation但复制旧stages/outputRefs/review，记录直接 `reusedFromOperationId`；不重建节点、不改节点producer，来源Operation本身也可能是一次复用。因此：

- Operation明确显示“复用历史结果”和直接来源ID，提供“查看直接复用来源”。一次显式导航只处理一个已保存ID，不自动递归追完整来源树；来源记录若仍有复用标记，也不能把它说成新生成。
- 沿用的候选、产物、执行计划和审核记录明确标作历史复用；不能把复制的审核时间/决定说成“本次人工批准”，也不能将本次Run的建立时间当原产物生成时间。
- 精确查源Operation后核对其已完成、转换/规格及保存产物映射与复用记录相符。已有复用语义继续由后端保证，前端不重新做候选选择、输入等价或可执行性判断。
- 在OperationReview加一个“冻结执行规格”折叠区，先显示转换/阶段/智能体版本与specHash，完整 `executionSpec` 作为JSON再展开；动态槽位按保存计划和Run冻结Agent记录解释，不拿当前工作区设置替换。
- provider/model、允许工具、提示模板及输入绑定是保存的配置，候选/审核是已接纳记录；不据此声称实际Host、模型调用次数、工具实际使用、完整展开prompt或未保存的外部响应。只读查看，不增加配置编辑器。

来源定位、复用链接统一进入C11历史面板：当前RunReview中的Operation将意图向Page转发；历史面板中的Operation在自身只读上下文内定位下一条直接来源。无论从哪进入，都不领取控制权、重做批准、自动继续运行或清除原请求。
