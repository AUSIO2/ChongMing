# 077 — 通用数据实例与可注册定义协议

状态：通用数据、定义注册、有限转换执行、分支内容版本、编辑/Run 占有、控制租约、同图多 Run、通用 UI、v4 数据包和显式迁移已实现，更新于 2026-09-29。本稿细化 [077 总体设计](./077-分支独占与分布式协作.md)，文件落点见 [实施清单](./077-implement-分支独占与分布式协作.md)。样例检查只验证静态工件，生产能力另由自动化集成测试验证。

## 1. 本轮确定的边界

本地用户不管理客户端租约：branch proof 与业务版本检查保留，编辑/启动省略 lease，Run 控制/审核省略 control，运行占有仍保护在途输入。下文编辑租约和控制租约的领取、续租指协作模式。Host 的 Agent Work 授权由系统自动管理。

- 调度沿用自有 Work、RabbitMQ／本机通知和既有租约；底层 DSH 保留。Host 容量可配置，4 槽只是之前的示例。
- 数据类型和转换规则可以注册。核心不枚举 claim、verification，也不为每种业务新建一个类。
- 允许后继类型是类型规则；具体后继实例由实际关系表达；实际执行由用户选定的有限计划和就绪工作决定。
- 第一版支持单项生成、有限槽位并行、已封闭输入组的汇总和人工审核。类型定义不包含任意执行脚本、自动递归派发或无界循环。
- 继续使用 GraphNode、GraphOperation、GraphWork 等已有概念；文中“通用数据实例”就是新版 GraphNode，不再引入同义 DataNode 表或另一套 AgentTask 队列。

## 2. 通用实例：数据版本与定义版本分开

| 字段 | 约定 |
|---|---|
| id | 服务端管理的稳定节点 ID；现有图内 ID 在迁移中保留 |
| revision | 实例内容版本；新建沿用当前从 0 开始的约定，合法修改递增 |
| typeId | 所属工作区内的类型身份，例如 fact-checking.claim；是注册标识，不是封闭枚举 |
| typeVersion | 解释本实例的确切定义版本，正整数，从 1 开始 |
| payload | JSON 对象，按该 typeId/typeVersion 的 schema 验证 |
| createdAt、updatedAt | 保留现有时间字段，由服务端填写 |
| validity | current/stale；表示输入或依据是否仍有效，不代替审核或发布状态 |
| producer／importedFrom | 服务端投影的产出／导入来源；用户及模型不能通过 payload 自报授权 |

mapId、workspaceId 仍由图和访问上下文确定，不在 payload 中另存一份可信归属。数据实例不携带允许类型的可写副本，也不携带自身的运行租约。

普通编辑保持 typeId/typeVersion，按旧定义校验新 payload。发布新类型版本不会自动改旧节点。首版改变 typeId 或采用新定义版本，以显式转换创建新节点并保留来源；不提供暗中重解释历史 payload 的更新路径。后续若需要原 ID 升级，必须另行定义迁移及所有入出边兼容检查。

数据 revision 不等于完整历史快照存储。Operation 保存实际使用的、经过授权的输入投影及摘要，以支持执行审计；不凭一个旧 revision 承诺任意历史 payload 都可重建。

### 2.1 节点、分支与整图版本各自负责什么

- 节点 `revision` 在该实例内容合法修改时递增，供分支摘要和冻结输入使用。
- `branch.get(mapId, rootIds)` 沿实际 successor 关系计算合并闭包，返回 `GraphBranchSnapshot { scope, version, rootRevisions, mapRevision }`。`version` 绑定根集合、成员、节点版本及所有相邻关系的身份/版本；reference 不扩展闭包，但相邻 reference 会影响版本。`rootRevisions` 和 `mapRevision` 只用于客户端把结果与当前展示快照配对，并发裁决不比较它们。
- 人工 `graph.apply` 携带 `GraphBranchProof { rootIds, expectedVersion }`。真实分支未变化时，同图其他分支抢先写入只会触发服务端在最新文档上重放局部补丁；目标分支变化则返回 `BRANCH_VERSION_CONFLICT`。
- 完全独立的新根使用 `expectedVersion: null`，只允许本次新节点之间的关系；successor 子图必须无环，且所有新节点都要从声明根沿 successor 可达。它不是跳过版本检查的通用写入口。
- Map `revision` 继续作为数据库 CAS 和快照/SSE 排序序号，不是客户端编辑草稿的版本。`map.create` 使用 workspace revision，`map.delete` 仍使用图资源 revision。

上述内容版本规则与编辑租约共同生效。`branch.claim/renew/release` 按服务端计算的实际分支范围裁决，`ownershipRevision` 独立排序占有变化，人工写入同时校验 branch version 与 holder/fence。`run.control.claim/renew/release` 保护暂停、继续、取消和审核；不相交分支可以同时拥有独立 Run、控制权和 Agent Work。

## 3. 类型定义与精确引用

统一定义引用为 `{ id, version }`。类型、转换、发布包使用各自注册目录，版本从 1 开始；Agent 绑定的 version 对应既有配置 revision，允许沿用 0，并保存确切内容快照，不能仅保存名字后执行“最新配置”。节点上的 typeId/typeVersion 与类型引用一一对应。

| DataTypeDefinition 字段 | 约定 |
|---|---|
| id、version | 不可变身份；同一身份内容相同可复用，内容不同必须冲突 |
| title、description | 展示文案，属于业务定义；title 为类型名称，字段标签可另由 presentation 指定 |
| schema | 第 4 节限定的字段结构与约束 |
| successorTypes | 精确类型引用列表；空列表表示该版本没有允许的结构后继 |
| presentation | 标题/摘要字段、标签、顺序、枚举值文案等声明式显示信息 |
| references | 指明哪些字段是真实资产引用或节点引用，供访问校验、删除和导出导入使用 |
| agentProjection | 模型可读取的字段及受限过滤规则；缺省不自动把整个 payload 交给模型 |

精确许可有明确成本：父类型 v1 只允许子类型 v1 时，不会自动允许子类型 v2。使用新后继版本要发布相容的新定义并显式选择；不使用浮动 latest、通配未来版本或隐式版本范围。

定义包包含 packageId/version、dataTypes、transitions 及外部定义/Agent 依赖。所有同批引用先整体解析，再一次发布；允许引用同包稍后出现的定义，不能让数组顺序决定合法性。跨包依赖也必须指定精确版本。

定义目录按 workspace 隔离。相同逻辑定义可在不同工作区存在；跨工作区引用需要先导入验证，不能只凭同名 ID 读取另一工作区资源。

## 4. Schema 首版支持范围

采用 **JSON Schema draft-07 的明确子集**。这只是字段约束协议，不表示支持所有 schema 关键字。使用超出范围的关键字或形状时，发布失败，不能静默忽略约束。

| 支持项 | 用途 |
|---|---|
| object、properties、required | 定义对象字段和必填项 |
| additionalProperties:false 或子 schema | 禁止额外字段，或表达 news.context 这样的同构字典 |
| string、number、integer、boolean、null | 基础值；允许明确的 nullable 类型集合 |
| enum、const | 业务枚举、离散评分、联合结构的判别值 |
| array、items、minItems、maxItems、uniqueItems | 同构数组、数量和去重约束；不支持位置含义不同的元组 schema |
| minLength、maxLength、minimum、maximum | 基础字符串和数字边界 |
| 有限 oneOf | asset/url 等通过必填 kind 常量唯一识别的对象分支 |
| 本定义内 definitions 和 #/definitions/... 引用 | 复用有限非递归字段结构；不读取远程 schema |
| title、description、default | 展示/建表单提示；校验器不隐式写入 default，不进行类型强转或删除未知字段 |
| 明确支持的 format | date-time、uri、uuid；指定格式必须实际执行校验，不将注释当约束 |

禁止通用条件表达式、外部引用、递归 schema 和用户上传校验代码。schema 深度、字段数、字符串/数组规模、单次输出及包大小受服务端已声明的资源限制约束；不因 JSON 合法就接受无界输入。

定义发布时同时验证：schema 能编译、表单可以表达、Agent 输出 schema 能转换为当前 DSH 工具支持的参数结构。DSH 无法表达的硬约束仍须在服务端完整验证；若无法生成清楚且可执行的输出协议，则拒绝该定义，不能默认降级为另一种业务类型。

验证器的生产依赖须在实施时显式声明并固定版本，不依赖其他包恰好带入的依赖。随文校验脚本只借用当前仓库已有 Ajv 检查协议样例，不是生产校验器。

## 5. 引用、可见性与实际关系

### 5.1 真实引用

references 区分 asset 与 node，并声明字段路径、是否必填、目标类型限制及可展开的数组/字典层。路径只允许对象属性和显式集合成员选择，不提供任意查询表达式；具体元数据结构以随文 JSON 样例为基线。

- 资产引用必须仍属于当前可访问工作区且可用；读取 URL/Asset 的媒体、大小及地址限制沿用原有能力。
- 节点引用首版限定同图，保存目标 ID；参与输入时另外冻结 revision。删除被真实引用的节点/资产须拒绝，或在同一授权修改中解除引用；不能保留未声明的悬空引用。
- 历史 Agent ID、legacyReportId、旧 bundle 标识属于历史标签，不强制指向当前可执行实体，也不能因为看起来像 UUID 就在导入时重写。
- schema 内节点引用不自动建立结构后继。Operation 的结果引用、GraphEdge 和 payload 引用各自按已定义职责保存，禁止镜像出两份可独立修改的后继列表。

### 5.2 Agent 投影

schema 回答数据是否合格，agentProjection 回答模型可以看到哪些字段。初版投影支持字段白名单，以及集合成员内固定布尔字段的过滤，例如 context 的 visibleToAI；投影不执行任意代码。

投影前执行当前用户/Work 的数据与资产访问检查；投影不能扩大已有权限。私有 context 字段不得因 payload 通用化进入提示词、data_read 或诊断事件。执行摘要绑定投影规则及其版本；同一 Work 的投影不能随目录更新变化。

### 5.3 结构后继与完整输入依赖

GraphEdge 的核心结构角色统一为 successor/reference。successor 方向统一为上游→产物，参与实际分支遍历；reference 不扩大结构后继范围。业务名称可作为展示标签或来源元数据保留，不作为引擎 switch。新建或修改 successor 必须在最终事务中拒绝实例图自环及环路；reference 可以形成普通关系环，遍历时按节点身份去重。

转换的输出声明 successorOf，指定允许作为结构锚点的端口。普通情况下引用主输入端口；第 9.1 节的原子发布还可引用同批声明的输出端口。两类引用须可区分，输出端口间的依赖必须无环。默认使用这些端口的全部绑定实例；允许逐产物选择时，提案只能提交 data_read 发放的 sourceKeys，服务端映射并检查范围。模型不能填写任意父节点 ID，来源选择也不删除完整输入审计。

**全部读取依赖不等于全部结构锚点。** 核查读取事实和几篇新闻，意见可以只作为事实的后继；所有读取的新闻仍进入 inputRefs/依赖摘要及最终输入校验。否则一次上下文读取就会意外扩大分支占有。

N→M 的一次生成用 Operation 的完整 inputRefs、contextRefs、outputRefs、端口和 groupId 留痕。结构边只表达定义指定的关系，不默认把所有读取输入与所有输出连成完全图。对使用 input 端口全体作为锚点的转换，发布时展开相应真实边，并检查整个影响范围是否已获授权。

## 6. 转换、数量与输入齐备

| TransitionDefinition 项 | 约定 |
|---|---|
| id、version | 精确转换身份 |
| ports.input | 命名主输入端口、inputType 精确引用、count.min/max；用于业务基数统计 |
| ports.context | 命名只读上下文输入；记录依赖但不计主输入基数 |
| ports.output | 命名输出端口、outputType 精确引用、count.min/max 和 successorOf |
| cardinality | OneToOne / OneToMany / ManyToOne / ManyToMany |
| execution | 有限顺序阶段、执行方式、Agent 精确绑定及阶段结果形状 |
| review | 无需审核，或在确定的计划/产物边界批准或选择；保留明确的审核身份与版本 |

基数按一次 Operation 的封闭主输入组与最终发布输出计数，不按尝试次数、Agent 数量或中间候选数计算。多端口转换还要分别满足各端口的数量约束。

| 基数 | 输入 | 输出 |
|---|---|---|
| OneToOne | 恰好 1 | 恰好 1 |
| OneToMany | 恰好 1 | 声明的 min..max；min=0 才允许空输出 |
| ManyToOne | 声明的 min..max，min≥1 | 恰好 1 |
| ManyToMany | 声明的 min..max，min≥1 | 声明的 min..max；可明确允许零输出 |

枚举序列化值分别为 `1:1`、`1:N`、`N:1`、`N:M`。Many 一侧的声明上限须允许多个值，但不要求每次实际数量大于 1，也不要求 N 与 M 相等。例子的上限只是转换/样例配置，不是 Host 并发或架构固定上限。

execution.stages 使用有限命名阶段与 dependsOn，每个已实例化 Agent 阶段/槽位对应一份 Work；ready 首版只支持 all-dependencies。单项、并行、汇总是这个有限依赖结构的形状，不另存一份可能与依赖矛盾的模式字段。一个 Work 也可以输出多个候选。resultStage 指定最终产物发布阶段，非结果阶段的合法数据仍是候选。

stage 的 resultMode 指定 outputs 或 selection，outputPorts/count 约束本阶段候选；Operation 的总输出基数只在最终发布时检查，不能要求每个并行 Agent 各自产生整个组的数量。需要 Agent 路由选槽时，使用受限 plan 结果：只能绑定已声明的后续阶段模板及冻结的可选 Agent/工具；路由先校验、保存并按要求审核，然后封闭 expectedWorkIds 再派发。该路由合同沿用已有可信角色约束，不允许输出任意新步骤或代码。

每个运行中的输入组持久保存 groupId、有序 inputRefs/contextRefs、sealed；阶段保存 expectedWorkIds、已接纳结果、发布结果及封闭状态。不能因为已经返回若干份意见就提前汇总，也不能把 outputs:[] 理解为“还没完成”。

## 7. 有限 Run 计划与执行规格

用户选择起点、目标及要使用的转换；默认事实核查包可提供预设计划。Run 保存有限步骤及明确依赖，每步有 stepId、transitionRef、输入绑定、grouping、onEmpty 和运行规模限制。

- each：前序每项已发布输出分别组成一个输入组。
- all：等待指定前序的输出集合封闭，再形成一组。
- explicit：请求中明确输入分组；第一版不猜测多来源配对，也不隐式生成笛卡尔积。
- onEmpty：上游确已成功且没有输出时，按已声明规则 skip 或 fail；未完成、失败、审核拒绝不能当成合法空结果。

结构后继和允许类型都不会自行创建未选择的计划步骤。计划冻结后不会吸收图中后来随意新增的同类型节点；支持范围内的实例化组由已选步骤的成功输出决定，组数受运行限制。

Run 启动时先对完整 scope 根集合读取 `branch.get` 并领取编辑权，在 `run.start` 携带非空 GraphBranchProof 和租约；服务端比较成功后冻结精确定义闭包和 Agent/工具配置，把编辑权转换为持久 Run 范围占有，并原子授予启动窗口控制租约。图以 `runs[]` 保存多个 Run，每个 Run 持久保存自己的 `branchState`；data_read、提案和审核发布都按 runId 复核摘要。正式产物必须通过 successor 留在所属 scope，并在原子发布后推进该 Run 的范围与版本。

输入节点版本、依赖边及成员集合在接纳新结果时重新校验。定义被冻结不代表输入可以任意改变。其他无关分支或兄弟报告的写入只造成内部 CAS 重试，不使本 Work 自动过期；这与 run.start 的分支摘要屏障共同保护从选择到最终接纳的输入一致性。

Run 完成以所选步骤及其输入组全部收敛、无未决审核和未封闭生产者为准，不以队列暂时为空判断完成。首版不做循环执行、脚本化跳转或无限创建新组。

## 8. DSH 输入与产物提交

DSH 的模型/工具/会话执行机制保持不变。工作执行器向 DSH 传入授权、冻结 schema、输入投影、提示词变量映射及 Agent 配置；模型不能从目录自由选择另一份 schema 给自己授权。

data_read 返回当前 Work、specHash、命名 inputs/context、当前阶段有权读取的 priorStageResults、outputContract 和 promptVariables。业务型变量名由默认定义包映射，不在通用提示词模块中维护 claim/verify 的分支。

data_propose 的阶段允许形态包括：

- outputs：`[{key, port, typeRef, payload, sourceKeys?}]`，提交合法类型的产物或候选；sourceKeys 仅在合同允许时使用。
- selection：`[{workId, key}]`，选择已有候选，不能借选择操作改写正文或引用其他执行组的候选。
- plan：经可信阶段合同限定的槽位选择；仅供路由阶段，不能修改整个 Run 的步骤图。

具体采用哪一种由可信阶段定义决定。工作身份、图身份、输入锚点和目标节点 ID 不由模型指定。MJS 工具 schema 从相同的冻结合同生成；服务端再验证 schema、类型许可、数量、输入/依赖、候选引用、Run 状态、分支内容 proof、持久 Run 范围占有与 Work fence。

specHash 只用于绑定及核对，不替代 payload 校验。Agent 身份、授权工具和执行出处由服务器根据 grant 写入 producer/生成记录；payload 中的历史标签或模型自述不作为可信执行身份。外部资源首次读取仍形成稳定收据和保存的内容快照，重试不得把同一个 Work 偷换成新抓取的网页正文。

### 8.1 输入和提示词绑定

变量映射只使用受支持的声明式绑定，不能靠业务类型名称猜变量含义：

| 绑定来源 | 规则 |
|---|---|
| inputs/context 的已投影端口 | 按固定字段路径取值，以 text/json/text-lines 渲染；缺失必需字段报错，不能穿过投影读取私有字段 |
| 指定依赖阶段的已接纳结果 | 只读取当前阶段授权的候选/结果及其稳定引用，以结构化值交给模型 |
| 冻结的可选 Agent 目录 | 用于受限路由；不包含密钥，也不能引用目录之外的 Agent/工具 |
| source-text 输入解析能力 | 显式绑定端口中的 locator，由现有受限 URL/Asset reader 读取、保存正文和收据；普通 uri 字段不自动触发网络读取 |

默认包中的 rawContent、claimContent、opinions 等仅是变量名称与上述绑定的组合。模板替换一次完成，输入文本中的模板符号不再次执行。

阶段对输出字段的固定值或取值范围可以进一步收窄注册 schema，例如某个拆分 Agent 只产生指定类别；不得放宽类型 schema、引用权限或字段可见性。收窄后的输出合同同样进入冻结规格、DSH 工具参数和服务端最终校验。

## 9. 结果身份、候选与发布

| 事实 | 持久化含义 |
|---|---|
| Work 结果已接纳 | 该业务工作已有稳定收据，不再重复接受不同内容 |
| 候选已保存 | Operation 保存带稳定 key 的类型化候选；可供该 Run 后续受限阶段读取 |
| 审核已批准 | 对明确 reviewId/revision 作出决定；不是一次不可追溯的普通节点修改 |
| 正式数据已发布 | GraphNode 与真实关系原子入图，可以成为符合授权的其他计划输入 |
| 内容 stale | 依据发生变化；原结果保留，是否复用须重新判定 |

候选不占用正式图节点身份，不参与普通后继遍历。候选 key 在所属 Work 内唯一；最终输出键包含原 Work/key 或发布者明确的稳定 key，不能只使用每次重排后的数组位置。

正式 ID 由服务端稳定分配并与发布收据同次保存；并发重试读取同一收据中的映射，不能创建第二批节点。ID 不包含当前 holder/fence，换 Host 只换执行尝试身份。改变输入重新计算必须建立新业务代次，不复用旧成功 workId。

产物默认 create-only；人工修改已发布数据走 GraphBranchProof、实例版本和分支租约检查。Run 产物则核对持久 Run 范围占有与自身 Work 授权。接纳阶段结果、收据、正式节点/边、Operation 推进和通知标记一并提交。暂停/取消与接纳竞争依赖最终存储条件；已正式发布的结果保留，未批准候选不能因取消而自动发布。

### 9.1 原子发布候选依赖和最终产物

默认核查需要在终审批准时，将先前的候选意见和引用它们的结论一起发布。为此转换可显式声明 publication.includeReferencedCandidates；缺省为 false。开启时同时列出允许发布的候选阶段/端口，以及这些依赖在 ports.output 中的类型和数量约束。

最终产物中被 references 标注的节点引用字段，可以在提案阶段使用 `{ candidate: { workId, key } }` 形式的临时引用。它只允许指向当前 Operation 中已接纳且获授权的依赖候选；不是任意 JSON 模板替换。payload 里未被声明为节点引用的字段不解释这种对象。工具输出 schema 为这些字段生成受限提案形状；持久化 schema 仍要求解析后的正式节点引用。

审核针对固定的根产物、候选引用集合和它们的版本/摘要作出决定。批准后，服务端在一个提交中：

1. 计算已声明且被实际引用的候选依赖闭包，拒绝未接纳、跨组、重复冲突、成环或超过发布上限的依赖。
2. 为根产物及闭包中的每个候选分配稳定节点 ID，建立 `(workId,key) → nodeId` 映射；同一候选被多次引用只创建一次。
3. 回填声明的引用字段，按正式 schema、引用权限及后继许可复验；在新分配实例之间建立明确的 successor/reference 关系。
4. 将正式节点/边、完整 outputRefs、映射和收据、审核完成状态、后继推进及通知原子保存。

Operation 的输出基数计算**本次实际发布的全部唯一节点**，包括被提升的候选；各输出端口也分别计数。最终 Work 的直接提案数量与整个发布包数量分开校验，不能要求汇总 Agent 重写候选正文来满足数量。

例如保留旧核查终审语义的默认转换可声明“1 个事实 → N 个意见＋1 个结论”，基数为 1:N，意见端口的结构锚点为事实输入，结论端口的结构锚点为本批意见输出。两个意见都已接纳但未批准时仍是候选；批准结论时三者同时入图，拒绝或取消则不会自动发布意见。已经独立发布意见的另一种计划，也可通过普通正式节点引用形成结论。

这是一项有界的原子数据发布能力，不新增 Agent 执行或自动派发依赖。定义包验证、迁移和测试必须覆盖该发布方式；普通 selection 仍可只选择已有候选作为最终产物。

## 10. 注册 API、事务和缓存

第一版沿用公共 read/dispatch，不新增上传脚本入口，也不要求先做定义编辑器。

| 方法 | 输入和结果 | 权限 |
|---|---|---|
| definition.get | workspaceId；可选成对的 packageId/packageVersion。省略时返回目录 revision、定义到发布包的索引；指定时返回精确包、完整依赖及摘要 | Viewer 及以上 |
| definition.publish | requestId、workspaceId、expectedRevision、完整包；返回已发布包引用、摘要及新 workspace revision | Owner |

目录协调沿用 workspace revision，不额外新增一套目录锁。发布的定义记录可独立存储并建立 `(workspaceId, kind, id, version)` 唯一约束；定义写入、目录 CAS、权限 writeFence、收据及工作区刷新通知处于同一事务。

处理顺序：在授权事务内验证身份 → 检查请求收据 → 解析/验证整包及精确依赖 → 检查不可变版本冲突与 expectedRevision → 原子保存。相同 requestId/输入重放返回既有结果；同一个定义 ID/version 若内容不同，不能覆盖。已有完全相同包可返回已存在，不制造重复版本。

摘要按现有规范化对象键的方式计算，保留数组顺序；发布版本的语义与展示定义均不可原地改写。客户端按 workspace、精确引用和摘要缓存；目录刷新不替换旧节点/运行正在使用的版本。未注册/未知版本禁止写入与执行，不能猜成某个默认类型。

故障数据中出现未知类型时保留原记录并明确标识不可编辑/执行；经过用户访问鉴权的诊断读取不得自动把未知 payload 发给 Agent。发布、读取失败不得删除或自动重解释用户数据。

| 错误码 | HTTP | 适用情况 |
|---|---|---|
| DEFINITION_NOT_FOUND | 404 | 当前授权目录中不存在精确版本；不回落到 latest |
| DEFINITION_VERSION_CONFLICT | 409 | 同一已发布 ID/version 的内容发生变化 |
| DEFINITION_INVALID / SCHEMA_UNSUPPORTED | 422 | 定义引用/阶段/端口矛盾，或声明了不支持的 schema 能力 |
| PAYLOAD_INVALID / TRANSITION_NOT_ALLOWED | 422 | 实例内容不符 schema，或结构锚点未许可该输出类型版本 |
| OUTPUT_CARDINALITY / OUTPUT_REFERENCE_INVALID | 422 | 阶段/发布数量超出合同，或候选/实例引用非法 |
| REVISION_CONFLICT / INPUT_STALE / LEASE_LOST | 409 | 沿用现有代码，分别表示版本竞争、实际输入变化、执行或编辑授权失效 |

固定错误文案进入既有 RuntimeMessage。错误响应不泄露目录外的定义、私有字段或内部凭据；客户端按 code 区分重读、修订内容和重新领取，不能一律自动重试模型。

## 11. 默认包与迁移

| 现有内容 | 新表示与保全要求 |
|---|---|
| source / evidence | 对应注册类型；保留 locator、label/content/capturedAt 及资产/URL 访问限制 |
| news | 注册类型，保留 content 和动态 context 的 visibleToAI 语义 |
| claim | 注册类型，保留 content 和可空 category；类别约束移入定义 |
| GraphReport / verification.opinions | 同一意见的候选或正式 opinion 实例；保留原 slotId、routeRevision、Agent ID/历史名称、angle、tools、createdAt 等只读来源信息，按原身份映射，禁止按文本相似度合并 |
| verification | 保留节点 ID、内容版本、评分和理由；意见改为引用，不复制另一份可独立修改的正文 |
| GraphMergeDraft、解析草稿 | 保留未发布状态及原审核，不因迁移变成正式节点 |
| splitReports / selected | 保留候选集合及原 reportId/index 选择关系；建立稳定候选 key 映射，未选候选不发布 |
| 旧边 | 保留边 ID，显式映射方向/结构角色；普通引用不全部变为 successor |

同一 report 往往同时出现在 Operation 和结论的内嵌意见。扫描当前及历史 Run、全部结论，按 `(mapId, legacyReportId)` 建一次映射；同键内容和来源一致才归并，不一致就阻止该图迁移并报告。原 report ID 可能不是 UUID，新意见节点 ID 单独分配并记录映射；旧 Work/提案/收据身份不能被替换成新节点 ID。

已由历史结论引用的意见可迁为正式节点；仅存在于待审/未结束操作内的意见保持原候选可见范围。缺失正文、来源冲突或不能解释的历史选择不能凭空补齐。合法的“有结论、无原 Run”数据保留可显示的来源标签，不伪造活跃运行。

已有节点 typeVersion 映射到能无损解释原内容的默认/迁移定义。旧 Agent 配置和提示词不套用今天的默认配置。当前迁移会阻止仍为 running/waiting 的旧 Run 和有效租约；终态旧 Run 以完整 `legacyArchive` 保留身份和内容，不伪造可继续执行的通用 Operation。迁移安装足以解释历史节点的数据定义；要启动新工作流，Owner 还须显式发布包含 Agent 依赖的完整可执行定义包。

迁移先备份、dry-run，再显式 apply；Mongo 与 SQLite 共用转换计划，实际写入走各自事务/版本条件。保留普通业务身份和历史，新增协调/格式版本显式记录。生产读写遇到旧格式时提示迁移，不做双写或静默升级。

数据包发布为新格式 v4，携带节点引用定义的完整依赖闭包和摘要；不向旧 v3 偷塞新结构。导入先校验定义，再统一分配节点/资产身份，按声明重写真实引用，最后原子发布新工作区；不带入可执行 Run 或有效租约。v3 通过显式转换路径进入 v4 结构。

## 12. 完成标准

1. 注册全新、非事实核查的类型和转换，不改核心代码即可完成创建、编辑、Agent 执行、审核、显示和导出导入。
2. 默认包覆盖旧来源/证据/新闻/事实/意见/结论，以及空输出、拆分候选、人工审核与字段可见性。
3. 同一组 Work 在单 Host 多槽、多 Host 和本机 adapter 下遵守相同就绪、幂等、授权与发布规则。
4. 非法 payload、后继类型/版本、数量、跨组候选、资产引用或失效 Work 在最终接纳时被拒绝。
5. 定义升级不改变在途运行；旧结果不被新定义重解释；分支范围不因上下文读取意外扩大。
6. 类型样例与协议检查可以离线运行；数据库竞争、分支摘要、不相交重放、编辑/Run/控制租约、同图多 Run、MJS/DSH、UI、v4 数据包与 Mongo/SQLite 显式迁移均有自动化验收。
7. 候选意见与最终结论的终审发布原子完成，引用被正确回填；拒绝、取消和重复提交不会留下半个发布包或重复意见节点。

node develop-docs/077-校验数据定义.mjs
