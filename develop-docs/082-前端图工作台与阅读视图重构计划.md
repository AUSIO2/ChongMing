# 082 — 工作区三维 Map 与单页阅读重构计划

日期：2026-10-06。状态：第一阶段已开始实现，当前 Map 的 3D 预览已落地；全工作区跨 Map 与密图性能仍是后续目标。按用户补充修订：全工作区、跨 Map 的三维 Map 与单页阅读双视图，统一视觉配色。

## 1. 目标与范围

以当前 Vue 3、TypeScript、Pinia、Vite 工程为基础，重新组织前端模块。产品结构采用「三维 Map + 单页阅读」：Map 视图用 3D 展示整个工作区的证据网络，覆盖多个 Map；单页视图借鉴参考仓库的书页风格，阅读一个真实节点及其相关材料。

Workspace 是 Map 视图范围，现有 Map 是业务图、数据归属与编辑/运行上下文，用户界面中的「Map 视图」不等于只显示一张后端 Map。单 Map 夹具用于早期验证，正式产品目标仍为全工作区。

参考：[ChongMing-Frontend](https://github.com/mrsouth132-prog/ChongMing-Frontend)，本次审计基线为 `fab7b468abfd89cc883800aba8d9bee1c1a2afbb`。参考实现是原生 HTML、全局脚本和 Electron，不能按文件逐行翻译成 Vue。

保留参考中的纸张配色、字体、双栏阅读、引用展开、正文与条目联动、编辑草稿和键盘操作；重新实现全局状态、DOM 拼接、事件委托和演示调度。业务规则先区分当前后端已有能力与待补能力，再决定如何迁移。

当前客户端通信、图契约、分支版本、多 Run 和协作控制继续复用。全工作区查询与跨图引用目前尚未提供，需要在设计阶段明确契约，最终接口阶段实现和对接。现有工作台在逐模块开发期间保持可用，新增组件先用隔离夹具验收；本次只修订文档，不修改后端协议、数据库或已有未提交实现。

## 2. 图与阅读视图如何对应

| 对象 | 界面表达 |
| --- | --- |
| Workspace | 整个证据网络的浏览范围、权限及配置归属 |
| Map | Map 视图中节点的业务图归属；数据编辑和 Run 仍进入所属 Map |
| Node | Map 视图上的真实节点；进入对应节点的单页阅读 |
| successor | 结构后继，用于分支导航；编辑与运行范围仍由服务端裁决 |
| reference / payloadReferences | 引用与证据导航，不扩展结构后继闭包 |
| Run / Operation / Stage | 独立运行、阶段进度、候选产物及审核 |

阅读视图以一个真实节点为入口，按其类型展示正文或结构化内容，并展示相关节点。多个来源、多篇正文、多个核查意见和共享证据均保留真实身份与关联。两个视图共用 Workspace/Map/Node 身份；跨图身份和引用版本策略在新增契约中明确，不用渲染数组下标代替。

事实核查书页属于特定业务展示；其他类型由精确类型定义提供通用详情。意见、证据和结论依据实际关系及产物来源关联，不把最新 Run 的结果套到任意事实，也不把多个意见压成一个没有来源的结果。

证据模型跟随 [083 设计](./083-移除独立Evidence类型.md)：证据是 Claim 在核查中承担的角色，新版 Opinion 通过 `evidenceClaimIds` 引用 Claim。Map 视图不新增独立 Evidence 节点类型；历史 v1 数据按自身精确定义展示。083 当前仍在实施，阅读新版本时以实际发布定义为准。

### 两种视图与切换

“星图与单星”只类比整体网络和单个节点之间的关系。两个视图统一视觉颜色，以三维网络和书页排版区分展示方式。

| 视图 | 视觉与操作 |
| --- | --- |
| Map 视图 | 使用与单页相同的暖白背景、正文色、强调色和状态色，通过三维节点、轻量连线、空间层次和聚焦突出整体关系；支持旋转、缩放、平移、搜索。节点簇代表展示聚合，不改变业务结构。 |
| 单页视图 | 使用同一套背景、文字、强调色和状态色，采用书页排版、衬线正文、内容与关联材料双栏；来源、相关陈述、核查意见和引用可逐条阅读。 |

顶部提供明确的「Map 视图 / 单页」切换。Map 视图点击节点先聚焦并高亮邻接关系，通过「打开单页」、双击或键盘操作进入阅读。未选中节点时单页入口提示选择节点。返回 Map 视图恢复相机、筛选和选择；沿引用打开另一节点时记录阅读路径，并可返回其 Map 视图位置。

切换可以使用简短的聚焦或内容过渡，保留当前节点的视觉定位；背景和配色保持一致。转场有固定结束时点，不等待整个布局重新收敛；减弱动画时直接切换，内容与操作仍完整。

两个视图共用一套颜色、字体、控件、选中态和状态含义，通过空间布局、排版及信息密度区分整体与局部。三维深度、节点聚焦、连线层次和适度交互效果负责增强表现力；全网连线不持续闪动。节点大小可反映受限的连接数量，不能暗示可信度；没有正式置信度字段时不生成概率或可靠性光效。

### 大量连线的展示原则

- 全库总览采用缩放分级：远处展示节点簇与主要连接，放大后展开真实节点和更细关系。聚合节点簇不是可编辑、可运行的业务节点。
- 普通关系使用低强调的细线；选中节点后突出一跳邻域，允许逐步扩展或筛选关系种类。箭头、文字和粒子优先用于聚焦关系，避免满屏重叠标签。
- `successor` 与引用关系保留不同语义和图例。引用网络可能有环，不能将整个证据网络强制按执行 DAG 排版；编辑、租约和 Run 范围仍由真实 successor 决定。
- 图上的近邻或节点簇来自结构布局或已注册分类，不自动表示语义相似、独立证据或可信群体。重复来源和循环引用的业务判定归后端规则。
- 清楚区分全库总数、已加载数量和当前显示数量；过滤、聚合、未加载的关系均可辨认，局部视图不能冒充完整证据链。
- 单页中的来源与引用列表保留明确导航；Map 视图提供可键盘访问的节点列表入口，减少动画选项与 WebGL 不可用时仍能进入单页。

## 3. 模块与职责

下列是目标职责边界。文件名在各阶段按实际组件需要确定，不先批量搬移文件。

当前不单独建立 Mapper 层，也不将其作为重构前置任务。先复用现有客户端、`graph-layout.ts` 和 `data-payload.ts`，转换逻辑留在实际使用它的功能模块；待三维 Map 和单页出现明确共享需求或转换复杂度后，再提取必要的函数与索引。下表描述职责，不要求每项都建立独立层。

| 模块 | 位置与主要组件 | 职责与状态归属 |
| --- | --- | --- |
| 主题与通用控件 | `apps/ui/style.css`、`components/ui` | 两个视图共用一套视觉设计值：背景、文字、强调色、状态色、字体和控件；参考 CSS 的多层覆盖整理为统一设计值，三维材质使用相同语义色。 |
| 页面外壳与视图导航 | `views/WorkspacePage.vue`、`components/shell` | 装配工作区导航、Map 视图/单页切换、节点阅读路径与图定位；拥有当前模式、面板尺寸、对话框开合及往返恢复信息。 |
| 图数据读取与转换 | 现有 `features/graph`，后续按实际复用提取 | 保留稳定身份和真实关系语义，复用已有内容读取逻辑；轻量渲染数据、索引和增量转换在相关功能实现时建立。现阶段不新增独立 Mapper，二维坐标算法不作为 3D 布局。 |
| 三维布局 | `features/map` 中的布局模块 | 维护三维坐标、布局迭代、固定位置和结构聚类；按拓扑差异更新，评估 Worker 或预计算。坐标和模拟速度只属展示状态，不写回业务节点。 |
| 三维 Map 渲染 | `features/map` 中的 `MapView.vue` 与渲染模块 | 管理 WebGL 场景、相机、点线、命中检测、焦点光效和资源释放；接收轻量投影，发送节点选择/打开意图，不读取数据库或控制 Run。 |
| 图探索与显示范围 | `features/map` 中的探索模块 | 管理搜索、关系筛选、邻域展开、聚合级别及可见数量；查询条件交给会话，真实邻接和权限由服务端提供。 |
| 类型内容查看与编辑 | `features/data` | 按精确类型显示 payload、生成编辑表单、维护草稿与版本冲突提示。现有 `NodeInspector.vue`、`DataPayloadEditor.vue`、`data-payload.ts` 随实际改写从 graph 归入此模块。保存意图交给会话。 |
| 单页阅读 | `features/reader` | 选中节点的正文/结构化内容、书页双栏、关联条目、引用展开和阅读位置；读取同一图投影，不维护另一套项目和结果。 |
| 事实核查展示 | `features/fact-checking` | 集中处理精确类型识别、Claim 及其证据角色、意见/结论标签与材料展示；通用 graph、reader、session 不散落业务名称判断。 |
| 运行与执行审核 | `features/run` | 运行范围表单、Run 选择、Operation/Stage 进度、候选产物、暂停/继续/取消及执行审核；复用 `RunReview.vue`、`OperationReview.vue`。运行状态由后端拥有。 |
| 工作区与配置管理 | `features/management` 及现有 workspace/agents/assets/settings | 保留成员、Agent、资产、设置与 v4 数据交换能力。管理表单拥有各自草稿；逐步统一外观。类型目录继续供内容模块读取，类型发布界面是否新增另定。 |
| 会话与通信 | `state`、`transport/client-gateway.ts`、`client/graph-client.ts` | 唯一远端状态来源。工作区浏览负责摘要、邻域、取消与缓存；现有 client-session 负责所属 Map 的详情、编辑、执行、租约和重试。按真实生命周期拆分所有者，不把多个可写图快照复制进浏览状态。 |

依赖方向：页面装配各 feature；Map、探索及单页读取同一份授权数据，渲染依赖布局结果；feature 使用公共契约和已有读取函数，通过 props/emits 表达用户意图；页面调用会话，会话使用 gateway。实际共享转换按需提取，fact-checking 可以使用通用 data/reader 能力，通用模块不反向依赖事实核查展示。

只提取实际复用的投影函数，不建立所有组件都必须经过的通用中间层。

## 4. 状态与操作边界

- **服务端事实**：节点、边、版本、Run、Operation、审核与权限，由会话接纳授权摘要、详情、增量及现有 Map 快照。进度和结果通过 computed 派生，不另存 `checked/result/running/parsePercent`。
- **页面状态**：Map 视图/单页模式、相机、布局坐标、筛选、聚合、引用展开和阅读路径，归所属模块。聚焦身份包含所属工作区/Map/Node，不使用数组下标。
- **编辑草稿**：归 data 或具体表单；标明所属 Workspace/Map、nodeId 和版本基线，避免跨图切换后存到错误位置。服务器更新不会无提示覆盖尚未保存的内容，冲突恢复和保存失败保持可理解。
- **用户偏好**：现有图标签、节点选择继续使用后端 Preferences；阅读布局等新偏好的持久化归属单独确定，不把业务图复制到 localStorage。
- **异步资源**：真实请求和订阅由 session/gateway 管理；组件管理自有监听、ResizeObserver 和显示效果，卸载时清理。切图、关闭阅读或断线不取消后端运行。

三维库使用独立轻量对象；其可能改写的 `source/target/x/y/z/vx/vy/vz` 不得进入 GraphSnapshot 或 payload。拓扑不变的租约、审核和活动更新不重建整个布局；节点内容更新保留已有坐标。单页显示时暂停隐藏场景的迭代/绘制，退出工作区释放布局任务、图形缓冲和监听。

主要交互约定：Map 视图节点选择发送包含 Workspace/Map/Node 的稳定身份；阅读视图切换只改变显示状态；数据保存指向所属 Map，传递精确类型、payload 和版本基线；运行启动传递明确 scope/plan/mode；审核指定 Run 和 Operation 对应的审核身份。版本与控制权检查沿用已有会话和服务端规则。

## 5. 需要另外设计的能力

这些差异在开发相应模块前明确，不能由前端模拟成后端已有能力；必要的契约扩展另立设计。

| 能力 | 当前差异与处理原则 |
| --- | --- |
| 工作区证据库总览 | 当前 `map.get` 与 SSE 是单 Map 完整快照，没有全工作区 Map 视图查询。需要摘要、邻域/分页、详情、统计和增量同步能力，所有结果在服务端授权；不通过一次性拉取所有 Map 构造已完成的全库接口。 |
| 跨 Map 身份与引用 | 当前边与 payload 引用只在所属 Map 内校验；跨图引用需明确节点身份、目标版本、删除/更新影响及权限。前端不擅自按相同正文合并节点或制造关系。 |
| 原文标注与定位 | 当前事实类型没有 `anchorStart/anchorEnd`。先支持真实关系导航；可靠锚点需单独定义，不能凭文本猜测制造准确位置。 |
| 已看记录 | 独立于机器结果和审核。展示状态与持久化范围另定，不能通过审核字段替代。 |
| 人工认可/需要复查 | 参考的 `agree/recheck/note` 是意见复核；当前 `approve/reject` 是执行计划或产物发布审核。保留不同名称和操作语义。 |
| 项目文件夹 | 当前 Workspace/Map 契约不等于参考的本地 folders；目录组织能力另定，导航先沿用现有层级。 |
| 人工引用材料 | 参考的全文适用/按陈述适用与后端证据节点引用不同，需明确材料类型及关联后再提供编辑操作。 |
| 数据交换 | 当前继续使用 v4 图/工作区包；参考 v1 项目 JSON 不直接复用。 |
| 一键完整核查 | 当前 UI 创建单步骤计划；完整解析、拆分、核查流水线需明确有限计划和审核边界，前端不自行编排 Agent Work。 |

## 6. 容量估计与技术验证

用户要求至少覆盖 Sandbox 实验规模。以下容量为工程估计和验收目标，不是当前已生成数据量。估算依据及计算随 Sandbox 预算变化更新。

### Sandbox 推算

[研究草案](https://github.com/AUSIO2/ChongMing-News-Experiments/blob/main/docs/benchmark/Sandbox研究问题草案.md) 的预算示例为 24 个本底、216 篇全文，其中 108 篇控制稿和 108 篇正式稿；每篇约 8–20 个 Claim，每个 Claim 1–3 条核查意见。[四种算法计划](https://github.com/AUSIO2/ChongMing-News-Experiments/blob/main/docs/benchmark/Sandbox四种算法实验计划.md) 另给出约 100–300 篇全文的扩展预算。数值训练查询和重复回放不直接算作新增独立图节点。

保守按全部 216 篇都拆分、每篇一个 Source、每个 Claim 一份汇总结论估算：

- Claim 数 C = 216 × 8–20，即 1,728–4,320。
- Opinion 数 O = C × 1–3，即 1,728–12,960。
- 核心节点 N = 2 × 216 + 2C + O，即约 5,600–22,000；再加资料库中的唯一陈述与出处节点。证据引用复用 Claim，不为每条引用再复制证据节点。
- 连线 E ≈ 216 + C + (3 + b)O；包含来源/正文、事实/意见、意见/结论、结论/意见引用及意见/证据引用。b 暂按每条意见引用 2–5 个陈述的工程假设，Sandbox 尚未规定其均值；约为 11,000–108,000，另加资料库出处关系。同一对节点不同关系是否视觉合并，另计显示边数。

正式稿只有 108 篇时，基础节点估计约 2,800–11,000；扩展到 100–300 篇时约 2,600–30,600，均尚未加入额外资料库与历史版本。以这些预算为依据，容量阶梯设为：

| 场景 | 节点 / 关系存量 | 用途 |
| --- | --- | --- |
| 交互样本 | 1,000 / 10,000 | 双视图、命中、选择与往返验收 |
| 常见实验 | 10,000 / 50,000 | 正式稿的常见规模与布局更新 |
| 首版主目标 | 50,000 / 200,000 | 覆盖 Sandbox 材料扩展预算，预留资料库和有限历史 |
| 扩展压力 | 100,000 / 500,000 | 高引用密度、多图和更多历史的压力验证 |

这些数字是规划余量，不是实测吞吐或已有证据库条数；全类型图节点数也不等于作为证据使用的唯一 Claim 数。多个实验版本与历史产物是否节点化另算，不能把四种算法、训练次数和重放次数直接乘成新的独立事实。算法回放共享冻结材料，数值训练查询不自动产生材料节点。

全库存量不等于一帧同时显示的精细对象。总览使用轻量摘要、点线或聚合；单节点探索按受控邻域加载。分别记录全库数量、已加载工作集和实际绘制数量，不以只画少量节点的帧率声称全量渲染通过。

### 技术候选与验证边界

- 渲染使用 WebGL/Three.js 方向。可用 [3d-force-graph 官方项目](https://github.com/vasturiano/3d-force-graph) 验证三维布局、聚焦、连线筛选与相机操作；是否作为生产渲染器，先由密图样本实测决定。
- 大量点线优先评估共享/批量几何和实例绘制，避免每个节点、标签、粗线都建立独立复杂对象。[Three.js InstancedMesh 源码说明](https://github.com/mrdoob/three.js/blob/dev/src/objects/InstancedMesh.js)提供实例绘制能力，具体吞吐仍需本机测试。
- 布局计算与绘制分开评估，必要时放入 Worker 或采用可复用坐标；候选库不默认具备后台计算能力。增量数据保持旧布局，不因实时状态变化让 Map 视图整体重新漂移。
- 性能验收同时记录加载/JSON 解析、布局收敛、GPU/内存、节点命中、视图切换和帧率。测试机器、实际绘制对象量及开关光效必须留记录；先以操作时约 30 FPS 为目标，再根据实测限定细节和工作集。
- 现有公共客户端限制整个 HTTP JSON 响应和单个 SSE 帧各不超过 16 MiB，见 `client/graph-client.ts`；完整图还包含 Run 与冻结定义。WebGL 不解决数据传输与解析，全库浏览需轻量摘要、按需详情和增量同步，不直接抬高上限代替设计。

## 7. 分阶段迁移

| 阶段 | 改写范围 | 阶段完成标准 |
| --- | --- | --- |
| A：双视图外壳与基础交互 | 最少身份/导航约定、统一主题、工作区导航、Map/单页切换、基础节点阅读与加载/空/错误状态 | 两个视图颜色与控件一致，选择同一节点，往返保留视口与阅读位置；形成第一块可操作界面 |
| B：三维 Map 与性能原型 | 按渲染需求建立轻量数据与必要索引，实现三维布局、点线渲染、聚焦、密图筛选及容量样本 | 5 万/20 万存量样本有工作集与性能记录；真实关系语义不变，模拟状态不污染快照；共享转换按实际复用提取 |
| C：单页阅读与事实核查展示 | 完整书页正文、Claim/证据角色、意见/结论、引用展开和关系导航 | Map 视图与单页定位同一真实节点，完整表达相关材料及非事实类型 |
| D：数据编辑与配置管理 | 类型编辑、草稿与冲突提示；工作区/Agent/资产/设置及数据交换界面统一 | 不丢未保存草稿，既有配置、权限与交换功能保留 |
| E：运行与执行审核 | Run/Operation/Stage 进度、范围选择、暂停/继续/取消、执行审核 | 多 Run 可分别查看与控制；意见复核若纳入首版，与执行审核分开表达 |
| F：全工作区接口与主页面对接 | 实现已设计的库摘要/邻域/详情/同步接口；新视图接会话，编辑/执行进入所属 Map | 授权范围、跨图版本、分页与增量同步通过；HTTP/IPC/SSE 和现有 Run 规则联调通过 |

每阶段先形成可独立验收的一块能力，再进入下一阶段。A–E 使用现有精确类型/Map 夹具，新增库能力的样例与契约随相关功能明确，区分已实现与待实现关系。全库接口及证据库边界与 [084 计划](./084-workspace证据库实现计划.md) 协调，不要求先设计完整跨图库接口才能开始界面。F 对接新增全库能力和视图，现有 Map 通信与执行规则持续保留。

### 当前第一阶段的具体交付

文件、函数、状态和测试级细化见 [087 第一阶段完整实施计划](./087-前端第一阶段完整实施计划.md)，该计划尚未开始编码。

目标是可看、可操作的双视图基础界面；本次只细化交付，尚未开始实施。

1. **统一视觉**：暖白背景、字体体系、强调色、状态色、按钮和选中态；外壳与两个视图使用同一套设计值。
2. **外壳与导航**：顶栏、现有工作区/Map 导航、内容区和明确的「Map / 单页」切换；保留现有管理与运行入口。
3. **基础单页**：显示选中节点的标题、精确类型、正文或通用 payload 以及基础关联材料，不要求本阶段完成全部事实核查专用组件。
4. **选择与往返**：使用 `{ workspaceId, mapId, nodeId }`；点击选择，明确打开入口进入单页，返回后保持选择和画布位置，重回同页保持阅读位置。
5. **完整界面状态**：加载、空 Map、未选节点、节点消失和读取错误都有清楚提示及返回入口；鼠标、键盘和减弱动画模式都可完成往返。

第一阶段起初沿用现有画布验证选择和导航；在用户查看预览后，已补入当前 Map 的 Three.js 场景。大图聚合与性能验证仍在 B。使用现有 `GraphSnapshot + catalog` 类型夹具，不新建 Mapper、不重写后端，不将夹具中的多 Map 导航当作生产跨图引用。远端状态保持唯一来源，相机/阅读位置只属于视图状态。

验收重点：同一节点在两视图的身份、类型与内容一致；多 Map 不串内容或草稿；返回后视口与选中状态保留；1440×900、1024×700、900×620 下内容内部滚动、键盘可达。第一阶段不恢复旧 Timeline，也不把 Operation 画成业务数据节点。
