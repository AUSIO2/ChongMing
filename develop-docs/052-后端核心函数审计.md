## 8. 最小目标函数与类型边界

以下是待实现的项目函数签名，不是 DSH 官方 SDK 的同名 API。GraphCommand/Node/Edge/Proposal/Review 等数据联合在 contracts 定义；GraphDocument/OperationLease 是后端类型；DSH 类型仅出现在 dsh.ts。内部 store CAS helper 不对网络/模型暴露。

### 8.1 固定身份

    type OperationKind = 'parse' | 'split' | 'verify'
    type InputRef = { nodeId: string; revision: number }
    type OperationLease = Readonly<{
      mapId: string; runId: string; operationId: string
      ownerHostId: string; holderId: string; fence: number
      leaseUntil: string; sessionId: string
    }>
    type ExecutionScope = Readonly<{
      lease: OperationLease
      producer: 'root' | 'worker'
      slotId?: string
    }>

OperationLease 是一次领取的不可变能力；所有异步 tool 闭包捕获原 fence。ownerHostId 用于路由，holderId 用于区分进程，fence 是写授权代数。operationId 不包含 Host/fence；sessionId 包含该执行代数并只在后端可见。data.read 实际暴露的数据版本由 Host 记录到共享 operation 的读集，后续写入验证该读集；模型不能自报一个缩水输入列表。

### 8.2 graph.ts：唯一业务数据写路径

| 目标签名 | 调用者与具体职责 |
|---|---|
| graphRead(actor, query: GraphQuery): Promise<GraphReadResult> | API/CLI；校验工作区访问，返回 list/snapshot/node，读取不启动恢复。 |
| graphEdit(actor, envelope: GraphMutation): Promise<GraphSnapshot> | API；map/node/edge CRUD、显式事实合并、可编辑策略；校验 expectedRevision、active Run 限制及资产引用，调用纯规则生成字段变化再 CAS。 |
| graphReadData(scope: ExecutionScope, query: DataRead): Promise<DataReadResult> | DSH data.read；检查共享有效 lease、访问范围和 producer 权限；只暴露 AI 可见上下文，持久登记实际读集。 |
| graphPropose(scope: ExecutionScope, proposal: DataProposal): Promise<ProposalResult> | DSH data.propose；有限 route/report/verification/accept 提案；验证身份、schema、输入/策略/草稿版本。自动接受和人工接受汇入同一最终提交分支。 |
| graphProject(document: GraphDocument): GraphSnapshot | graphRead、API 流；纯投影正式图、目标、多个 Review、过期/能力；不覆盖正式节点为草稿、不查 DSH。 |

graphPropose 内部固定顺序：按已定 proposal/commitKey 查收据→检查执行围栏和输入版本→检查必要决定→以当前 map revision 和同一有效 lease 条件提交字段变化。返回冲突时只重新读当前图并校验已有候选，不能重新调用模型。最终接受必须同次写 Node/Edge/Receipt、operation.completed、合法后继 ready 项和 revision。

### 8.3 rules.ts：固定业务规则，纯函数

| 目标签名 | 职责 |
|---|---|
| rulesReadWork(graph: GraphDocument, run: RunRecord): WorkSpec[] | 查询 scope/until 尚缺的 parse/split/verify，按输入版本/收据判完成；独立 News/Claim 合法；不发起模型、不安排 worker。 |
| rulesValidateProposal(graph, operation, proposal, policy): ValidatedProposal | 校验报告/结果 schema、允许端点与边方向、来源/证据、producer/slot、最大数据量及人工决定要求；结构错误与合法空结果区分。 |
| rulesInvalidate(graph, edit: ValidatedGraphEdit): GraphChanges | 根据实际读集/输入版本标记旧结果过期、更新来源位置有效性；不按所有图边可达性连坐。 |
| rulesCheckGoal(graph: GraphDocument, run: RunRecord): GoalCheck | 检查完整 scope 是否达到 until，返回 completed/remaining/user-declined；不能只数已登记 operation。 |
| rulesOperationId(runId, kind: OperationKind, targetId): string | 标准库稳定 hash；同 Run 同变换同 target 唯一，Host/fence 不参与。 |
| rulesCommitKey(operation, proposalVersion, inputFingerprint, policyVersion): string | Host 生成业务幂等身份，包含实际输入/关系/上下文读取范围与批准路由版本；同 key 不同 payload 报冲突。 |

只有三个 operation 规则可分支；不建可编程工作流引擎。Input 指纹的数据库验证和权限仍由 graph/store 写路径执行，纯函数不能证明租约仍有效。

### 8.4 run.ts：用户目标、Review、共享终态

| 目标签名 | 调用者与职责 |
|---|---|
| runStart(actor, mutation: RunStartMutation): Promise<GraphSnapshot> | API；requestId 幂等、expectedRevision、一个活跃 Run、scope/until/mode、冻结配置；登记初始业务项立即返回。 |
| runReconcile(mapId: string): Promise<void> | Host 启动、退避轮询、接受结果后；纯规则发现缺项，稳定 ID 幂等补 ready；尝试终态；不常驻驱动 Agent。 |
| runSetMode(actor, mutation: RunSetModeMutation): Promise<GraphSnapshot> | API；改变未终结目标的后续决策策略，保留已拒绝/已失效决定语义。 |
| reviewEdit(actor, mutation: ReviewEditMutation): Promise<GraphSnapshot> | API；匹配 reviewId/draftRevision/expectedRevision 后修改草稿，提升草稿版本、使旧 validate/save 决定失效。 |
| reviewAnswer(actor, mutation: ReviewAnswerMutation): Promise<GraphSnapshot> | API 任意 Host；身份+版本竞争，持久 accept/revise/reject 决定，适用时 operation waiting→ready；不要求 Agent lease。 |
| runCancel(actor, mutation: RunCancelMutation): Promise<GraphSnapshot> | API；先原子终结共享 Run，再通知 owners 停 DSH；保留既有结果。 |
| runFail(lease: OperationLease, error: BusinessError): Promise<void> | 有效执行者；同次有效 lease CAS 标记 operation.failed/Run.failed；旧持有者失租不能报死新执行者。 |
| runRetry(actor, mutation: RunRetryMutation): Promise<GraphSnapshot> | API；新建新 Run，不复活终态；只复用仍符合当前输入/配置的报告和收据。 |

不另建 runContinue 状态游标。进入人工等待通过 graphPropose 同次保存 Review、operation.waiting 和释放执行租约，再停驻本机 DSH；用户回答与执行者续租是两个独立授权域。

### 8.5 claim.ts：仅 operation 领取，不调度智能体

| 目标签名 | 职责 |
|---|---|
| claimAcquire(candidate: WorkAddress, host: HostIdentity, ttlMs: number): Promise<OperationLease \| null> | Mongo 单次条件更新：Run active、ready 或过期 executing、本机兼容能力、未终结；用数据库时间写 owner/holder/leaseUntil、fence+1 和该代 sessionId。争抢失败返回 null。 |
| claimRenew(lease: OperationLease, ttlMs: number): Promise<OperationLease \| null> | owner/holder/fence/status/run 匹配且租约仍有效，数据库时间延长；不提升业务 revision，不可复活过期旧 lease。返回新到期值但身份不变。 |
| claimRelease(lease: OperationLease, reason: 'shutdown' \| 'yield'): Promise<void> | 只释放仍属于自己的 executing 项为 ready；先关闭本机 DSH admission/副作用，不能把新持有者或 waiting/completed 改回 ready。正常退出也可保留到期接管策略，必须统一。 |
| claimLoop(host: HostIdentity, signal: AbortSignal): Promise<void> | 先查本机容量与能力，再选 ready 项/调用 claimAcquire，成功后 dshStartOperation；续租、失租停本机工作、有退避轮询；只跟踪本进程已占用 operation，不存 worker attempt/队列。 |

claimLoop 不是唯一中心服务；每个 Host 均可运行。网络失联时在保守本地截止前停派生和计算，所有接受仍由数据库有效期裁决，不能根据本机时钟直接承认业务成功。

### 8.6 dsh.ts：每次领取一个本地 root

| 目标签名 | 职责 |
|---|---|
| dshOpen(config: HostRuntimeConfig): Promise<DshRuntime> | 一次装配 DSH 官方 services/provider/persistence/checkpoint/subagent，与本机 secret 解析；不假定 SQLite。 |
| dshStartOperation(lease: OperationLease, input: OperationInput): Promise<void> | 读取共享报告/路由/决定，创建或恢复该代本地根 Session；绑定 data.read/propose；委派/并行/merge/重试交 DSH；同一 binding 防重复驻留。 |
| dshStopOperation(lease: OperationLease, reason: StopReason): Promise<void> | 仅停止精确 operation/fence 的本机树；用公开 drainContinuableDescendants，再释放 root，不能误停新代。 |
| dshProjectActivity(binding: LocalBinding, event: DshObservedEvent): Activity \| null | 过滤/脱敏 DSH 事件并携带 operationId/fence/序号；没有 SessionId 的前端业务 DTO。 |
| dshClose(runtime: DshRuntime): Promise<void> | 关闭 admission、drain 所有本机树、关键 flush、dispose；报告失败，不把 shutdown 转用户取消。 |

dshStartOperation 不以 root.whenIdle 作为 operation 完成：必须有 graphPropose 的共享接受收据。continuable child 通过报告工具显式交数据，根 Agent 读取后汇总。新的 Host 接管 fence 时创建自己的 Session，复用共享业务报告；不要求搬迁另一个 Host 的 DSH 日志。

### 8.7 store.ts：Mongo 约束与短写

| 目标签名 | 职责 |
|---|---|
| storeOpen(config: StoreConfig): Promise<void> | 显式连接共享库、验证部署要求，生产禁静默 memory fallback。 |
| storeReadGraph(mapId: string): Promise<GraphDocument \| null> | primary/所需 read concern 下取得字段一致聚合；读取不修复、不启动运行。 |
| storeListGraphs(workspaceId: string, page: PageQuery): Promise<GraphPage> | Workspace 范围列表，稳定分页及摘要；不把全部 Graph 载入进程。 |
| storeCommit(write: GraphWrite): Promise<WriteOutcome> | 私有类型承载明确 filter/字段变化；原子写 expectedRevision，以及适用的 run/operation/holder/fence/leaseUntil>数据库时间条件。不能允许模型或网络传原始 Mongo modifier。 |
| storeWatch(listener: (mapId: string) => void, signal: AbortSignal): Promise<void> | Change Streams 提示 API 重读业务快照；游标失效重新基线；通知非正确性根基。 |
| storeClose(): Promise<void> | 关闭 change stream、Mongo 连接；仅在 claim/DSH 已停止后。 |

storeCommit 对用户 edit、Review、执行者 proposal、领取/续租使用不同的有限 guard 类型，避免把“存在 lease”泛化为所有写路径的必要条件。续租是不增业务 revision 的专门更新；图的业务 CAS 不顺带带回读取时的 leaseUntil。Mongoose schema/索引在此文件，允许本模块有少量直接 Mongo helper，不另造 Repository/interface/事件总线。

## 9. 收敛后的职责图

    API / CLI
       ├─ graphRead / graphEdit
       └─ runStart / reviewEdit / reviewAnswer / runCancel / runRetry
                       │
                       └─ rules + store → 共享 Mongo

    每个 Host 的 claimLoop
       └─ claimAcquire → 本机 dshStartOperation
                             ├─ DSH route / delegate / parallel / merge
                             ├─ graphReadData → 受限输入 + 实际读集
                             └─ graphPropose → 报告 / Review / 接受收据
                                                   └─ rules + store CAS

    Mongo 变化 → 每个 API Host → Snapshot SSE
    执行 Host DSH → Activity → 任一 API Host 的 owner 代理

保留的确定性逻辑都回答“数据是否成立、这个 operation 当前能否由此执行者提交”；DSH 回答“该 operation 如何组织智能体完成”。不保留 MapperCallRecord、step 游标、worker 重试队列；也不把业务领取/fence 错误地下放给 DSH 自己猜测。

## 10. DSH 证据范围与实施约束

官方核查基准仍为 commit b2e3b2a0125854567a4a5fcba75782e42fe84901，未在当前项目验证安装/打包/运行闭环。可复用的已核查公开能力为 continuable 子会话、消息/列举/冷恢复、tool schema/guard、持久 store/flush、drain descendants。one-shot 没有恢复 handle，continuable 没有 structured-result Promise；tool 的 execution-local value 不等于已持久报告。

DSH checkpoint 只保证执行意图和已 flush 的会话前缀；数据库已接受而工具结果未落日志时会出现 unknown outcome。业务 proposal/commit 收据提供幂等，不许用随机 callId 或本次 fence 代替业务幂等 ID。参考：[DSH checkpoint policy](https://github.com/deepseek-ai/deepseek-harness/blob/b2e3b2a0125854567a4a5fcba75782e42fe84901/packages/session/session-checkpoint-policy/README.md)、[Subagent](https://github.com/deepseek-ai/deepseek-harness/blob/b2e3b2a0125854567a4a5fcba75782e42fe84901/docs/subsystems/subagent.md)、[Tools](https://github.com/deepseek-ai/deepseek-harness/blob/b2e3b2a0125854567a4a5fcba75782e42fe84901/docs/subsystems/tools.md)。

开始生产迁移前的最小验证必须同时包含：一个 operation 两个 continuable worker、一个共享报告已保存时强制停止 Host A、Host B 过期接管、人工 Review 竞争、旧 fence 迟到报告拒绝、最终接受幂等、正常 shutdown 与用户 cancel 区分。旧测试的人工账本接管不能代替这个闭环。
