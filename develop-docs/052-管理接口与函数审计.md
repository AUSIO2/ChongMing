# 052 — 管理接口与函数审计

本文以当前工作树的 TypeScript 实现为准，记录现有 ElectronAPI、管理 DTO、实际副作用、错误行为及向 051 多 Host 方案迁移时的对应职责。本文不表示这些接口已改成 HTTP，也不把 050/051 的目标能力写成当前实现。

审计范围覆盖 electron/api 中指定的全部管理 service、types、channels、register-handlers，另核对 preload、shared 设置/路径/提示词/错误/数据库实现、skills/registry 及文件导入使用的 mapDocumentInsert。**共 43 个 ElectronAPI 方法：Mapper 3 个，管理及 Desktop 40 个。** 全部列于下文；Mapper 的详细 Command/Node/Run 载荷由图接口主文档定义，此处保留其入口和边界。

目标迁移部分仅规定数据与职责建议。**目标传输路径、最终方法名、鉴权与错误 envelope 以主契约定稿为准，本文不创建另一套已承诺的 HTTP 路由。**

## 1. 当前传输与错误共同规则

- window.electronAPI 由 preload 暴露，调用参数直接交给 ipcRenderer.invoke；没有 token、actor、workspace 权限、统一 DTO schema 校验或 mutation requestId/expectedRevision 包装。[preload](/Users/xiong/ChongMing/electron/preload.ts:5)
- IPC 注册的 handle 包装器捕获同步/异步抛错，经 errUpdateNormalize 后，把错误编码进 Error.message。服务直接返回的 `{ ok: false, error }` 则是正常 resolve，不经过抛错序列化。[注册包装器](/Users/xiong/ChongMing/electron/api/register-handlers.ts:26)
- 编码为 `__APP_ERROR__:{"code":"…","msg":"…","failedNode":"…"}`；failedNode 可选，cause 不跨 IPC。原生 fs、JSON、Mongoose、参数类型错误若未被服务捕获，归为 INTERNAL_ERROR。preload 不自动还原 AppError；消费方可使用 errReadApp/errReadMessage。[错误实现](/Users/xiong/ChongMing/electron/shared/errors.ts:75)
- 本文各方法的“返回”均指 Promise 的成功值；只有 mapper.watch 同步返回取消订阅函数。内部同步 service 经 IPC 后也呈现 Promise。
- 当前没有统一的 not-found 约定：workspace.get 返回 null；file 导出返回 ok:false；workspace.update/delete 抛 AppError；catalog/registry/prompt 查无记录使用 CONFIG_INVALID_SUBAGENT。
- 除明确说明外，方法没有分页、服务端权限、CAS/revision 防丢更新、业务幂等键，也没有通用回滚承诺。TypeScript 参数类型不等于 IPC 运行时验证。

## 6. 多 Host 目标迁移：40 个原方法逐项覆盖

目标原则：共享 Agent 库进入 Mongo；promptPath 保留为逻辑键；catalog/registry/promptConfig 合并为同一配置事实源的不同查询/编辑能力。Workspace 保留私有 Agent 副本，copy 的 merge/replace 行为保留。文件只用于 seed 或显式导入，不再是执行时共享配置真源。

下表“目标职责/函数”是语义建议，最终命名和网络路径未定；同一目标函数可以覆盖多个旧方法，不要求保留三个重复 CRUD 服务。

| 原 ElectronAPI 方法 | 目标职责/函数建议 | 必须保留或明确改变的行为 |
|---|---|---|
| workspace.list | 共享 Workspace 列表 | 按 actor 授权范围过滤；保留 name/description/Agent 和 Map 数量 |
| workspace.get | Workspace 详情 | 保留私有 agents；时间统一为 ISO，增加版本信息 |
| workspace.create | Workspace 创建 | 保留客户端稳定 ID、name/description、可选源 Agent 复制；重复 ID 的幂等语义由主契约定义 |

## 7. 编写目标接口前必须处理的现状差异

1. **共享配置事实源。** 当前三份 Agent 内容、目录缓存、fire-and-forget 同步不满足任意 Host 读取一致配置。目标写共享版本记录，Run/operation 固定其配置快照；Workspace 私有副本保留显式复制语义。
2. **凭据与设置作用域。** 当前 app.getSettings 和 db.getSettings 会回传磁盘 secret/完整 URI；app.saveSettings 是本机明文文件写入。目标 secret 只写、查询只给 configured 等状态，Host secret 与共享模型/profile 配置分开。
3. **数据库切换。** 当前 reconnect/switch 操作的是进程级连接、带 bootstrap 副作用、可能回落独立内存库。051 的数据裁决依赖共同 Mongo，目标必须是管理员受控的部署变更。
4. **可移植导入导出。** 当前文件服务包含 Desktop 对话框、同步磁盘 I/O、非事务导入、原样保留 ID/run。目标后端负责包内容与引用/权限校验，Desktop 负责路径选择；不能只把旧 service 包成 HTTP。
5. **异常与字段语义。** 当前既有 reject、null、ok:false，又有返回类型窄于实际对象、非法输入写后失败、部分字段静默忽略。主契约需要逐项确认迁移后的明确行为；本文记录当前事实，不以“规范化”名义隐去差异。
