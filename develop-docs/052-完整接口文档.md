## 1. 通用约定

- 前缀 `/api/v1`。生产 HTTPS；开发 loopback 可 HTTP。
- HTTP 用户认证为 `Authorization: Bearer <token>`。身份由 Host 解析，客户端没有 actorId/role/ownerHostId/fence 参数。令牌只保存 hash；生成后的明文仅返回一次。
- ID 为客户端预分配 UUID（operation/receipt 等内部身份除外）；时间为 UTC ISO 8601；revision 为非负安全整数，从 0 开始。业务身份不编码父节点或数组位置。
- JSON 固定 UTF-8，拒绝未声明字段。必填字段必须出现；`null` 表示明确清空；可选查询字段省略表示不筛选。Node、Agent、Review 的 update 是指定内容对象的完整替换，避免不同 Host 对隐式 patch 默认值理解不同。
- 普通 JSON 请求最大 1 MiB，单资产最大 64 MiB，导出/导入 bundle（包含 base64 后的整个 JSON）最大 64 MiB，单 Map 业务文档软上限 8 MiB。bundle 通过二进制资产上传路径传送，控制命令只带 assetId，因此不受 1 MiB 普通 JSON body 限制。上限属于部署配置，所有 Host 一致；超限返回 413。附件不内嵌 Map。
- Page.limit 默认 50，范围 1–200；cursor 为不透明字符串，仅可配合原查询继续使用。列表按 `(updatedAt,id)` 或指定稳定键排序；游标分页不保证跨多次请求的全库快照。
- 同一活跃 Run 期间，正式图 Node/Edge/Policy CRUD、去重、Map/Workspace 删除均拒绝；Map 重命名和用户自己的偏好可更新。人工改动通过 Review；多个 Host 的合法运行结果可并行接受。
- 查询不存在的资源返回 404，不使用成功响应中的 null。对不可见 Workspace/Map/Asset 同样返回 404；已可见资源的操作权限不足返回 403。

### 成功/失败响应

```json
{"ok":true,"requestId":"UUID","replayed":false,"data":{}}
```

```json
{
  "ok":false,
  "requestId":"UUID",
  "error":{
    "code":"REVISION_CONFLICT",
    "message":"数据已变化，请重新读取后提交",
    "retryable":false,
    "conflict":{"resource":"map","id":"MAP_UUID","currentRevision":18}
  }
}
```

`data` 是 QueryMap/CommandMap 对应 output；没有 `any` 业务载荷。未知服务器错误不返回堆栈、数据库 URI、模型凭证。诊断接口可以在成功信封内返回 `data.ok=false`，表示诊断完成但被测端点不可用。

### 写入幂等和 revision

所有 command 携带 requestId。相同 actor、method、资源作用域、requestId 和规范化输入的重复请求不重做写入；同 ID 不同输入为 `IDEMPOTENCY_CONFLICT`。先检查已接受收据，再检查旧 expectedRevision，修复“服务器已提交但响应丢失”。

重放保证动作不重复，返回当前可读资源视图和原创建 ID，`replayed=true`，不保证快照逐字节等于首次响应。资源已经删除则返回 410 `RESOURCE_GONE`，绝不通过重放重新创建。收据保留紧凑身份/结果引用，不拷贝整个 Snapshot；首版不自动清理仍可被重试引用的收据。删除使用业务 tombstone 保留裁决信息。

409 后客户端重读并让用户合并；确认的新输入使用新 requestId。网络错误可原样重试同一请求。`GraphWriteResult.snapshot.revision` 低于本地基线时只接受命令确认，不用旧快照覆盖新快照。

## 2. HTTP 路由总表

| HTTP | 路径 | 请求/响应 | 权限与说明 |
|---|---|---|---|
| POST | `/query` | QueryRequest → Success<对应 output> | 200；逐查询鉴权 |
| POST | `/command` | CommandRequest → Success<对应 output> | 一般 200；创建资源 201；接受运行/回答继续 202 |
| GET | `/maps/{mapId}/events` | text/event-stream；GraphEvent | 可见 Map 的成员；完整首帧 |
| POST | `/assets?workspaceId=…&filename=…` | 原始二进制 → Success<Asset> | Editor；Content-Type、Content-Length、X-Content-SHA256、Idempotency-Key 必填；201 |
| GET | `/assets/{assetId}/content` | 二进制；Content-Type/Length/Disposition/ETag | 资源所在 Workspace 的成员；200；v1 不承诺分段续传 |
| GET | `/maps/{mapId}/export` | MapBundle JSON 下载 | Viewer 也可导出自己可见内容；200 |
| GET | `/workspaces/{workspaceId}/export` | WorkspaceBundle JSON 下载 | Owner，包含工作区 Agent 配置；200 |
| GET | `/health/live` | `{"ok":true,"version":"…"}` | 无凭证；只表示进程可响应，不等于 DB 可用 |
| GET | `/health/ready` | `{"ok":true}` 或 503 | 受部署网络访问策略限制；需要共享 DB、相同 schema 与配置准备完成 |

路径参数及 filename 使用标准 URL 编码。导出使用固定 `Content-Disposition: attachment` 的安全文件名；不把用户文件名当服务器路径。请求经过 API Host，执行 Host 对前端透明。

### 查询请求

```json
{"method":"map.get","params":{"mapId":"MAP_UUID"}}
```

查询无业务副作用；只会产生普通请求日志。每条响应 requestId 由 Host 生成，或采用合法的 `X-Request-Id` 关联值。

### 命令请求

```json
{
  "requestId":"REQUEST_UUID",
  "method":"run.start",
  "params":{
    "mapId":"MAP_UUID","expectedRevision":12,"id":"RUN_UUID",
    "scope":{"kind":"nodes","nodeIds":["NEWS_A_UUID","NEWS_B_UUID"]},
    "until":"verified","mode":"human-in-loop"
  }
}
```

run.start 在目标和初始业务项耐久接受后立即返回 202，不等待模型执行。202 表示已接受，不表示图已经达到目标。

| `map.get` | mapId | GraphSnapshot | 成员；只读，不领取操作、不恢复运行 |

workspace.get 面向当前小团队场景全量返回成员和工作区配置，不连带返回全部图。Preferences保留自己的revision，Workspace资料/成员/Agent共用Workspace.revision；组合响应不把这两个并发版本合成一个假全局版本。

## 4. 全部业务命令

MapMutation 为 `mapId + expectedRevision`。成功一般返回 GraphWriteResult（完整快照、创建节点/边 ID、本次 runId）；明确删除返回删除确认。普通编辑均要求 Editor 或 Owner。

| method | 附加必填参数 | 语义/边界 |
|---|---|---|
| `map.create` | workspaceId/expectedRevision/id/name | expectedRevision 是 Workspace 版本；201；节点为空 |
| `map.delete` | 无 | 无活跃 Run；tombstone，同图订阅收到 map.deleted |
| `graph.apply` | changes | 明确的名称、Node、Edge、Policy变更集；统一校验，单次原子接受，规则见下 |
| `claims.merge` | groups | 非空、互不重叠的keepId/removeIds分组；每组removeIds非空且不含keepId；原子迁移来源和出处并处理失效，不按裸删除模拟合并 |
| `run.start` | id/scope/until/mode | 无活跃 Run；冻结业务配置；仅登记工作，202 |
| `run.retry` | previousRunId/id | 仅 failed Run；新 Run ID，范围与目标不变；引用仍匹配输入/配置的旧报告，旧 Session 授权不复活；202 |
| `run.cancel` | runId | 活跃 Run → cancelled；先落终态再停止执行；重复取消同 Run 返回其状态；200 |
| `run.set-mode` | runId/mode | 仅活跃 Run；影响尚未决定的 Review；不复用旧批准或推翻已拒绝决定；202 |
| `review.update` | runId/reviewId/expectedReviewRevision/content | 仅 pending Review；kind 不可改变；增加草稿版本、废弃依赖旧稿的后续批准 |
| `review.answer` | runId/reviewId/expectedReviewRevision/decision/note | pending → answered；原子记录答案；批准/修订可使 operation ready，202；明确拒绝终结 Run |

这里没有 lease.acquire/release、timeline.update、run.continue 的兼容别名。原 run.continue 拆成草稿更新、回答 Review 或显式失败重试，分别验证状态。

### graph.apply 的完整语义

```json
{
  "requestId":"40000000-0000-4000-8000-000000000001",
  "method":"graph.apply",
  "params":{
    "mapId":"10000000-0000-4000-8000-000000000001",
    "expectedRevision":0,
    "changes":{
      "nodes":{"put":[{"id":"20000000-0000-4000-8000-000000000001","data":{"kind":"news","content":"新闻正文","context":{}}}]}
    }
  }
}
```

- changes 只允许 name、nodes、edges、policies。不是JSON Patch，不接受任意字段路径、Mongo modifier、Run、Review或执行状态。
- nodes/edges 的 put 是明确的全内容设定：ID不存在则创建，存在则更新；节点kind不能改变；已删除ID不能复活。用户编辑只提供id/data，revision、出处和有效性由Host维护。
- remove 只指定要删除的ID，目标不存在则冲突；同一集合内ID不得重复，也不得同时出现在put/remove。nodes.remove自动清理该节点的NodePolicy和原图中以它为端点的展示边，无须客户端逐条列出；共享的其他节点保留。删除记录保留必要历史来源，计算引用转为missingInputs。若本批edges.put仍引用被删节点，整体拒绝，不能静默丢弃明确提交的新关系。
- policies 是按 `(nodeId,operation)` 完整替换的明确条目，支持split/verify；恢复默认使用auto+空preferences。批量priority/hint由共享纯函数按当前Snapshot展开后提交，不引入服务器筛选语言。
- 省略字段是不修改；空数组不修改；整个变更集至少一个动作。活跃Run仅允许单独name变化，不允许把名称更新夹带进图编辑。
- 先构造候选最终图再验证所有引用，支持一次创建多个节点并连接它们；失败整体不落库。后端按真实输入变动处理过期状态，不依赖前端标记。
- 公共人工图编辑只需expectedMapRevision，不重复要求每个节点expectedRevision。节点revision仍保留用于计算输入和来源验证；Map CAS保证整个编辑基线未变。

精确去重使用共享纯函数 `claimsReadMergeGroups(snapshot,nodeIds)`：trim+Unicode NFC+toLowerCase，category同样归一化，保留最早createdAt再按ID排序的节点，产出MergeGroup[]。前端和CLI均可复用，然后调用claims.merge；服务器继续负责引用迁移、出处保留与原子校验。

### Node/Edge 校验

- Source locator 只允许已 ready 的同工作区 assetId 或 HTTP(S) URL；URL 采集由受控输入工具执行，不是把网页地址直接送给文件读取函数。
- URL 采集对每次重定向重新验证目标，默认拒绝私网/metadata 地址，只有 Host 明确配置允许时开放；设置超时和体积上限。采集失败返回明确错误，不使用本机文件或另一个 URL 作为无声兜底。
- NewsContext 保留 value/visibleToAI；所有根/子 Agent 读取时移除 false 字段。值限定字符串，旧 Mixed 数据在一次性迁移边界明确转换或报告错误。
- Claim.category 保留 string|null，配置中拆分类型参数仍限制 data/quote/causal。业务记录不强制缩窄已有手工类别。
- Verification.score 与 Opinion.score 仅 0/0.5/1。Opinion 有稳定 ID、Agent/slot/report 出处，不用数组索引充当身份。
- Node.provenance 保留逐产物的 report/Agent/slot 来源数组，接受 CandidateNode 时从 reportIds 固化；合并事实合并出处数组，不能只保留整个 operation 的笼统来源。导入来源有明确的 importedFrom 字段。
- `derived-from` 产物→输入；`mentions` 新闻→事实；`supports/refutes` 证据→事实；`verifies` 结论→事实；`related-to` 同图非自身数据节点，允许关系环。verifies 每个 Verification 恰好一个目标，创建时需同次给出边。
- derived-from 合法端点为 news→source、claim→news、evidence→source/news、verification→claim/evidence/news；其他组合拒绝。报告采用实际 NodeRef 和采集内容声明计算来源，不能用一个 related-to 边替代计算依赖。
- 派生 DAG 按实际输入版本与收据验证；普通关系不能触发无限工作扩张。有效历史收据及本次结果扩展 scope，共享 Claim 不反向纳入别的新闻。
- source/evidence 的资产摘要和原文摘录保留，不能以缺失远端来源为由静默替换证据。

### Review 的明确状态机

```text
route pending → approve → 操作 ready，DSH 执行允许的 slots
validate pending → approve → 操作 ready，生成当前版本 save Review
save pending → approve → 操作 ready，新持有者检查批准并原子接受结果
任意 pending → revise → 操作 ready，要求修订后生成新 Review
任意 pending → reject → 该 operation 与 Run 终结为 failed/user-declined
```

auto 模式按同一校验规则自动决定，无需创建等待中的假人类 Review。waiting 释放执行租约；答案由用户权限验证，不要求执行租约。两位 Editor 同时回答，只有一个提交成立。Review/草稿信息保存在 Mongo，不靠 DSH 内存 Promise 保存。

OperationContext 持久保存当前 approved route、canonical draft、draftRevision/fingerprint、所有 auto/user 决定和 reportIds。即使 auto 不产生 Review，另一 Host 也能恢复同一份路由和草稿。save 提案只引用已验证 canonical draft 的版本/指纹，不接受另一份任意内容。编辑 save Review 的草稿会使旧 save Review superseded，生成新的 validate Review；旧 validate/save 批准全部失效，不能直接批准修改后的 save。

## 5. 全部管理命令

WorkspaceMutation 的 expectedRevision 是 Workspace 版本；AgentMutation 的 expectedRevision 是对应 library/workspace Agent 集合版本。scope=workspace 时集合版本就是 Workspace.revision；其 Agent CRUD/copy 与工作区资料/成员变更共用同一 CAS。scope=library 时使用独立 libraryRevision。个人 Preferences 有自己的 revision。

| method | 参数要点 | data 类型 | 权限/行为 |
|---|---|---|---|
| `workspace.create` | id/name/description/agentSource | Workspace | 登录用户；自动成为 Owner；empty/library 明确选择，不隐式合并 |
| `workspace.update` | WorkspaceMutation/name/description | Workspace | Owner；不再通过这个方法整包覆盖 agents/ui |
| `workspace.delete` | WorkspaceMutation | `{workspaceId,deleted}` | Owner；有活跃 Run 则冲突；先 tombstone 工作区，拒绝新写入与订阅 |
| `member.set` | WorkspaceMutation/userId/role|null | MemberWriteResult | Owner；role=null移除，否则设置角色；不允许移除最后Owner；移除后撤销订阅；返回member或null及新workspaceRevision |
| `preferences.set` | workspaceId/expectedRevision/openMapIds/currentMapId/nodeSelection | Preferences | 本人；只有可见且属于工作区的 ID；不影响其他成员标签页 |
| `agent.create` | AgentMutation/agent | AgentList | library：HostAdmin；workspace：Owner；新建仅 split/verify SubAgent |
| `agent.update` | AgentMutation/agentId/expectedAgentRevision/agent | AgentList | 同上；id/promptPath/kind/agentType 不可改；支持清空 model/baseUrl 为 null |
| `agent.delete` | AgentMutation/agentId/expectedAgentRevision | AgentList | 同上；固定 parse/route/merge 不能删；被持久策略引用时拒绝 |
| `agent.copy` | WorkspaceMutation/libraryRevision/agentIds/mode | Workspace | Owner；merge 按 promptPath 覆盖所选，已有目标保持原工作区 agentId；replace 用所选完整替换，新项生成工作区 ID；被持久策略引用的删除必须拒绝，不能留下悬空 slot；两模式均保护固定角色与引用 |
| `settings.update` | expectedRevision/llm/limits | ClusterSettings | HostAdmin；全对象更新；影响未来 Run，已有快照不变 |
| `endpoint.test` | hostId/kind | EndpointHealth | HostAdmin；network 测连通延迟，llm 做真实小请求；可能产生模型费用，不是无副作用 query |
| `asset.delete` | assetId/expectedSha256 | 删除确认 | Owner；被引用则 ASSET_IN_USE；先逻辑删除，物理 chunks 后续清理 |
| `workspace.import` | id/bundleAssetId/stagingWorkspaceId/name | ImportResult | staging 工作区 Owner；导入 bundle 建立一个新工作区，201；不覆盖原工作区 |

共享 Agent 库是原磁盘 catalog/registry/promptConfig 与 local_agents 的目标统一入口。磁盘 JSON 仅首次 seed 或 HostAdmin 显式导入。Workspace.agents 保留私有副本语义，不因为 library 修改自动覆盖工作区；Run 冻结实际 profile 版本。

密钥不出现在 ClusterSettings。各 Host 管理员通过本机 HostAdminAPI 设置凭证；只有配置满足的 Host 才领取相应操作。运行 profile 的语义配置共享，secret 不写入 prompt、返回 DTO 或导出文件。Agent刷新直接重读agent.list；重建共享配置只能使用管理员显式seed/import，不存在agent.reload写命令。

Workspace/成员/Agent 等跨聚合管理动作使用 Mongo 原生事务或明确的 tombstone 可见性边界；禁止先返回成功再 fire-and-forget 同步另一数据源。共享配置版本是读取/写入约束，不在 Handler 内各自 fallback 到本机磁盘。

## 6. SSE 与多 Host Activity

请求必须认证。使用 fetch 读取 SSE 流以携带 Authorization；不要把 token 放 query string。首帧为完整 snapshot，所有持久业务状态从它恢复。

```text
event: snapshot
id: 18
data: {"type":"snapshot","snapshot":{"mapId":"…","revision":18,"…":"按GraphSnapshot完整字段"}}

event: activity-reset
data: {"type":"activity-reset","operationId":"…","attemptId":"opaque-new-attempt","frame":null}
```

上例 snapshot 展示帧格式，实际 payload 必须符合完整 GraphSnapshot，不使用省略字段。

- snapshot.id 是 Map revision；客户端丢弃较旧帧。建立订阅时先缓冲数据库通知再读基线，随后仅发送高于基线的结果。
- Last-Event-ID 允许携带；v1 重连仍发送最新完整基线，不承诺事件日志回放。
- Activity 是当前执行的展示投影，使用不透明 attemptId 与局部递增 seq。只有 activity-reset 可切换 attemptId；迟到的旧代帧丢弃。
- API Host 按内部 ownerHostId 代理执行 Host 流，内部 fence 不作为客户端写入参数。数据库与网络丢帧不影响业务收据。
- heartbeat 为 SSE 注释，每 15 秒；每订阅只保留一个最新待发完整快照，Activity另设1 MiB缓冲。Activity缓冲溢出或连接持续不能完成发送时断开重建基线；不因一张合法完整快照大于1 MiB就拒绝首帧。
- map.deleted 结束订阅；access.revoked 结束订阅并清除本地数据。授权变化后重新校验，不仅连接时验一次。
- 前端关闭标签页只取消订阅。run.cancel 必须由独立业务命令触发。

## 7. 资产、导入导出

上传为原始二进制，Host 流式写 GridFS 并计算 SHA-256，长度/摘要匹配、文件持久完成后返回 Asset。重复 Idempotency-Key 且内容摘要一致返回相同 assetId；不同内容为冲突。上传未完成的资产不能被 Source 引用。

下载按工作区授权读取；ETag 为内容摘要。v1 不暴露 storageKey、GridFS 内部 chunk ID 或 Host 本地缓存路径。

MapBundle/WorkspaceBundle 是 version=3 的完整可移植 JSON，字段见契约。资产内容使用 base64，导出包含所引用资产；不隐式只带某台电脑的路径。输出排除 secret、token、DSH 会话、lease、可执行 Run 和别人的 UI 偏好。

BundleNode 带原 revision、validity、provenance，Edge 带引用版本及有效性。导入生成新 ID，但保留这些节点版本数字；后续编辑从该版本递增。只有指向本包导出 head 的 NodeRef 才能映射为新节点当前版本，旧 sourceRevision 仍是旧版本且必须保持 stale。显式 missingInputs 表示原来已删除/缺失的历史输入；导入为这些引用预留独立 ID 并保留缺失状态，禁止误映射成现有节点。

已有 verification 的 reportId/出处属于历史来源标签；导入时写入 Node.origin/importedFrom，旧 reportId/operationId 保留为可展示的历史来源，不解析为新工作区的可执行 operation。Agent/slot/node 等仍在包内的有效引用全部重映射。原文与意见内容保留，缺少可复现输入收据的导入自动结论标记 stale，不谎称已验证当前输入。

导入步骤：

1. Desktop/Web/CLI 把 bundle 作为资产上传到本人有 Owner 权限的 stagingWorkspaceId。
2. workspace.import 校验格式、字段、内容摘要、引用闭包（含显式 missingInputs）和数量上限；只接受 version=3。
3. 为 workspace/map/node/edge/agent/slot/嵌套意见中的引用生成完整 ID 映射；不沿用旧活跃 Run 或 Session。
4. 先写完整不可变资产，再用有限 Mongo 事务发布新 Workspace 和所有 Map。失败不发布半个工作区；孤立上传资产作为未引用内容可清理。
5. 返回 ImportResult。相同 import command 重试不再创建一份工作区。

单图 export 能用于导出阅读与后续工具处理；v1 的导入入口接受 WorkspaceBundle，保持当前仅工作区导入的功能范围。超出 bundle/事务限制返回明确错误，不在请求成功后悄悄继续后台导入。

## 10. Host 内部执行接口

ExecutionAPI 是进程内函数契约，多个 Host 直接通过共享 Mongo 条件更新协调；不额外提供公网 claim/renew/commit 端点。

失败以具有 PublicError 字段的项目异常拒绝 Promise。HTTP adapter 映射成 Failure；DSH 工具 adapter 映射成原生 isError 工具结果。不能把异常装成一个空候选列表或 accepted 状态。

| 函数 | 入参 → 返回 | 原子条件/行为 |
|---|---|---|
| claim | ClaimInput → LeaseResult|null | 按容量/能力发现 ready 或过期 executing 项；原子 owner/holder/fence++；无可领取项返回 null |
| renew | ExecutionGrant → 新 grant | owner/holder/fence 匹配、Run 活跃、DB 租约未过期；仅更新 leaseUntil |
| release | ExecutionGrant → void | 已停驻本地执行后放回 ready；只有相同 holder/fence 可释放，waiting/completed 不被改回 ready |
| read | DshBinding+DshRead → DshReadResult | 限定 operation 输入/节点/关联证据/报告/Review；解析来源文本、裁剪不可见上下文，返回持久 OperationContext 并登记实际读取版本 |
| propose | DshBinding+DshProposal → DshProposalResult | 所有写入检查有效授权及业务状态；候选报告、Review、接受分别幂等 |
| fail | ExecutionGrant+PublicError → void | 仅有效持有者可将 operation 与 Run 同次 failed；旧持有者失租不能杀死新执行 |

默认 lease 30 秒、约 10 秒续租，部署可调整。截止比较用 Mongo 时间；进程 holderId 每次启动变化。fence 只属于执行授权和 Session 绑定，不放入业务 commitKey。

结果、边、接受收据、operation 完成、新后继项在同一 Map 条件更新中保存。纯心跳不改业务 revision；其他可见状态改 revision。字段级更新不能覆盖别的 operation 的 lease/报告。

全局完成由任意 Host 按同一 revision 重算 scope/until，再 CAS 写 completed；永久失败同次写 Run.failed。终态不能复活，retry 新建 Run。取消先写 Run.cancelled，所有后续领取/续租/提交被阻断。

### Host 之间唯一需要的流协议

内部路径 `GET /internal/v1/maps/{mapId}/operations/{operationId}/activity?fence=N`。调用者为注册 Host，使用专用服务凭证或 mTLS，不接受普通用户 token 代替机器身份。接入 Host 先校验用户可见性，执行 Host 再校验请求 Host 和当前 owner/fence。

响应 SSE 为局部 Activity 原始展示帧；执行代数不匹配返回 409 `LEASE_LOST`，结束返回 stopped。API Host 将内部代数映射为公开 attemptId，前端不能借它提交数据。Host 地址表为部署配置，不是可由模型编辑的图数据。

## 11. DSH 模型可见工具

只注册 `data.read` 与 `data.propose`，schema 对应 DshRead/DshProposal。binding 由 Host 闭包注入，模型看不到 ExecutionGrant。

二者与scope/工具guard合在一个本地DSH业务接入插件模块中，转接ExecutionAPI；普通业务HTTP命令不批量注册成模型工具。Agent角色是profile数据，跨Host领取、Review和提交裁决留在普通后端。详细插件边界见架构主稿第9节。

| 角色 | read 能力 | propose 能力 |
|---|---|---|
| root | 当前操作输入、已验证报告、Review/决定 | route/validate/save |
| worker | 已分配槽位的输入及允许资料 | report |

data.read 返回本阶段合法的 proposalTokens，模型只能回传其中的 proposalId/draftRevision；Host 不信任模型随机造的提案身份。候选报告的 producer/slot/operation/input 指纹由绑定填写，用户或模型不能冒充其他槽位。

显式重试复用的旧报告加入新 OperationContext.reportIds 允许引用集；读取/提案按这个集合校验，不要求历史 report.operationId 必须等于新 operationId。报告内容和原作者出处保持不变。

input 查询返回 resolvedInputs：从 ready 资产读取或受控采集 URL 得到的完整文本、来源版本、摘要和采集时间，原始采集内容先持久保存；同操作恢复复用该输入，不悄悄重抓网页。v1 解析支持 UTF-8 text/plain、text/markdown、text/html、application/json，其他媒体返回 UNSUPPORTED_MEDIA_TYPE；文本上限 1 MiB，超限明确失败。nodes 查询及 evidence 查询限同图、获授权的操作上下文；evidence 的 cursor/limit 为 1–100，实际返回的节点和关系范围进入读集。数据查询不会扩大本次自动运行 scope。

validate 提交草稿后 Host 保存 canonical 版本并计算 fingerprint；save 只引用这个版本与 fingerprint，再检查 validate 和 save 的有效决定。read 所返回的 context 包含 auto 决定，接管不需要重新推导“此前是否已批准”。

data.propose 的返回状态：recorded（报告落库）、waiting（等待 Review 并释放执行权）、approved（当前草稿已通过该门）、accepted（最终收据）。解析、拆分允许零结果仍 accepted；schema 验证失败不伪装成空列表。

DSH 子 Agent 的原生控制工具属于 DSH，不在业务 HTTP 中复制。其命名工具配置只暴露批准的 profiles/slots/最大数量；priority 决定领域路由排序/选取，不能假设它天然等于 DSH 集群调度优先级。

## 14. 第一阶段：独立 DSH 执行接口

用户明确先封装DSH。因此先实现DshRuntimeAPI，作为后续新后端直接调用的模块；用一个薄loopback HTTP入口验证。此接口不计入面向产品的9查询/23命令，也不要求最终前端直接操作DSH。当前实现锁定官方`@deepseek-ai/dsh-sdk-client@0.1.5-rc.1`，遵守其实际线协议。

### 三个方法

| 方法 | 入参/返回 | 语义 |
|---|---|---|
| start | 无 → void | 启动SDK子进程并完成initialize；不发送prompt |
| run | prompt/sessionId? + onEvent? → DshRunResult | 向命名或新Session发送prompt，流式观察根与已发现后代通知，等待根Agent下一个idle并返回该区间最后一个root assistant文本 |
| close | 无 → void | 请求shutdown并按官方SDK退出阶梯确认子进程结束；幂等，关闭后不可重用 |

运行时由dshCreateRuntime装配；profile、模型、工具、dshBin路径与secret由本机配置。HTTP请求只提交prompt和可选sessionId，不上传profile、插件或密钥。相同sessionId用于延续历史；profile/provider/model是进程级初始化配置。

run完成只表示官方SDK拥有的receipt-to-idle区间结束。finalResponse是该区间最后一个根会话assistant文本，不是与本次prompt绑定的强因果结果；根idle也不能用作未来业务Run完成条件。

### 本机HTTP映射

| HTTP | 路径 | 对应方法 |
|---|---|---|
| GET | `/health` | 进程已完成DSH initialize后返回ok |
| POST | `/runtime/dsh/run` | body为prompt/sessionId?；200 application/x-ndjson，逐行event，最后一行为result；执行失败写error行 |

close由进程生命周期调用，不暴露远程关闭接口。第一阶段绑定loopback；正式鉴权与产品Graph API后续接入。

### 持久化和恢复契约

- 官方SDK自动生成messageId，当前协议没有调用方幂等消息ID。因此网络未知结果不能安全地盲目重复run；业务层后续必须使用自己的operation/proposal收据保证业务结果幂等。
- 当前SDK协议没有冷Session查询、单Session关闭或中途cancel。close会结束整个SDK运行时；第一阶段不将它伪装成cancel(sessionId)。未来需要精确取消时评估直接嵌入DSH公开Agent API，先补测试再扩DshRuntimeAPI。
- SDK profile负责JSONL Session持久化；恢复行为必须用同一dshHome和sessionId实测。当前封装不额外保存消息副本。
- 不承诺恢复JavaScript栈、自动继续所有子孙或模型调用exactly-once。结构化业务结果通过后续schema报告工具保存，不把普通工具临时value当作可恢复结果。

第一阶段使用官方[SDK client](https://github.com/deepseek-ai/deepseek-harness/tree/master/packages/sdk/client)和[SDK protocol](https://github.com/deepseek-ai/deepseek-harness/tree/master/packages/sdk/protocol)；取消与查询能力按协议限制处理，不从完整DSH内部API反推SDK已经暴露的能力。

### 上下文与记忆托管

- 会话消息与工具历史使用原生Session/persistence；原始事件持久化，不等于每次都把全部历史重新送给模型。
- 上下文压力估算、工具结果裁剪、自动摘要交给启用的token-meter/compaction/provider/pruner。此为可选插件能力，必须装配并验证；摘要更新当前模型看到的上下文，有损摘要不替代原始业务数据。[DSH Compaction](https://github.com/deepseek-ai/deepseek-harness/blob/b2e3b2a0125854567a4a5fcba75782e42fe84901/docs/subsystems/compaction.md)
- 跨Session长期记忆尚未选型，第一阶段不引入社区记忆插件。此前仅凭README列出的社区实现引用已移除；接口可扩展不代表某个依赖已经可用。后续若有明确需要，须核对源码、维护与版本兼容证据并完成隔离/并发/恢复测试后再决定。
- 多用户/工作区记忆必须按明确身份和Workspace隔离；跨Host需共享存储或同步/检索策略。图、证据、报告、Review和接受收据仍保存在业务数据库，不能靠模型记忆推断是否已接受。
- 自动上下文管理通过profile/runtime配置启用，执行接口不因此增加memory CRUD。上下文窗口估算/每次输出上限不等于整个业务Run累计token/费用硬限制，后者由运行预算单独控制。

## 15. 契约验收

接口实现不得只通过 TypeScript 编译就视为完成。至少验证：未知字段/非法状态、权限与跨 Workspace、所有命令重复请求、旧 revision、多人 Review 抢答、网络中断后的基线、两 Host 争抢/过期迟到、结果已提交但响应丢失、失败重试的新 Run 隔离、导入所有嵌套 ID 重映射与资产完整性。

当前方法和目标函数的源代码证据分别见 [前端审计](./052-前端与入口函数审计.md)、[后端核心审计](./052-后端核心函数审计.md)、[管理接口审计](./052-管理接口与函数审计.md)。主架构和实施清单见同编号设计及实施原稿。
