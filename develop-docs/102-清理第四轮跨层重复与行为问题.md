# 102 — 清理第四轮跨层重复与行为问题

## 目的与范围

处理最新只读审查确认的 12 组及 2 处小项，保留前三轮及工作区已有功能。4 组行为问题为 schema 字典读取原型、JSON 非法 UTF-8 误分类、下载清理覆盖主错误/遗留读取器锁、运行端固定枚举隐式字符串化。

## 接口与不变式

- schema properties/definitions 仅按自有条目解释，未声明原型键或引用不可通过；显式声明相同名称仍合法。
- UTF-8 解码错误属于非法响应，不进入网络重试。真实 fetch/read 失败、取消、关闭及超时继续区分。
- 下载保留大小、完整性与文件名限制；次级取消错误不覆盖主失败，读取器锁在所有路径释放。不增加重试或假成功。
- RPC 按方法一次完成必要字段形状验证，并用窄类型承接结果，不在通用和分支重复检查。
- IPC 来源和 Host 永久错误码严格比较原值，保留未知对象、可信框架、白名单及资源排空检查。
- 私有 DSH schema 只处理上游仍可能产生的结构，不建立兼容回退。
- 图、应用、资产共享同事务内已验证的正文与引用；资产状态、所属工作区、媒体类型、引用权限及最终写入仲裁仍必须检查。无 unchecked 入口或以可选参数补默认的替代设计。
- 导出一次取得同一元数据快照内的目录、包和 Agent；保持授权、包摘要和精确闭包。
- 导入复用未变正文的解析结果，重映射后的新正文仍完整验证，保留根对象与容量约束。
- 结果审核复用本次同步 attempt 的已验输入和发布计划；版本比较必须先于审核修改，收据优先顺序和无版本原语义不变。
- UI 预览保持本地候选与权威预览的真实匹配、代次及材料检查；ready 类型携带对应有效结果。已发布 schema 与 primary 字段的合法关系通过类型表达，不用断言或新兜底遮掩。

## 实施与恢复

按客户端 3 组、后端跨层 4 组、运行及 schema 3 组、UI 4 组分文件并行完成并交叉检查。实施前保存工作区差异和未提交文件副本。只叠加本轮修改，不覆盖新增 run-history、publication preview 等并发功能。不迁移数据、不部署、不提交或推送。

## 验证

行为问题先补可复现回归再修复；纯删除使用现有业务回归，不写镜像实现测试。运行相关 schema、客户端/文件、IPC/Host、DSH、图/Run、资产/包、预览/阅读及必要集成测试；完成主项目/测试类型、架构/运行文案及差异检查。保持原测试超时，不增加重试或跳过；前轮本机长暂停问题按有限相关套件和持续等待验证。
