# 014 — Map 层坏味道清理

## 目标

清理 Map 内存图维护中的缺陷与重复实现，并落实 claim 草稿的 `shouldSave` 人审语义。

## 变更要点

### 运行态重置

`resetIdleFromNews` 必须清空 `runId` / `graphType` / `draft` / focus，避免 cancel 后 resume 死 run。

### CRUD 复用

`addSubAgent` 统一走 `ensureSubAgent`（规范化 instanceId、维护边）。

### activeTool

`applyProgress` 在进入 running 时保留焦点节点，写入 `runtime.activeTool`。

### 权限单轨

Map 不再存 `gate`；`canWriteRouteInstructions(pendingTool)` 仅当 `pendingTool === 'invoke'`。

### shouldSave（与 dataPhase 正交）

| 字段 | 含义 |
|------|------|
| `dataPhase` | 是否已落库（workerOut / persisted） |
| `shouldSave` | 草稿是否保留待落库；默认 `true`；仅 merge 可改为 `false` |

流程：`subAgent` 产出草稿（`shouldSave=true`）→ `merge`（LLM，只改标记）→ 工具 `validate` 人审 → continue 剔除 `false` → 剩余写入 `mergedClaims` → 工具 `save`。

**工具 vs 节点**：Map 节点只有 news / subAgent / claim / opinion。`merge` 是图内 LLM 步骤，不做人审中断、不投影为 Map 节点；人审挂在焦点上的工具 `validate`（图内空节点与工具同名）。`save` / `invoke`（confirmRoute）同理是工具。

图编排：`… → merge → validate → save`，`interruptBefore: confirmRoute | validate | save`。

merge 输出与草稿同序的 `shouldSave`，不猜 `sourceAgent`。

### 侧栏

Map 有 claim 时以 Map 为准；DB 补 score；展示「不保存」/「待保存」。

## 非目标

- 不改 verify 的 opinion 丢弃语义（仅对称加入 `validate` 工具中断点）
- 不删除 `getActiveRun` IPC
