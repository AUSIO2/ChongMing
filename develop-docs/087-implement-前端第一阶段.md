## 单页来源脚注增量

用户要求子节点注明原文出处，例如事实来自新闻第 1、3 行。现有 successor 只记录节点关系，故新增可选 `GraphEdge.sourceAnchors`：字段 JSON Pointer、来源节点 revision、闭区间行号和精确摘录。原文行号按真实硬换行从 1 起算，含空行，CRLF 只计一个换行；屏幕折行不计数。第 1、3 行是两个独立定位，不扩成第 1–3 行。

- `contracts/source-text.ts` 统一行号与摘录规则；HTTP、graph.apply、Mongo schema、客户端快照验证与便携包保留该元数据。新增/修改定位须与当前来源版本和原文逐字匹配；未修改的历史定位可保留，来源改写不删除旧摘录。
- `reader-sources.ts` 读取真实来源脚注与反向行标记，不从相似文本猜来源；`DataPayloadView` 在有定位的原文显示行号、脚注及高亮，`NodeReader` 在子页展示来源摘录，打开来源后滚到精确行。
- `SourceAnchorEditor.vue` 提供多字段、离散行和连续范围标注、摘录预览、清除定位。草稿绑定打开时原文版本；版本变化后须重新打开。`client-session.saveSourceAnchors` 经分支版本核对保存完整边，本机不调用租约，协作模式复用或临时领取所需授权。
- 旧版原文定位显示版本变化提示，保留摘录并禁止在新版正文冒充准确高亮。未定位的真实父节点显示“尚未标注具体行”。

验证：`reader-sources`、`session`、`graph-client`、后端 `source-anchors`、`bundle-v4` 共 5 个文件、58 项定向测试通过；整个仓库 `vue-tsc --noEmit`、架构/运行文案检查、Vite 构建与 diff whitespace 检查通过（上一节记录的临时类型错误已由对应模块修复）。浏览器实际保存了第 1、3 行，确认子页脚注、原文第三行高亮及原文脚注返回子页。当前提供手动标注和协议读取；自动生成的节点要带来源定位，仍需后续提取流程显式产出该元数据。
