编码前创建。

2. SQLite文档与GraphStore实现，独占文件、原子提交、版本和执行围栏。

## 完成记录（2026-09-13）

- 引入Persistence事务/记录/资产端口。auth/control/assets共用同一套业务规则；Mongo适配保持原集合、日期/ObjectId存储表示及原生事务。按ID、等值/包含筛选组织业务查询，SQLite没有Mongo操作符解释器。
- SQLite使用Node 24内置node:sqlite，没有新增数据库运行时依赖；新增@types/node 24仅用于类型检查。WAL/FULL/EXCLUSIVE，事务跨await期间排队隔离其他读写，提交后才发变化，退出释放OS锁；DB及WAL/SHM、凭据、资产按0600保存。
- SQLite GraphStore实现图版本、收据与产物同事务写入，保留最新租约而不覆盖续租；暂停在授权事务内撤租约，重新领取递增fence，旧持有人不得续租/提交/释放新租约。
- 本机消息通道只有一个消费端，无空闲工作轮询；SQLite提交驱动重新发现工作，启动补查未完成Run，忙租约用到期等待。Host共用领取/续租/释放/DSH逻辑，协作路径继续使用RabbitMQ。
- 共用HTTP/SSE及Activity，工作区/权限/资产变化广播；租约和纯writeFence变化不触发业务快照噪声。
- 新增local:serve：loopback API、一个Host、本机身份和默认工作区自动准备；Token不打印，connection.json指向0600的user-token文件。重启复用配置和身份；正常关闭排空Host，通知通道失效时关闭本机服务。模型/工具仍可联网，环境变量优先于秘密配置，自定义patch路径解析为绝对路径。
- 本机资产为不可变文件+SQLite元数据，导入导出/摘要校验/引用保护/未知提交结果保留文件的规则与协作模式一致。SQLite计数直接SQL处理常见标量查询；管理分页仍在业务层排序，大型工作区目录可后续下推游标，不影响授权和版本语义。
