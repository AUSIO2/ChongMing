# 058 — 封装与内联精简

本轮按实际调用次数和职责审计新后端及客户端传输边界，不把所有短函数视为冗余。目标是减少理解一条流程时需要跳转的地方，不增加通用框架，不改变公开业务协议。

## 修改范围

- 删除 storeDeleteConnection：仅 await connection.close()，没有策略或额外行为；同步所有调用方，直接使用 Mongo Connection 的公开方法，不保留别名。
- 内联 graphAssertRevision：仅一个调用点，版本比较与原错误放回 dispatch，不删除 CAS 检查。
- 内联 apiReadDataQuery：仅一个路由使用的两字段解析放回该路由，保留对象白名单和字段校验。
- 内联 clientTrackSender：只在登记 IPC 调用时使用，销毁监听和中止逻辑放在登记处，保留每个 sender 只监听一次。
- 合并 apiCreateBridge 到 apiCreateGateway：先处理无桥的浏览器/异常桌面分支，桌面分支直接构建 adapter；AbortSignal 转换仍共享一次实现。
- 资产相关 HTTP 命令直接使用已有 assetsReadCommand，删除两份重复解析分支。控制命令解析器从 control-input 直接导入，去掉 control 的转发出口。
- 删除无引用的 PortableBundle 类型；保留必要的具体导入/导出 DTO。

## 保留理由

连接创建统一 Mongo 参数与就绪状态，事务函数保证 session 释放，租约函数封装领取/续期/截止时间，资产流函数统一大小和摘要校验。这些都有独立职责或多个调用点。输入解析、公开 DTO 投影与幂等回执也不因函数短而机械复制到各调用处。

GraphStore/Auth/Host/ClientGateway 是当前实际执行边界，删除它们会混合 HTTP、鉴权、存储和生命周期，并非更简单。本轮没有新增接口、类或兼容层，也不修改尚未清理的旧后端。

## 验证

沿用已有全量 HTTP、DSH、多 Host、资产导入导出、CAS、客户端和 IPC 测试。为内联后的 sender 生命周期补充同窗多请求只监听一次、销毁全部中止的回归；类型、构建和文档检查。统计实际移除函数与生产代码净行数。
