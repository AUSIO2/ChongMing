# 065 — 独立本机运行

独立模式不连接其他重明实例，模型和外部工具照常联网。需要Node.js 24+，使用Node内置SQLite；不需要安装或启动MongoDB、RabbitMQ、Docker。Node 24可能输出SQLite实验性API提示，不影响运行。

## 启动与连接

安装项目依赖后执行：

```bash
npm run local:serve
```

默认只监听127.0.0.1:4320，数据目录为当前项目的.chongming-local。启动自动准备SQLite、共享配置、本机用户和工作区，再启动API和单个DSH Host。再次启动复用原用户、Token、工作区与配置，不覆盖已保存数据。

可显式指定目录与端口：

```bash
npm run local:serve -- --directory /absolute/path/to/local-data --port 4321
```

启动输出baseUrl、connectionPath及tokenPath，不打印Token值。桌面连接baseUrl，使用tokenPath文件内的用户Token登录。CLI可直接使用：

```bash
npm run headless -- read workspace.list --url http://127.0.0.1:4320 --token-file .chongming-local/user-token
```

浏览器开发预览仍使用固定同源代理：

```bash
CHONGMING_GRAPH_API=http://127.0.0.1:4320 npm run dev:web
```

模型密钥可放启动环境或现有.chongming-host秘密配置，环境变量优先。模型/provider/提示词/工具声明在管理工作台配置；自定义DSH插件可用--patch绝对或相对文件路径。这里只是不与其他重明协作，没有离线模型限制。不要在本机模式另起host:serve；它是RabbitMQ协作Host入口。

## 文件与生命周期

本机 CLI/桌面用户直接编辑、启动、暂停、继续、取消和审核，无需领取或续租客户端租约。`app.bootstrap.metadata.clientLeases` 为 `none`。编辑和启动仍携带 branch proof，运行中的范围不开放普通编辑。Host 内部的 Work 授权和防重复提交由系统自动维护。按用例操作见 [CLI 使用手册的本地模式分支](./077-CLI使用手册.md)。

- chongming.sqlite及其WAL/SHM：业务图、用户、配置、资产元数据及租约。
- assets/：不可变资产文件。
- dsh/：Host的模型运行目录；业务续跑不依赖恢复模型上下文。
- connection.json：本次服务地址及用户Token文件路径。
- user-token：本机用户登录凭据；新建数据目录权限0700，凭据/数据库/资产文件0600。

SQLite采用WAL、FULL同步和操作系统独占锁，同一目录只能由一个重明服务进程打开；不要将这个文件作为多Host共享数据库。端口占用或数据库已打开会明确失败。

Ctrl+C正常关闭Host、API和SQLite，保留数据。客户端退出不会停止服务；停止服务会排空模型执行并释放租约，下一次启动从业务状态发现未完成工作。崩溃后未提交事务回滚，已接受产物保留；未过期的旧租约仍被尊重，到期后以更高fence重新领取。暂停状态保持，不因重启自动解除。

备份时先停服务，再复制整个数据目录；恢复也在服务停止后使用完整目录，包含数据库和资产。不要运行中只复制主sqlite文件、遗漏WAL或assets。当前不提供Mongo到SQLite的自动转换；当前格式的图/工作区可通过现有导出/导入交换业务数据，不导入可执行Run。

## 验证与交付边界

```bash
npm run test:local
node --import tsx tests/client/ui-fixture.ts --sqlite
```

test:local直接使用临时SQLite及确定性模型夹具，不启动Mongo/Rabbit；完整npm test仍测试Mongo/Rabbit协作模式，因此仍需要测试broker。SQLite和Mongo共用身份/配置/资产/Graph规则，仅持久化和通知传输不同。

本阶段交付独立服务启动命令。Electron安装包仍是客户端，尚未包含Node 24服务运行时或自动启动/退出托管界面；后续在此运行入口上接入，不重新实现业务调度。
