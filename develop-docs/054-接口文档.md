# 054 — 新后端完整接口

本文件记录054阶段。055已加入用户认证、真实Workspace和共享配置，公开run.start不再接收configuration；当前接口见[055-接口文档](./055-接口文档.md)。

这是 054 阶段 `backend/` 当前实现的接口，替代 053 的无租约执行接口。052 中的架构仍包含后续阶段；旧 Mapper/IPC 不适用此文档。权威类型：[contracts/graph.ts](../contracts/graph.ts)。DSH 通用运行时接口保持不变，见 [README](../README.md)。

## 地址与约定

图服务默认 `http://127.0.0.1:4320`。全部 POST 使用 `Content-Type: application/json`，请求体最多 1 MiB。未知字段、错误类型、无效枚举会被拒绝。Map、节点、边、Run、Review、公开 requestId 使用 UUID；operationId、proposalId、reportId 是服务端生成的不透明字符串，不按 UUID 解析。

开发工作区固定 `workspace:development`。版本从 0 开始。图修改通过 Map 的 `expectedRevision` 做 CAS，每次成功写入增加 1。相同 requestId 与相同输入重放不重复写入，返回当前快照；同一 requestId 改内容返回 409。活动 Run 期间禁止 graph.apply 和 map.delete，先取消 Run。

## 公开端点

| HTTP | 地址 | 用途 |
|---|---|---|
| GET | `/health` | 返回 `{"ok":true}` |
| POST | `/api/v1/query` | 读取图 |
| POST | `/api/v1/command` | 修改图、Run 与 Review |

query 请求为 `{method,params}`。command 请求为 `{requestId,method,params}`。

成功包络：`{ok:true,requestId,replayed,data}`。query 的 replayed 为 false。首次 map.create 返回 201；其余成功返回 200。命令的 data 为 `{snapshot,createdNodeIds,createdEdgeIds}`，map.delete 例外返回 `{mapId,deleted:true}`。

错误包络：`{ok:false,requestId,error:{code,message,retryable,currentRevision?}}`。5xx 的 retryable 为 true；409 应先重新读数据，处理冲突后使用新 requestId；传输失败可重发原请求。

### 方法表

| method | params | data / 行为 |
|---|---|---|
| `map.list` | `{workspaceId}` | `[{id,workspaceId,revision,name,nodeCount,claimCount,updatedAt}]` |
| `map.get` | `{mapId}` | GraphSnapshot |
| `map.create` | `{workspaceId,expectedRevision:0,id,name}` | 新空图，snapshot.revision=0 |
| `map.delete` | `{mapId,expectedRevision}` | 软删除，活动 Run 时 409 |
| `graph.apply` | `{mapId,expectedRevision,changes}` | 原子修改节点、边、名称 |
| `run.start` | `{mapId,expectedRevision,id,targetId,mode,configuration?}` | targetId 必须是 Claim；一个 Map 同时一个 Run；id 不可复用 |
| `run.cancel` | `{mapId,expectedRevision,runId}` | 标记 cancelled，后续新提案拒绝 |
| `review.update` | `{mapId,expectedRevision,runId,reviewId,expectedReviewRevision,reason,slots}` | 只编辑 pending route Review；替换完整 slots，route/review revision 各加 1 |
| `review.answer` | `{mapId,expectedRevision,runId,reviewId,expectedReviewRevision,decision}` | decision=approve/reject；route 批准放行 worker，result 批准提交已保存的草稿；拒绝令 Run failed |

map.list/map.get 用 query，其余用 command。run.start.mode 是 `auto` 或 `human-in-loop`。run.start 保存状态；常驻 Host 自动发现并领取工作。审核 route 获批后，Host 自动继续处理未完成的角度。

### 图数据

GraphSnapshot：`{mapId,workspaceId,revision,name,nodes,edges,run,updatedAt}`。node：`{id,revision,data,createdAt,updatedAt}`。edge：`{id,revision,kind,from,to,createdAt,updatedAt}`。时间为 ISO 字符串。

node.data 为以下之一：

- news：`{kind:"news",content,context:{字段名:{value,visibleToAI}}}`。value 为字符串；DSH 仅能读到 visibleToAI=true 的 context 字段。
- claim：`{kind:"claim",content,category}`，category 为字符串或 null。
- verification：`{kind:"verification",score,reason,reportIds,opinions}`。score 为 0/0.5/1；opinions 为完整 GraphReport 数组，可直接回传编辑，不丢失出处。

edge.kind：`mentions` 为 news→claim；`verifies` 为 verification→claim；`related-to` 可关联任意两个不同节点。禁止悬空边、自环、改变已有节点种类。

changes：`{name?,nodes?:{put?:[{id,data}],remove?:[id]},edges?:{put?:[{id,kind,from,to}],remove?:[id]}}`。put 按 id 整体替换 data；删除节点同时删除关联边。不能同批 put/remove 同一 id，空 changes 无效。

### 自定义 Agent / Tool 配置

configuration 为 `{router,merger,agents,tools,maxSlots}`，Run 持久保存这份配置，不再读取后来修改的默认配置。

| 字段 | 类型与约束 |
|---|---|
| router / merger | GraphAgentProfile |
| agents | 1–64 个候选 GraphAgentProfile，路由只可引用这里的 id |
| tools | `[{name,description}]`，工具名唯一且对应 Host 已注册的真实工具 |
| maxSlots | 1–32 的整数；默认 8 |

GraphAgentProfile：`{id,name,description,content,tools,provider,model}`。id 在 router/merger/agents 间唯一；name 是显示名称；description 帮助路由选择；content 为实际 persona；tools 是允许使用的工具名称数组；provider/model 为 DSH 已注册 provider 与模型。不同 Agent 可以使用不同模型。自定义 endpoint/凭证在 Host 注册 provider 时配置，不写进图。

id、slotId、工具声明名称符合 `[a-zA-Z0-9_-]{1,64}`。profile.tools 必须属于 configuration.tools。`data_read/data_propose/data_delegate` 及原生 subagent/fork/workflow 等编排入口保留给运行时，不能作为自定义能力扩大权限。

配置只描述工具；实现通过可信 Host 的 DSH patch/plugin 注册。声明一个名称不会生成工具实现；执行器在运行前检查注册情况，缺失时报错。自定义 Agent 配置入口已在 run.start，独立资产管理 UI/CRUD 尚未接入。

示例（省略外层 requestId）：

```json
{
  "method": "run.start",
  "params": {
    "mapId": "00000000-0000-4000-8000-000000000001",
    "expectedRevision": 1,
    "id": "00000000-0000-4000-8000-000000000003",
    "targetId": "00000000-0000-4000-8000-000000000002",
    "mode": "human-in-loop",
    "configuration": {
      "router": {"id":"router","name":"路由","description":"选择适合陈述的角度","content":"读取任务并动态选择核查角度和Agent/tool，提交route后结束。","tools":[],"provider":"deepseek-official","model":"deepseek-v4-flash"},
      "merger": {"id":"merger","name":"汇总","description":"综合证据与分歧","content":"读取全部报告，给出结论并提交merge。","tools":[],"provider":"deepseek-official","model":"deepseek-v4-flash"},
      "agents": [{"id":"statistics","name":"统计核查","description":"核对统计口径、比例和时间段","content":"按批准的角度核查并提交本slot报告。","tools":["ledger_query"],"provider":"deepseek-official","model":"deepseek-v4-flash"}],
      "tools": [{"name":"ledger_query","description":"查询可信统计资料库"}],
      "maxSlots": 4
    }
  }
}
```

同一个候选 Agent 可以承担多个不同角度。上例需要 Host 实际注册 ledger_query；也可以省略整个 configuration 使用默认配置。

## Run 与审核数据

Run：`{id,mode,status,configuration,operation,error?,createdAt,updatedAt}`。error 为 `{code,message,workId}`，Host 执行失败时保存可公开的简短原因。status 为 running/waiting/completed/failed/cancelled。

operation：`{id,kind:"verify",targetId,status,inputRefs,route,reports,draft,review,resultNodeId}`。inputRefs 为 `[{id,revision}]`，绑定 Claim 与关联新闻版本。route/draft/review/resultNodeId 初始为 null。

route：`{revision,reason,slots,approved}`。slots 是动态数组，长度 1..maxSlots，slot.id 唯一。每项 `{id,agentId,angle,priority,hint,tools}`；priority=high/medium/low；angle 为非空核查角度；hint 可空；tools 必须是该 Agent 白名单的子集。批准后不再修改路由；重做使用新 Run。

GraphReport：`{id,slotId,agentId,agentName,angle,tools,routeRevision,score,reason,createdAt}`。Agent 身份、角度、允许工具由服务端按冻结的 slot 填写；tools 表示授予的工具，不表示每个工具都实际调用过。实际调用记录属于 DSH 日志。

draft：`{id,routeRevision,reportIds,score,reason}`。merger 必须精确引用全部批准 slot 的报告，代码不投票、平均或重算 score。

review：`{id,kind,revision,state,decision,createdAt,answeredAt}`。kind=route/result，state=pending/answered，decision 初始 null。人工模式先审 route，再审 result；前端根据 kind 展示 route 或 draft。result 批准提交保存的 draft，不能在 answer 中传临时结果。

终结 Run 在开始下一 Run 时保存在数据库 runHistory；当前 map.get 只返回最新 Run。历史 verification 节点保留报告意见，独立 Run 历史查询端点尚未实现。

## Host 自动执行

启动图服务后，启动一个或多个 Host。各 Host 共用同一 Mongo，或者连接同一个受信图服务。公开服务仍绑定 loopback；跨机器部署可在各机器启动连接同一 Mongo 的本机图服务，Host 使用本机接口。不要把当前无用户鉴权的公开接口直接暴露到互联网。

```bash
# 所有参与的图服务使用相同 CHONGMING_MONGO_URI；与本机 Host 使用相同 CHONGMING_DATA_TOKEN。
npm run graph:serve
npm run host:serve -- --host-id host-a --dsh-home /absolute/path/to/host-a \
  --patch /absolute/path/to/custom-tools.patch.yml
# 另一个终端/机器
npm run host:serve -- --host-id host-b --dsh-home /absolute/path/to/host-b \
  --patch /absolute/path/to/custom-tools.patch.yml
```

不指定 host-id 时每进程使用新的 UUID；默认 DSH 目录为 `.dsh-runtime/hosts/<hostId>`。各 Host 使用独立目录，并部署所需的相同 Agent provider/tool 插件及其凭证。Host 每次执行一个工作项；不同 Host 可同时领取同一 Claim 的不同 slot。候选工具部署不一致会明确失败，本阶段未实现按 Host 能力匹配。

| 配置 | 默认 | 用途 |
|---|---|---|
| CHONGMING_MONGO_URI | mongodb://127.0.0.1:27017/chongming_graph | 图服务数据库 |
| CHONGMING_GRAPH_PORT | 4320 | 本机图服务端口 |
| CHONGMING_LEASE_MS | 15000 | 图服务发放的租约时长，100–300000 ms |
| CHONGMING_DATA_TOKEN | 必填于 Host；图服务缺失时拒绝内部请求 | 可信 Host 的认证 |
| CHONGMING_DATA_API / --data-api | http://127.0.0.1:4320 | Host 使用的图接口 |
| CHONGMING_HOST_ID / --host-id | 随机 UUID | Host 实例标识 |
| CHONGMING_DSH_HOME / --dsh-home | 按 Host ID 的独立目录 | DSH 持久文件目录 |
| CHONGMING_HOST_POLL_MS / --poll-ms | 1000 | 空闲轮询间隔 |
| CHONGMING_HOST_REQUEST_TIMEOUT_MS / --request-timeout-ms | 5000 | 内部 HTTP 超时 |
| --map-id / CHONGMING_MAP_ID | 全部可运行 Map | 限定领取一张图 |
| --patch | 可重复 | Host 可信插件/provider patch |
| --cwd / --process-cwd / --dsh-bin | 执行器默认路径 | 工作目录、子进程目录、DSH CLI 路径 |
| --max-tokens / --max-rounds | SDK默认 / 3轮 | 本项模型预算与未产出时的跟进上限 |

`hostCreateWorker(input)` 是代码入口，见 [backend/host.ts](../backend/host.ts)，返回 `{hostId,start(),close()}`。start 启动后台循环；close 停止领取，Abort 当前工作，等待 DSH 真实退出后释放租约。续租约为 leaseMs/3；使用单调时钟保守截止时间，失去续租确认立即停止该项。

原 `dsh:verify` 无授权命令与 `dshRunVerification` 已删除。内部 `dshRunWork({grant,dataApiUrl,token,dshHome,signal?,...})` 仅执行已领取的一项，返回 `{workId,mapId,runId,operationId,sessionId,status:"accepted",finalResponse}`；不会自行领取或更换 grant。worker/merge 都是自己的 DSH 进程根 Agent。已接受产物直接返回，不重复模型调用。所有新业务写入都带固定 grant。

## 内部工作接口

POST `/internal/v1/work`，认证头 `Authorization: Bearer <CHONGMING_DATA_TOKEN>`。请求 `{method,params}`，成功返回 `{ok:true,data}`。错误使用同一 GraphFailure 包络。Host token 认证可信部署，本阶段没有用户/租户权限管理。

| method | params | data |
|---|---|---|
| claim | `{hostId,holderId,mapId?}` | GraphWorkGrant 或 null（暂时无可领取工作） |
| read | `{mapId,workId,holderId,fence}` | `{workId,status:"ready"|"accepted"}`；跨Run确认已接受收据，未接受的工作要求有效grant |
| renew | `{mapId,workId,holderId,fence}` | 原授权的新 expiresAt；失效返回409 LEASE_LOST |
| release | `{mapId,workId,holderId,fence}` | `{released:boolean}`，只释放匹配代次，不改变Run |
| fail | `{mapId,workId,holderId,fence,message}` | `{failed:boolean}`；有效持有者将尚未完成的Run置failed；已接受工作不误标失败 |

holderId 是每次claim调用新生成的 UUID；Host不并发重试同holder，claim不承诺全局请求幂等。未收到grant就不执行，响应丢失的未知租约到期回收。不要把某次 grant 改成新 fence 来提交旧工作。message 非空、至多1000字符，Host 默认只保存通用原因，详细错误写 Host 日志。hostId 至多128字符。fence 是正安全整数。

GraphWorkGrant：`{mapId,runId,operationId,workId,actor,routeRevision,hostId,holderId,fence,expiresAt,leaseMs}`。actor 为 `{role:"router"}`、`{role:"worker",slotId}` 或 `{role:"merge"}`。workId 等于稳定 proposalId，不包含 fence；路由角色 routeRevision=0，其余角色绑定批准的 route revision。

工作资格从已有事实推导：无route时领取router；批准后领取尚无报告的slots；报告齐全后领取merge；waiting/cancelled/failed/completed不产生新工作。续租和释放不增加图revision。Mongo服务器时间决定过期；租约存在不代表工作还需要执行，已接受产物优先。

Mongo连接使用primary读取、majority写确认和5000 ms写确认超时。Host暂时无法访问数据接口时保留已接受进度，不将网络故障写成模型执行失败；停止本项后允许重新领取。模型执行本身最终失败仍会将Run置failed。

leases单独保存在Map文档顶层，普通查询不包含它。报告提交只更新业务字段，并在同一次Mongo更新中验证未过期的holderId/fence，避免覆盖别人的续租。并发角度报告遇到版本冲突只重试原提案的数据库接受，不重跑模型。崩溃后租约过期，其他Host用新fence继续；外部工具未提交前的计算可能重做，不承诺工具副作用恰好一次。

## DSH 数据桥接

POST `/internal/v1/data/read` 与 `/internal/v1/data/propose` 除 Bearer token 之外，必须带：

```text
x-work-id: <grant.workId>
x-work-holder: <grant.holderId>
x-work-fence: <grant.fence 的十进制正整数字符串>
```

角色、slot和operation从已保存grant解析；旧 x-dsh-role/x-dsh-slot 不能授权执行。模型工具参数不含这些身份头。

### data.read

请求 `{mapId,operationId}`，返回 `{ok:true,data:GraphDataRead}`。

GraphDataRead：`{mapId,runId,operationId,claim,context,configuration,route,reports,draft,review,phase,proposalId,work}`。claim为完整Claim节点；context为 `[{id,content,context}]`，排除不可见上下文。phase=route/workers/merge/waiting/done 表示整个operation阶段；done表示终态，是否成功看公开run.status。

work 为 `{id,actor,routeRevision,status:"ready"|"accepted"}`，表示本执行器自己的工作。单个worker报告接受后可结束，其他slot可以仍在运行。租约字段与内部token不会交给模型。

### data.propose

共同字段 `{mapId,operationId,id,kind,reason}`，id来自本grant的workId。按kind增加：

| kind | 额外字段 | 条件 |
|---|---|---|
| route | `{slots}` | router授权、尚无route |
| report | `{routeRevision,slotId,score}` | 本slot的worker授权、批准版本一致 |
| merge | `{routeRevision,reportIds,score}` | merge授权、精确覆盖全部批准slot报告 |

返回 `{ok:true,data:GraphSnapshot}`。已接受的相同内容可确认重放；相同id修改内容返回409。未接受的过期/被接管授权返回LEASE_LOST。换新Run后旧授权不能新增结果。所有新写入最终都经数据库fence与状态校验，不能靠先读后写绕过取消。

DSH只注册 `data_read` 和 `data_propose` 两个业务工具，并给该角色授予冻结的自定义工具白名单。router提交route后结束；各slot由Host领取，DSH用对应profile执行。原 data_delegate 已删除，以保证同图跨Host执行都经过领取。原生DSH AgentLoop、模型provider、工具执行和上下文管理继续复用。

## 主要错误与当前边界

| HTTP | code 示例 | 含义 |
|---|---|---|
| 400 | INVALID_JSON / INVALID_ARGUMENT / INVALID_CONFIGURATION / UNKNOWN_METHOD | 请求或配置错误 |
| 401 | UNAUTHORIZED | 内部 token 缺失或不正确 |
| 403 | FORBIDDEN / ROLE_NOT_ALLOWED / SLOT_NOT_ALLOWED | 未绑定的角色或越权 slot |
| 404 | MAP_NOT_FOUND / RUN_NOT_FOUND / OPERATION_NOT_FOUND | 目标不存在 |
| 409 | REVISION_CONFLICT / IDEMPOTENCY_CONFLICT | 版本或重复请求冲突 |
| 409 | RUN_ACTIVE / RUN_ID_REUSED / RUN_NOT_ACTIVE | Run 生命周期约束 |
| 409 | LEASE_LOST | 租约到期、被接管、Run取消或已切换 |
| 403 | WORK_SCOPE_MISMATCH | 提案不属于该工作授权 |
| 409 | ROUTE_NOT_APPROVED / REVIEW_CONFLICT / REPORTS_INCOMPLETE / PROPOSAL_CONFLICT | 提案或审核不满足当前阶段 |
| 410 | MAP_GONE | 图已删除 |
| 413 | PAYLOAD_TOO_LARGE | 请求超过 1 MiB |
| 422 | UNKNOWN_AGENT / TOOL_NOT_ALLOWED / INVALID_ROUTE / INVALID_RUN_TARGET / INVALID_RELATION | 业务引用或路由无效 |
| 503 | WRITE_CONTENTION | 高频并发重试已耗尽，可稍后重发原提案 |

当前保持单 Map 文档CAS、单活动Run、单Claim verify。自动领取、同图多Host角度并行、失租停止、崩溃接管与HITL自动继续已在本阶段实现。用户鉴权、Agent/tool资产管理界面、parse/split、产品SSE与旧前端接线仍按后续计划推进。未承诺DSH SDK冷Session原样恢复；接管读取数据库业务进度，未接受的推理允许重做。
