# 116 仓颉证据图检查与报告导出

## 目标与范围

为重明新增一个实际参与演示的仓颉模块：读取完整图快照，检查证据关系的结构完整性，生成中文Markdown核查报告。用于2026仓颉杯创新原型赛道；交付后可据实说明“仓颉实现部分模块”。本模块不判断新闻真假，不重新调用模型，不改写图数据。

第一版完成命令行闭环。现有Node入口读取本地JSON或经公共客户端调用map.get，仓颉二进制完成解析、结构检查与报告生成，Node负责参数、认证、进程和输出文件。第一版不增加网页按钮、HTTP服务、数据库表或桌面安装包；这些是后续独立工作，避免为快速原型扩大交付范围。

## 当前依据

- contracts/graph-api.ts的GraphSnapshot：mapId、workspaceId、revision、name、nodes、edges、runs及运行控制元信息。
- contracts/graph.ts：节点id/typeId/typeVersion/payload、payloadReferences、libraryClaimRefs；边kind为successor/reference。
- resources/data-definitions/fact-checking.json：factcheck.news/claim/opinion/verification第一版类型；opinion.evidenceClaimIds引用事实，verification.opinionIds引用意见。
- client/graph-client.ts已有认证查询；apps/cli/main.ts的read输出是{ok:true,data}包裹，不等同于裸GraphSnapshot。
- 当前工作区存在大量其他未提交更改，新增独立目录；不重置现有修改，不将现有工作统一提交。

## 架构与文件归属

```text
本地快照文件 / 公共API map.get
              ↓
apps/evidence-audit/main.ts（Node读取与进程管理）
              ↓ UTF-8 JSON临时输入文件
apps/evidence-audit-cj（真实仓颉可执行程序）
              ↓ JSON结果，含中文Markdown
标准输出 / 新建报告文件
```

仓颉模块包含cjpm.toml、src/main.cj及按输入/检查/报告职责拆分的源文件、README和模块内构建产物忽略规则。Node入口只做适配，不复制仓颉检查算法；tests/apps/evidence-audit保存合成样例及进程集成测试。scripts下提供构建/验证入口，package.json仅增加相关命令。

SDK与扩展库在任务专用用户cache安装，使用匹配版本；不改全局shell配置，不把SDK提交到仓库。先验证JSON库可编译运行，再确定依赖与构建命令并回写实施记录。

## 输入与输出约定

仓颉读取裸GraphSnapshot JSON或保留所需核心图字段的投影。这里的“完整图”要求nodes/edges覆盖当前图，而非截取单个分支；不要求携带本模块不使用的运行元数据。Node的--input支持裸快照以及现有CLI成功响应{ok:true,data:快照}，显式拒绝失败响应和v4 Bundle。--map-id通过现有client.read('map.get')读取完整快照，沿用用户token认证，不向仓颉传递token。

只验证本模块使用的结构；不声称实现完整GraphSnapshot/JSON Schema验证。要求mapId、workspaceId、name、revision与nodes/edges存在且类型正确；版本号为非负安全整数（最大9007199254740991），接受等值的合法JSON数值写法；节点要求id、revision、typeId、typeVersion、payload；边要求id、kind、from、to。额外字段原样忽略。可选payloadReferences与libraryClaimRefs存在时校验所用结构。

仓颉输出单个JSON对象，包含protocolVersion=1、status、summary、findings、markdown。status为pass/warning/fail；输入不可解析或不符合基础结构时返回invalid及error。findings带稳定code、severity、message和可定位的nodeId/edgeId/path。报告内容与输入顺序稳定，不插入当前时间或随机ID；注明图ID、图版本及检查边界。

退出码：0表示检查完成且无结构错误（允许warning）；1表示检查完成但发现结构错误，仍输出完整报告；2表示输入或用法错误，不能出具有效报告；Node额外以3表示编译后二进制缺失、子进程超时/异常等执行故障，不伪装为检查成功。

Node参数：--input PATH 与 --map-id ID二选一；--url/--token-file仅用于API模式；--format json|markdown（默认json）；--output PATH可选，输出文件以新建方式写入，拒绝覆盖。二进制位置通过明确环境变量或模块默认构建路径解析，spawn不启用shell。限制输入和输出字节数并设置有限执行超时；进程资源与临时文件由入口finally清理。

## 检查规则

| 类别 | 规则 | 结果 |
| --- | --- | --- |
| 身份 | 节点ID重复、边ID重复 | error |
| 图边 | from/to不在当前快照节点集合中，或successor结构环 | error；reference环允许 |
| 节点引用索引 | payloadReferences.targetId缺失 | error |
| 事实核查引用 | v1结论opinionIds指向不存在节点或非v1意见；v1意见evidenceClaimIds指向不存在节点或非v1事实 | error；未来版本区分为未支持提示 |
| 基础字段 | 已支持v1类型的正文、分数、引用列表不符合本模块明确要求 | error |
| 未完成事实 | 由successor关系找不到对应核查结论 | warning，不能按结构损坏处理 |
| 外部证据库 | libraryClaimRefs | 保留引用说明并标注本次未解析外部库；不按本图缺失节点处理 |
| 未支持类型 | 未知typeId或已知类型的新typeVersion | warning，仅执行通用图检查，不套用v1业务字段 |

reference边和payload引用不参与“事实是否已有结论”的successor遍历。第一版不检查运行鉴权、租约、外部URL真实性、跨库内容正确性，不以producer缺失判定错误，不做依据文本真假推断。不依赖完整运行历史重建事实归属；关系歧义如有，保留并提示，不猜测。

## 报告组织

先说明结构检查结论与范围，再列错误/待完成/未验证事项；按输入顺序列新闻和事实、关联意见及结论，保留原有score与reason，所有值均标明为输入数据。正文中的Markdown特殊结构作安全转义，防止原始新闻内容伪装成报告标题或检查结果。列出未归属节点，避免静默遗漏。

## 验收与比赛材料

最低验收包括：正常中文样例通过并导出报告；断链样例精确指出目标；未完成事实只警告；跨库引用不误报本图断链；未知类型/版本不伪装为已完成业务验证；坏JSON/非法字段/重复ID可定位；相同输入两次输出一致；Node调用真实仓颉二进制，验证退出码、输入文件不变与输出拒绝覆盖。

已有111新闻演示工件是历史投影，缺少运行元数据和news.context等字段；本模块明确不依赖这些字段，直接核查其核心图字段，不伪装成完整业务Schema验证，不重新联网调用模型。验证结果按实际完成情况记录。只有真实仓颉编译、执行和Node接入验收通过后，更新报名表为“是（部分模块）”；声明保留现有TS/Vue/Node核心与本次新增模块的边界。
