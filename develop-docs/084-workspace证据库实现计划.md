# 084 workspace 证据库实现计划

日期：2026-10-06。状态：持续实现计划；089 已完成 Mongo 核心收录闭环，界面与后续接入待实施。前置工作见 [083 类型清理](./083-移除独立Evidence类型.md)，界面协作见 [082 双视图计划](./082-前端图工作台与阅读视图重构计划.md)。

## 1 目标与已确定需求

在 workspace 内建立可显式收录、检索和复用的 Claim 集合，为核查提供已有确定判断及其依据。库内记录与流程中的陈述共用 Claim 内容模型和原始身份，证据用途通过引用表达，不重新建立独立 Evidence 节点。

已确定的规则：

- 显式收录。用户或被明确授权的流程主动选择 Claim；不把全部 Claim 或全部核查结果自动入库。
- `confidence = 1` 表示该陈述完全正确，`confidence = 0` 表示该陈述完全错误。保留陈述原文；0 记录也按原文保存。
- 库只接纳数字 0 和 1，拒绝 0.5、其他数值、null 和字符串。库内判断固定，不随着来源图或后续核查更新。
- 保存收录人、收录时间、说明及判定依据；允许来源上游和自身核查下游为空，但必须有可解释的收录依据。
- 支持查询、匹配复用、上下游追溯、重复与冲突提示、撤回及历史引用保留。
- 支持固定证据集快照和导入导出，供 Sandbox 使用同一批材料回放。

本计划只确定实现路径。本轮不发布软件新版、不自动升级已保存定义、不迁移用户数据库；正式发布时与其他开发改动统一处理版本和迁移。

底层选型已确定为 MongoDB，读优先证据库沿用现有协作图服务的 Mongo 部署。条目、出处、使用关系、快照和收据使用独立集合，与图数据共用同一 Persistence/连接及事务会话。本阶段以 MongoDB 实现和验收为主；现有本机 SQLite 保留，其证据库适配作为可选后续工作，不承诺同步完成两个后端。

## 3 收录记录与不可变内容

### 3.1 同一 Claim 的收录快照

采用独立的库记录空间，不把全库数组嵌入 WorkspaceDocument。一个条目保存现有 Claim 的收录快照及固定判断；条目 ID 是收录身份，原 Claim 的 mapId/nodeId/revision 是陈述身份与版本。保存快照不会在目标图里创建另一份 Claim 或 Evidence 节点。

建议公共数据形状如下；这是待实施的契约，不是当前接口：

~~~ts
interface EvidenceLibraryEntry {
  id: string
  workspaceId: string
  revision: number                 // 管理状态版本，用于并发写入；不是内容版本
  claim: {
    origin: { mapId: string; nodeId: string; revision: number }
    type: { id: string; version: number }
    definitionDigest: string
    nodeSnapshot: GraphNode        // 原 Claim 身份、payload 和 producer 的只读快照
  }
  confidence: 0 | 1
  applicability: ClaimApplicability
  decision: { reason: string; basisRefs: ProvenanceRef[] }
  collectedBy: string
  collectedAt: string
  contentDigest: string
  status: 'active' | 'withdrawn' | 'superseded'
  statusReason: string | null
  replacementEntryId: string | null
}
~~~

`nodeSnapshot` 按原 Claim 的精确类型定义校验，confidence 是对该陈述的固定收录判断。两个位置都使用相同的陈述内容模型；不为库新增另一种事实 payload。来源没有核查结果时，收录人仍须明确给出 0/1 及理由。已有 Opinion.score 或 Verification.score 只能作为依据之一，不能由收录接口静默转换成固定真值。

为使固定判断始终作用于同一条陈述，收录时同时冻结内容、适用范围、判定依据和精确定义摘要。来源图后续编辑或删除不改变收录快照；库详情可以另行显示来源当前状态，但历史内容按收录快照读取。

### 3.2 适用范围与来源

ClaimApplicability 保存主体、事件、时间、地域和条件等用于检索及匹配的结构化描述。已知字段显式填写；未知字段保留未知，不把缺失时间解释为永久有效，也不凭空推断范围。首版允许人工填写及复用已有明确上下文。

ProvenanceRef 使用带种类的引用：图节点版本、库条目、附件或人工说明。图节点必须带 mapId/nodeId/revision；附件带 assetId/sha256；用户可选的 Source、News、Opinion、Verification 保存当时的内容快照和真实关系。完整原文仍由 Source/Asset 承载，不把整篇材料伪装成一个 Claim。

关键判定材料使用已保存的不可变 Asset。仅保存一个会变化的网页 URL 不足以复现依据；需要保存的 URL 正文沿用现有 SourceReader 访问、类型和大小限制，先在事务外采集、暂存，再在收录事务中校验和绑定。每份冻结的附件引用参与资产删除保护。

### 3.3 状态与纠错

内容、confidence、收录人和收录时间没有更新接口。管理 revision 只随状态变化递增。

- 取消收录或撤回：条目转 withdrawn，不参与后续默认检索和新选择，原 Claim、依据及历史引用继续可读。
- 纠正误收录：另建条目，并用显式替代动作把旧条目转 superseded；旧内容和旧 0/1 不变。
- 替代引用必须同属 workspace，目标存在，禁止自替代及替代链循环。
- 首版不物理删除条目、冻结内容和仍被引用的附件。Workspace 的访问和逻辑删除仍按现有规则执行。

相同原 Claim 版本、适用范围、判断和固定依据再次收录返回已有条目，不静默激活已撤回记录。更换依据时可以建立新的收录记录；更改陈述内容时使用新的 Claim 版本再收录，不覆盖旧记录。

## 4 上下游与引用模型

证据库管理 Claim 的收录关系；上下游属于具体陈述及其使用记录。

~~~mermaid
flowchart LR
  S[Source 原始材料] --> N[News 正文]
  N --> C[Claim 原始陈述]
  C --> O[Opinion 自身核查]
  O --> V[Verification 汇总]
  C -. 显式收录 .-> L[库内同一 Claim 的固定快照]
  L -. 只读依据 .-> O2[其他陈述的核查意见]
  C2[其他待核查 Claim] --> O2
~~~

| 关系 | 保留方式 | 对运行范围的影响 |
| --- | --- | --- |
| 来源上游 | 保存选定 Source/News 等版本与出处关系 | 不扩大新核查的结构写范围 |
| 自身核查下游 | 保存收录依据中的 Opinion/Verification；后续结果另记 | 不回写库内 confidence |
| 被其他核查使用 | 索引引用库条目的图节点版本、Run/Operation/Work 和时间 | 库是只读输入，目标图仍按原分支取得写授权 |

上下游查询同时说明哪些内容是收录时保存的快照、哪些是当前图可见节点、哪些是已删除来源。遍历设置深度、数量与 visited 集合，引用环不当作结构 DAG。超出范围返回分页或边界标记，不冒充完整证据链。

### 4.1 本图引用与库引用

保留 Opinion.evidenceClaimIds 表达当前 Map 内的 Claim。新增 `libraryClaimRefs: Array<{ entryId: string; contentDigest: string }>` 表达库内固定快照；管理 revision 不作为内容版本。库外引用不能直接塞进 evidenceClaimIds。

在 DataReferenceDefinition 中增加显式 workspace 只读数据目标，声明允许的 Claim 精确类型及引用对象形状。本图 node 和 asset 的解析规则保持清晰；新增种类只能由应用层注入的解析器访问对应 workspace 的库记录，不按任意 URL 取数。

Graph 核心通过通用的只读引用解析能力校验存在性、类型、摘要和权限，不依赖证据库模块的具体存储实现。人工新增或更换库引用要求条目 active；原有引用和历史读取允许解析已撤回条目的冻结内容，避免撤回导致其他无关图编辑失败。

正式图提交同时写入库使用索引。用户编辑意见移除引用时结束当前使用关系，保留先前节点版本的历史使用记录；重复请求和已接受 Work 重放不重复记账。消费者节点和核查目标的必要快照保证原图删除后仍能解释当时如何使用该条记录。

## 6 收录与查询接口

下表为目标方法，具体 TypeScript 签名在阶段 A 完成。所有写入沿用 requestId、expectedRevision、授权事务和幂等收据；读方法按 workspace 成员权限检查。

| 方法 | 主要输入与结果 | 最低角色 |
| --- | --- | --- |
| evidence.collect | Claim 精确版本、0/1、范围、理由及选定出处；返回条目和重复/冲突信息 | editor |
| evidence.get | entryId；返回固定内容、状态和出处摘要 | viewer |
| evidence.search | workspace、关键词、0/1、范围筛选、游标和 limit；返回轻量条目摘要 | viewer |
| evidence.match | 待核查 Claim、范围和候选上限；返回匹配候选及匹配依据 | viewer |
| evidence.relations | entryId、方向、深度和游标；返回来源/核查/使用关系 | viewer |
| evidence.withdraw | entryId、预期管理版本和理由；返回状态 | editor |
| evidence.supersede | 旧条目、替代条目、预期版本和理由；原子建立替代关系 | editor |
| evidence.snapshot.create/get | 选定条目或已确认筛选范围；建立/读取固定清单 | editor 创建，viewer 读取 |
| evidence.export/import | 固定快照或库包；返回数据包/导入映射及冲突报告 | viewer 导出，owner 导入 |

### 6.1 完整收录事务

收录动作在一次事务中完成：授权并取得现有写入身份 → 核对 requestId、method/inputHash 与已接受收据 → 合法重放返回原结果 → 仅新请求校验 Claim 类型/版本、0/1、范围和选定出处 → 检查精确重复 → 保存固定内容、出处、索引和收据 → 提交后通知。关键来源在提交前再次验证 revision；收录只读原图，不修改其分支，但仍按事务快照验证来源一致性。成功后来源编辑或删除、条目撤回不改变合法重放的结果。

置信度无默认值，不补 0.5 或根据模型 score 猜测。附件采集、网络和模型调用在事务外；提交结果不确定时沿用现有暂存资源保留规则，不能清理可能已经被条目引用的字节。

### 6.2 有界查询与重复判定

首版采用精确指纹、结构化筛选和关键词词项索引。规范化只处理明确的文本格式差异，保留数字、单位、否定词和条件。范围摘要参与陈述指纹；缺失范围与已知范围不自动判为相同。语义检索可后续追加，不作为首版持久化正确性的前置条件。

精确重复键绑定 workspace、原 Claim 身份/版本、范围摘要、confidence 和固定判定依据摘要；数据库唯一约束处理并发收录。同一 Claim/范围/0或1 使用不同依据可以另建条目。相同陈述不同来源提示可能重复并保留出处，不自动丢弃来源。相同陈述及范围出现相反 0/1 时返回冲突标记，保留双方记录，由显式撤回或替代动作解决。

查询在 Mongo 端筛选、排序和 LIMIT，禁止使用 `list({workspaceId}).filter(...).slice(...)` 作为分页。Mongo 建真实复合索引，列表按需投影摘要；后续若适配 SQLite，须建立对应的 SQL 索引/词项表，不能只调用目前会忽略非唯一索引的通用 index 方法。

建议初始上限：每页默认 25、最多 100；一次 match 最多 50 个候选；一个 Operation 选择的库条目最多 32。上限是工程初值，阶段 B 用样本验证后在原计划更新。游标绑定 workspace、查询条件及库读取版本；跨页变更返回明确的游标过期结果，避免静默重复或遗漏。

## 7 核查执行与引用冻结

首版链路为“检索候选 → 显式选择 → 启动核查”。UI 或明确授权的编排流程给核查步骤提供库条目集合；普通 Agent 不直接扫描实时全库或自动收录结果。

1. 扩展有限计划的只读库上下文绑定，明确 selected entry refs 或固定 snapshotId。
2. 实时选择的 Operation 建立时校验条目 active、同 workspace、类型与摘要匹配，冻结原 Claim 快照、confidence、范围、判定依据及精确定义。明确指定历史 snapshotId 的回放按固定清单校验，允许清单中后来撤回的成员。
3. 冻结集合及其摘要纳入 ExecutionSpec/specHash；恢复、重试、Host 接管和历史复用都比较这份集合。固定快照成员不同不能复用旧产物。
4. GraphDataRead 的库上下文使用明确 DTO 返回这份获权快照，不假装库条目存在于本图 nodes。Claim schema 与投影继续由其精确定义控制。
5. 核查提示词读取固定陈述、0/1 和依据，提交 libraryClaimRefs 及使用理由；服务端只接纳本 Work 已获权集合中的引用。已冻结 Work 的发布检查固定集合和当前执行权限，不重新要求成员 active。
6. 产物接纳仍验证目标图的 holder/fence、branch proof、当前 Work 和收据；库读取授权独立于目标图写范围，不把其他 Map 纳入 successor 闭包。
7. 条目在冻结后撤回时，已冻结 Operation 继续读取原内容，历史展示其后续撤回状态；新 Operation 不再选择它。Workspace 撤权、Run 暂停等沿用现有执行授权规则。

历史库快照可供 Sandbox 显式回放；该模式需要指定 snapshotId 并标明读取的是历史清单，不能把历史成员混进实时默认搜索。库中的 0/1 直接属于其陈述；如何匹配目标和形成核查意见仍由核查过程说明。

## 8 快照与数据交换

快照是不可变条目清单，保存 workspace、snapshotId、条目 ID/contentDigest、必要定义/出处/资产清单、创建人和清单摘要。条目状态变化不修改已创建快照；当前访问仍检查 workspace 权限。内容按分页读取，不把整个库和全部正文放进一个 HTTP 响应。

独立库包携带选定快照及必要依赖。导入到目标 workspace 时为条目、图、节点和附件建立明确映射，保留 importedFrom 出处；包外 mapId/nodeId 只作为原始身份标签，不取得源工作区访问权限。导入不会把 0 改成 1，也不会把错误陈述改写成否定句。

现有 v4 图/工作区包不包含库闭包，不能仅加若干外部 ID 就声称已经可移植。阶段 F 增加明确的库包及组合包格式：组合包携带图/工作区内容与被实际引用的库条目、快照、精确定义和资产闭包；既有纯 v4 路径继续处理原格式。最终格式标识和版本在阶段 A 冻结，软件发布仍与其他改动统一安排。

导入先校验包内原始引用、摘要、数量、0/1 与闭包完整性，再暂存附件和分配目标身份。contentDigest 覆盖规范化固定内容与其依赖身份；导入重映射身份后重算目标摘要，并建立旧 entryId/contentDigest 到新 entryId/contentDigest 的映射，重写意见库引用、依据、快照清单和使用索引。引用目标摘要单独校验，不递归参与本条目摘要，阶段 A 固定规范化规则，避免引用环造成摘要无法重算。

最后在一个事务中发布库记录、图、资产保护/使用索引和收据。重放返回相同映射；冲突保留双方数据并返回报告，不覆盖固定判断。导出闭包覆盖被选中的撤回或替代条目的历史依据及附件。超限包要求缩小快照范围，不静默截断材料。

## 9 界面与全工作区浏览

按用户“证据库和 Map 差不多就行”的要求，证据库在 workspace 侧栏作为与 Map 并列的固定入口，沿用 Map 的图浏览、选中节点、右侧详情、双击进入单页和返回定位。默认呈现与 Map 相同的三维画布，缩放、旋转、聚焦与键盘交互共用已有展示组件；关键词/范围/0或1筛选放在现有工具栏位置。列表用于检索与定位，主浏览仍是图和单页。

库节点呈现收录时的 Claim，标注固定 0“确定错误”或 1“确定正确”；详情和单页沿用现有内容排版，补充范围、收录理由、依据、出处与库状态。收录、撤回、替代及重复/冲突提示沿用 Map 工具栏和对话框交互。撤回条目在显式历史浏览时置灰，旧身份与固定内容保留。

来源 Claim 详情提供“收录到证据库”，表单显式填写 0/1、理由和范围；已有核查仅提供可选依据。库详情显示收录时内容及来源当前状态，两个版本清楚区分。退出库的动作解释其历史保留含义。

核查界面增加证据选择，展示待使用的库条目及摘要；意见详情可回到被引用的固定版本。UI 只通过公共 client/session 访问，不自建库副本或直接操作数据库。

082 的三维 Map 与单页共用库摘要、关系和详情接口。展示层接收节点、连线、选择和打开事件，由 Map 与库各自提供数据；库读取 evidence.search/evidence.get，使用条目 ID 及 workspace/原 map/node/revision 保留收录身份，单页打开固定快照。共用展示组件不要求库构造普通 GraphSnapshot 或取得图编辑租约。

上下游沿用 Map 的节点和连线表达，来源、自身核查及被使用关系来自实际关系接口。当前四个核心 API 没有关系查询，首轮界面先完成收录节点浏览、筛选和固定详情，再接入真实上下游。初次加载只读摘要与受控邻域，明确已加载数和关系边界；总数由实际统计接口提供，分页结果不冒充完整全库。

## 11 验证与交付条件

重点回归：

- 0 和 1 均能收录；其他值和无依据输入被拒绝；字段更新接口不能修改固定内容或判断。
- 原 Claim 后续变更、来源图删除、库条目撤回后，历史读取保持原文及 0/1；附件删除受库依赖保护。
- 重放、并发重复、不同依据另建条目、相反判断冲突、错误预期 revision、替代循环和跨 workspace 操作有稳定结果；来源变更/删除或条目撤回后合法重放仍返回原结果。
- 人工库引用、Work 库引用及导入引用的权限、类型和摘要均校验；目标 Map 分支与库读取分开验证。
- 冻结后撤回仍可按获权内容发布，撤回后可按明确指定的历史快照重新回放；暂停恢复、Host 接管、重复提案与候选发布保持材料和引用一致，使用索引没有重复或缺失。
- 快照和包缺失依赖、摘要不符、身份重映射失败时拒绝发布；未知提交结果不损坏附件，重复导入返回原映射。
- Mongo 游标无重复/遗漏，查询计划使用真实索引；响应遵守现有 16 MiB 上限，超限明确拒绝或分页。

容量复用 082 的工作区测试阶梯：1,000/10,000、10,000/50,000、50,000/200,000 的节点/关系样本，另记录实际入库 Claim 数、词项数量、选定快照大小和峰值内存。原稿的 100,000/500,000 用作扩展压力测试。以上是工程目标，未作为已测容量。

实施后按范围执行生产源码类型检查、受影响测试类型检查、架构/消息边界、Mongo 集成、DSH 核查、公共客户端、数据包与桌面运行验证。双视图、导入导出和 Sandbox 人工验收记录实际环境、数据量和操作结果；正式发布前执行整体构建/回归并统一版本与迁移方案。

交付时至少跑通：从一条 Claim 显式收录 0/1 → 在另一张 Map 检索并选用 → 产生获权意见及固定库引用 → 查看出处和使用记录 → 撤回后旧核查仍可读、新选择排除 → 固定快照导出导入后身份映射正确。
