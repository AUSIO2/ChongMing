# 114 — 画布布局全面审计

本轮检查现有主Map、证据库Map、单页、外壳、拖动、提示与渲染尺寸链路。只做审计与隔离测量，没有修改产品实现或发布线上；临时浏览器测量代码已从tests目录移除，源代码与几何工件保存在`test-results/114-canvas-layout-audit`。此前113的保存提示修复保持。

## 结果与证据强度

发现7项确认问题：5项由真实页面/后端测量确认，2项由现有计算公式复核确认。失焦拖动、SVG键盘焦点、分页状态和极窄单页另列风险，不冒充已复现问题。浏览器测量脚本完成不表示布局通过，其作用是记录下列失败行为。所有请求仅到隔离SQLite/Mongo后端，没有真实模型调用或生产数据写入。

### L01：选中不同类型会让主工具栏改变高度（优先）

- 位置：`apps/ui/views/WorkspacePage.vue`的`selectedClaim`收录按钮；`apps/ui/components/shell/WorkspaceViews.vue:61–95`。
- 原因：收录按钮按节点类型出现，toolbar只设min-height；view-switch和内容仍能被压缩换行。响应式只依据窗口宽度，不依据扣除两侧栏后的实际画布宽度。
- 实测：1280px窗口，选新闻时工具栏44.5px，选事实64px，画布上边缘从132.5变152px，高度减少19.5px。1000px窗口同一操作可从44变77.5px，差33.5px。此变化不依赖偏好保存横幅。
- 最小修复：稳定工具栏高度，视图切换不压缩换行；按钮保持单行，在有限工具区内横向滚动或收进更多菜单。图名/计数按实际容器空间收缩或隐藏。
- 先行用例：选新闻→事实→意见，分别在1280、1000px及较宽侧栏下比较工具栏和canvas bbox；所有操作仍可触达。

### L02：左右侧栏没有共同宽度预算，缩窗可遮住画布（优先）

- 位置：`usePanelResize.ts:78,96`的左右独立上限；`AppShell.vue:133–135`的中心最小宽度。
- 实测：1440px下正常拖到左400、右520，随后缩到1000px，中心与右侧区域重叠128px。html宽仍为1000px，不能只检查页面是否有横向滚动条。
- 最小修复：按可用宽度共同分配两侧栏与中心最小空间，在恢复偏好、拖动、窗口变化和右栏显隐时使用同一规则；区分用户偏好宽度与当前有效宽度。
- 先行用例：真实拖到较大侧栏→缩到1000/901px→恢复，检查center/right bbox不重叠、画布在中心内、缩窗不破坏用户原偏好。

### L03：701–900px分隔条仍能保存不可见的宽度变化

- 位置：`AppShell.vue:186–189`固定180/280宽，分隔条仍调用`usePanelResize`。
- 实测：800px下拖左分隔条，左栏实际宽度前后均180px；扩大到1100px后，隐藏保存的340px才应用。
- 最小修复：此范围隐藏无效分隔条，或让响应式和拖动共同使用有效宽度，避免保存界面未展示的结果。
- 先行用例：800px下分隔条应隐藏或确实改变可见宽度；扩大窗口不突然应用用户未看到的拖动结果。

### L04：证据库首次选条目/清选择会新增、删除关系状态行（优先）

- 位置：`EvidenceLibraryView.vue:163,184`的`relations-status`。
- 实测：1440px下库画布高度676px；选条目进入真实关系读取时变644.3125px，完成后仍为644.3125px；清选择恢复676px。约31.7px差来自条件插入的状态行。本例只收录一个孤立事实，排除了邻域节点增长的干扰。
- 最小修复：关系状态放固定状态区或覆盖层，详细警告放详情或区域内部滚动；普通读取文案不增减画布布局行。
- 先行用例：真实`evidence.relations`回包挂起，检查选择前、读取中、完成和清选择四阶段几何；另测长警告不改高度。

### L05：证据库检索按钮文案变化会使筛选栏多折一行（优先）

- 位置：`EvidenceLibraryView.vue:159–160,185`，`search-toolbar`可换行，按钮自然宽度随“检索/检索中…”改变。
- 实测：1220/1230px窗口，中栏692/702px，筛选栏正常72px，检索中112px，完成恢复72px，画布同步减少再恢复40px。1240px以上本次没有出现，说明是临界空间问题。
- 最小修复：按钮宽度稳定；筛选布局根据实际容器响应，普通loading不改变行数。无需改查询协议。
- 先行用例：挂住真实`evidence.search`回包，在临界中栏宽度比较前/中/后筛选栏与canvas bbox。

### L06：3D“适应”只考虑垂直视角，窄画布仍可裁节点

- 位置：`GraphScene.vue:119–136`的`fitScene`。
- 原因：距离由垂直FOV计算，没有同时约束水平FOV/宽高比。
- 公式复核：两节点x为0和3.8，现有45°相机和方向、距离9.415。aspect=1时NDC x为−0.389/0.468；aspect=1/3时变−1.166/1.404，均超出可见范围±1。此项为准确公式复核，不声称读取了在线相机私有状态。
- 最小修复：按水平和垂直可见角共同决定距离；隐藏→显示时使用有效尺寸。同步核对距离上限与大图范围，不把所有容器resize都改成自动重置相机。
- 先行用例：给已有U11场景增加窄容器，点击适应后节点投影位于画面内；普通选点/状态更新仍保留视角。

### L07：SVG平移后缩放重复扣除平移，锚点漂移

- 位置：`useCanvasPanZoom.ts:58–91`；影响主图与通用图的SVG降级场景。
- 原因：`localPoint/viewCenterPoint`相对已经transform的SVG计算坐标，`zoomAt`又减一次translate。
- 公式复核：初始scale=1、translateX=100，容器锚点250，放大1.12倍后原锚点内容落到262，漂移12px。
- 最小修复：滚轮与按钮锚点统一以未变换的container为坐标系，并保持focus/fit使用相同坐标约定。
- 先行用例：平移后以固定指针Ctrl滚轮、再以工具栏按钮缩放，检查对应内容点保持原屏幕坐标。

## 尚未复现的风险

| 项目 | 位置与条件 | 需要验证的边界 |
| --- | --- | --- |

| SVG键盘导航带动祖先滚动 | `GraphCanvas.vue:93`使用裸focus，同文件其他入口和3D已用preventScroll | 禁用WebGL，用方向键选到远节点，核对容器scrollLeft/Top为0、浮动工具栏不移位、节点可见 |
| 库底部加载/分页状态换行 | `loaded-status`可wrap、说明和按钮按状态出现 | 本轮1条无分页数据在7个宽度下均保持38px；多页及长状态尚未验证，不能写成已确认跳动 |
| 极窄单页 | NodeReader/证据固定单页在320–390px仍保留双列 | 属于阅读宽度适配风险，未证明会挤动隐藏Map；与画布闪动分开验收 |

## 全部影响路径核对

| 路径 | 对画布的影响与结论 |
| --- | --- |
| 自动保存、同步连接状态 | 113已把saving移固定26px页脚；普通保存不改busy/loading、不重载图，也不通过Mongo偏好写入触发图SSE |
| 顶部session.error、本机服务失败、偏好冲突/未确认 | 仍处于正常布局，会改变主区高度；这是目前的异常提示策略，并非后台保存回归。应统一决定固定区域或覆盖层，长错误/按钮不得随意改变画布空间 |
| `librarySourceNotice` | 位于中心区Map/库视图之前，来源定位/依据读取提示会占空间；应纳入相同通知策略 |
| Map工具栏 | 动态按钮与换行已确认L01；操作可用性不应通过增加栏高表达 |
| 标签页 | 容器头部固定44px，标签横向滚动；多标签不增加画布上方行数 |
| 左右栏拖动/恢复/窗口缩放 | 用户主动变化属于正常resize，但L02/L03破坏有效空间约束；浏览器放大会减少CSS可用宽度，同样进入这些断点 |
| 700px及以下侧栏展开 | 现有绝对定位覆盖层不会直接挤压画布；跨断点是预期布局切换 |
| 单页/Map与证据库切换 | Map使用v-show常驻，退出单页恢复尺寸/焦点；单页隐藏右栏引起宽度变化属于用户显式模式切换，不应作为普通自动保存效果 |
| 单页正文、脚注、关联材料、详情表单 | 已有min-width/min-height:0和内部滚动/长文本处理；未发现从内容增长直接撑大主Map的路径 |
| 管理、运行、历史、证据编辑/收录弹窗 | 使用原生dialog.showModal的顶层模态框，不参与AppShell正常布局 |
| 库筛选、关系与分页 | L04/L05已确认；收录结果/错误栏也占正常布局，应与普通loading策略一起整理，详细结果可内部滚动 |
| 节点颜色图例、选中摘要、activity标签 | 绝对定位，不参与容器尺寸分配；窄画布的控件拥挤可随L02的有效宽度与容器响应规则一并检查 |
| 3D ResizeObserver | 只调整renderer尺寸、相机aspect和投影，不主动fit/reset；它会放大上层布局抖动的视觉效果，但不是保存闪动的起因 |
| 快照、节点/关系变化 | 业务结构变化重新布局，新节点自动fit是现有U11既定行为；同节点数的正文/纯活动更新保留相机。不能把业务增长与纯UI状态闪动混同 |
| 图身份切换/首次挂载 | 预期重置场景；普通选点不应卸载canvas，已有A02和113几何检查守住此边界 |
| SVG缩放、平移、焦点 | L07与键盘风险需要处理；场景隐藏时已取消画布平移，卸载已清理监听 |
| bottom-dock | 当前应用没有使用此插槽；高度恢复/缩窗重约束是未启用抽象的潜在缺口，不是现在线上根因，不优先扩改 |
| 全局字体、样式与主题 | 当前使用系统字体，没有异步远端字体加载链；focus outline、box-shadow及颜色动画不改变盒模型。按钮可换行和实际容器宽度才是主要布局耦合 |

## 建议修复顺序与测试边界

1. **稳定普通状态布局**：L01、L04、L05；明确通知区域策略，检索按钮和工具栏尺寸稳定。先用现有fixture补几何回归，保持正式查询与保存协议。
2. **统一侧栏有效空间**：L02、L03；补较大侧栏→缩窗→恢复的用例，再验证拖动失焦风险。保留真实用户拖动与窗口改变的resize行为。
3. **修正取景和降级交互**：L06、L07；窄场景取景、SVG缩放锚点、远节点键盘焦点。保留用户相机姿态和现有新增节点策略。

不需要为本轮补服务重启、队列并发或新的异常状态机。验收核心是：后台状态和普通选点不改变canvas bbox；用户明确调整尺寸时不重叠、不遮挡；正常缩放/取景坐标正确。

## 工件

- `layout-measurements.json`：12个窗口宽度的节点类型切换与侧栏操作几何。
- `library-measurements.json`：真实库收录/关系读取/检索前中后的几何。
- `projection-check.json`、`svg-anchor-check.json`：两项计算问题的独立数字复核，均标明非在线相机/手势回放。
- `audit-summary.json`：确认项、风险项与范围摘要。
- `probe-source.ts`：已移出测试发现目录的测量源；其完成状态不是布局合格判据。库测量最初对未挂载状态行调用boundingBox导致等待，修正测量脚本后完成，未据此改产品。
