# 059 — 节点级执行与暂停接口

本文描述本轮生产合同，以 `contracts/graph.ts`、`contracts/client.ts` 为准。055–058 的鉴权、管理、资产和连接协议沿用；下列运行协议取代单 Claim/单 operation 形态，不保留 targetId 启动别名。

## 启动与范围

`run.start` 参数：`{mapId, expectedRevision, id, scope:{nodeIds:string[]}, until:'news'|'claims'|'verified', mode:'auto'|'human-in-loop', regenerate?:boolean}`。节点 ID 非空且不重复，起点为 Source、News 或 Claim。客户端提供单节点和批量选择入口。

同图一个未结束 Run；内部 `operations[]` 可并行处理多个节点。Source→parse→News、News→split→Claim、Claim→verify→Verification。候选报告/草稿/Review 属于各 operation，核查角度仍可在 operation 内分别领取。Graph 保存 `derived-from`（News→Source、Claim→News）、`mentions`（News→Claim）、`verifies`（Verification→Claim）与原 related-to。只有业务派生及明确来源关系扩展 scope，不反向纳入共享事实的其他新闻。

默认复用输入、配置及输出版本均有效的历史操作；成功零结果同样完成。`regenerate:true` 明确要求重新生成。重新生成保留已有数据，不覆盖人工节点；暂停后继续使用 `run.resume`，不创建新 Run。

每个 operation 保存 kind/targetId/inputRefs/configurationHash/outputRefs，以及相应 route、reports、splitReports、draft、contentDraft、review。outputRefs 记录输出版本与拆分候选的 reportId/index 来源。Run 聚合所有操作和新后继：有可执行项为 running，剩余项全部待审为 waiting，目标闭包全部达成为 completed；拒绝审核或不可继续错误为 failed，显式取消为 cancelled。

## 审核与暂停

`review.update`：`{mapId,expectedRevision,runId,operationId,reviewId,expectedReviewRevision,reason,slots}`，编辑对应操作的待审路由。

`review.answer`：`{mapId,expectedRevision,runId,operationId,reviewId,expectedReviewRevision,decision:'approve'|'reject'}`。parse 结果审核展示 News 候选；split 结果审核展示已选择的事实；verify 结果审核保存结论。一个操作待审时，其他可执行操作继续。

`run.pause`、`run.resume`、`run.cancel` 均接受 `{mapId,expectedRevision,runId}`，返回现有 GraphWriteResult。请求外层仍携带 UUID requestId；相同逻辑重试复用原 ID/参数。Editor/Owner 有权控制，Viewer 无权。

Run.paused 独立于业务状态。pause 在鉴权事务中保存暂停、原子过期该 Run 租约、增加 Map revision 并写收据；保留 fence/holder，快速 resume 也不会复活旧授权。resume 保留 Run/输入/配置/报告/Review，重新领取未完成工作。paused 中仍可回答 Review，批准不会清 paused。未结束 Run 继续阻止普通图编辑、删除或新 Run 覆盖。

数据库暂停生效后拒绝新执行提交；Host 在续租失效后关闭对应 DSH。默认租约 15 秒、正常续租间隔约 5 秒，外部请求未必瞬间停止。模型和工具可重跑，业务结果只接受一次；不承诺会话或 token 级恢复。关闭客户端不暂停，关闭单个 Host 不等于暂停共享 Run。

## 执行配置与提案

Run.configuration 保留顶层 verify 的 router/merger/agents/tools/maxSlots，新增可选 parse profile 和 split `{router,merger,agents}`。所有使用的模型、工具、变量、优先级、类别随 Run 冻结，业务阶段缺少配置时明确报错，不调用旧 Mapper。

内部 data.read 按 grant 返回 `operationKind`、`target`、可见上下文、冻结配置和该 operation 的草稿/报告；原 claim 字段已移除。parse 首次读取共享 Source 正文，原子保存为 operation.rawContent，恢复复用该输入。资产必须 ready、同工作区、媒体一致；URL 仅公开 HTTP(S)、无凭证、无重定向，DNS 解析与实际连接固定为校验后的地址。文本限 1 MiB、UTF-8，URL 总时限 10 秒。

新增提案：

- `parse`：`{kind,reason,news:[{content,context}]}`，允许空数组。
- `split-report`：`{kind,routeRevision,slotId,reason,claims:[{content,category}]}`，候选保存在对应 slot 报告。
- `split-merge`：`{kind,routeRevision,reportIds,reason,selected:[{reportId,index}]}`，须引用全部有效报告，选择每个存在候选至多一次；服务端按引用创建 Claim，允许全不选。

三者仍带 mapId/operationId/id，身份由可信 grant 绑定。split 路由沿用 route 提案；verify 的 route/report/merge 内容合同保持。每次最多 256 个候选/输出，原图 8 MiB 软上限继续生效。节点、边、完成记录、后继操作和业务收据在同一 Map CAS 内保存。

## 显式升级

`npm run admin -- data.migrate-node-runs` 默认检查；`--input` 指向含 `{"apply":true}` 的文件才提交。先停止 Host 并等租约过期。工具在真实事务内按 Mongo 时间检查租约，迁移当前/历史单 operation 记录，保留所有业务身份；活跃旧 Run 迁为 paused，不自动执行。任一不支持的旧结构或有效租约使 apply 整批回滚。新结构不重复迁移。

迁移不改用户 Agent 配置或图内容。已有工作区的占位 parse/split 提示词及缺少的拆分 Agent，须通过已有 Agent API 显式更新。新初始化使用新的默认配置。Source/Claim 等导出后重新导入，依然不携带可执行 Run/租约；数据交换包不是执行断点备份。
